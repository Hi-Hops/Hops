# Spring–Python MVP 계약 논의

**상태: #22 논의용 제안. 승인된 API·스키마나 구현 기준이 아니다.** 이 문서는 Spring·Python 담당자가 입출력의 최소 의미를 맞추기 위한 자료다. 경로·필드명·타입·필수값·상태 코드는 합의 후 구현과 함께 검증한다.

## 기존 문서에 반영된 방향

근거는 [PRD](../../docs/PRD.md)와 [API 설계](../../docs/API.md) 3절이다. 아래 방향을 여기서 다시 결정하지 않는다.

- Spring이 Python에 HTTP로 분석 실행을 요청하고 SSE로 진행 정보를 받는다. 최종 결과 전달 방식은 미정이다.
- Python은 분석과 티켓 제안을 반환한다. 권한·실제 티켓 저장·부서 배정은 Spring이 확정한다.
- 추가 질문은 문제당 최대 3회다. 정정 후에는 이전 문의 버전의 미반영 결과를 적용하지 않고 기존 성공 티켓은 유지한다.
- 사용자 JWT·Socket.IO 명령·저장 ACK는 API 설계 2.4·2.5절을 따른다. Python에는 사용자 JWT 대신 Spring이 검증한 최소 문맥을 전달한다.

## 입출력에서 맞출 정보 — 제안

아래는 필요한 의미를 나열한 것으로, 모든 항목을 필수 JSON 키로 확정한 표가 아니다.

| 방향 | 정보 | 목적 |
| --- | --- | --- |
| Spring → Python | 실행 ID·문의 ID·문의 버전 | 요청과 결과 연결, 오래된 결과 차단 |
| Spring → Python | 관련 메시지와 수정 버전 | 최신 대화 분석과 근거 참조 |
| Spring → Python | 기존 문제·생성 작업과 식별자 | 질문·분석 재개, 동일 작업 중복 제안 방지 |
| Spring → Python | 허용된 부서·서비스와 최소 사용자 권한 문맥 | 제공 범위 안에서 분석·배정 제안 |
| Spring → Python | 종료 시각·호출 예산 | 실행·재시도 제한. 구체 시간·횟수는 미정 |
| Python → Spring | 실행·문의 식별자와 입력 버전 | 요청 결과의 대응 여부 검사 |
| Python → Spring | 답변·문제별 다음 행동 | 추가 질문·티켓 제안·범위 밖 구분 |
| Python → Spring | 문제별 티켓 내용·부서 제안·근거·불확실성 | Spring 검증 후 작업별 저장·배정 |
| Python → Spring | 기술 실패와 재시도 가능 여부 | 모델/통신 장애를 분류 실패·업무 성공과 구분 |

## 설명용 가상 예시 한 쌍

**아래 JSON은 일부 정보만 표현한 축약 예시다.** 키 이름·임시 참조·enum·필수성은 제안이며 실제 전송 스키마가 아니다. 식별자는 테스트용이고 실제 계정·공통 seed·평가 자료가 아니다. 인증 문맥·카탈로그·예산·결과 외피의 최종 형식은 생략했다.

요청 예시:

```json
{
  "runId": "00000000-0000-4000-8000-000000000001",
  "inquiryId": "00000000-0000-4000-8000-000000000002",
  "inquiryVersion": 1,
  "messages": [{
    "messageId": "00000000-0000-4000-8000-000000000003",
    "revision": 1,
    "content": "VPN 연결이 실패하고 포털 조회도 안 됩니다."
  }]
}
```

분석 결과 예시:

```json
{
  "runId": "00000000-0000-4000-8000-000000000001",
  "inquiryId": "00000000-0000-4000-8000-000000000002",
  "inquiryVersion": 1,
  "answer": "VPN은 담당 부서 조사를 제안하고, 포털 오류는 추가 정보를 확인하겠습니다.",
  "problems": [
    {"ref": "new:p1", "summary": "VPN 연결 실패", "action": "PROPOSE_TICKETS"},
    {"ref": "new:p2", "summary": "포털 조회 실패", "action": "ASK_USER", "question": "어느 메뉴에서 어떤 오류가 나오나요?"}
  ],
  "ticketProposals": [{
    "problemRef": "new:p1",
    "workScope": "VPN 접속 장애 조사",
    "departmentCode": "NETWORK",
    "uncertainty": "실제 원인은 아직 확인하지 못했습니다.",
    "evidence": [{"messageId": "00000000-0000-4000-8000-000000000003", "messageRevision": 1}]
  }]
}
```

이 결과는 티켓 저장·배정 성공이 아니다. Spring이 근거·부서·참조·최신 버전을 검증하고 실제 저장한 결과만 화면에 확정 표시한다.

## 구현 전에 결정할 항목

1. 요청·응답 필드명, 타입·필수/선택·null, 공유 코드와 오류 표현.
2. 실행 접수·SSE·최종 결과 전달 경로와 서비스 간 인증.
3. 연결 단절·서버 재시작 시 결과 복구, 중복 수신·늦은 결과·취소 처리.
4. 종료 시각과 실행·모델 호출·재시도 예산, 보존 범위.

Spring·Python 담당자가 해당 항목을 리뷰하고 합의 내용을 PR에 기록한다. 이후 #24에서 타입·검증·계약 테스트를 구현하며 필요한 기계 판독 명세의 원본·생성 방식을 정한다. 이 문서가 병합되더라도 미정 항목이 확정되거나 #22 전체가 완료된 것으로 해석하지 않는다.
