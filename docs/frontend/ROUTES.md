# 구현된 화면 경로

> **PRD 1.44 전환:** `hops-system-1` 단일 계약은 시스템 단위 업무·상세 모달·처리/정정·해결 응답·사례 검토/승인/반영 UI를 제공한다. 실제 Spring·AI·검색 통합 완료는 별도로 검증한다.

상태: 신규 계약의 프론트 UI·REST/SSE 호출 구현 / 실제 서비스 통합 검증 별도. 실제 등록은 [router.tsx](../../frontend/src/app/router.tsx), 공용 경로 생성은 [paths.ts](../../frontend/src/shared/config/paths.ts)가 원본이다.

## hops-system-1 현재 구현

- `/login`: 기존 로그인 폼·내부 복귀 주소. 기본 복귀는 업무 관리 → 담당 시스템 업무 → 새 문의 순이다.
- `/`: 자연어 문의·선택적 보고 시스템. 첫 저장 확인 후 본인 채팅으로 이동한다.
- `/inquiries`, `/inquiries/:inquiryId/chat`: 본인 목록·최근 채팅, 질문 5회·시스템 선택, 정정/보완 대상 연결·접수 결과·수동 재확인·문제별 해결/미해결 응답.
- `/tickets`: 현재 PRIMARY의 시스템 보드/목록. `view,systemId,state,page,size`를 URL에 보존하고 `scope=ASSIGNED_SYSTEMS`로 조회한다.
- `/tickets/:ticketId`: 목록 위 상세 모달. 보고/책임 시스템·배정 담당자/현재 PRIMARY·표준 요청·허용 관련 대화·배정 이력과 정정 모달. `tab=request/work/case`는 같은 모달의 탭이며 처리·검증 입력과 이력도 모달 안에 표시한다.
- `/admin/tickets`, `/admin/tickets/:ticketId`: BIZ_ADMIN의 관리 목록·제한 상세 모달·책임 시스템 정정. `scope=ADMIN`과 관리 전용 DTO를 사용하며 원문·표준 요청을 조회하지 않는다.
- `/cases`, `/cases/:caseId`: 현재 사례 시스템 PRIMARY의 검토 목록·현재 초안 편집·승인·같은 버전의 양쪽 반영/검색 공개 상태·수동 확인/실패 재시도. 최신 버전만 표시한다.
- `/403`, 미등록 경로: 기존 인증 가드와 오류 화면을 사용한다.

상세 진입과 목록 복귀는 필터·보기·페이지를 유지한다. 모든 탭은 직접 진입도 목록 위 모달로 열고 닫기·Escape로 tab을 제외한 목록 조건과 티켓 포커스를 복원한다. 탭 전환·브라우저 뒤로/앞으로 이동에서도 미전송 처리 입력을 보존한다. `view/tab`은 표시 상태라 서버로 보내지 않는다. 메뉴는 새 문의·내 문의와 해당 능력의 담당 시스템 업무·사례 검토·업무 관리다. 계약 선택 설정은 없으며 데이터 소스만 mock/live로 선택한다.

## URL 상태

모든 업무 경로는 인증 가드 아래 있으며 서버 UUID를 사용한다. 내 문의는 page, 티켓 목록은 systemId/state/page/size를 조회에 전달한다. view는 표시 상태이며 서버에 보내지 않는다. 담당 업무 기본은 보드, 관리 기본은 목록이다. 최종 권한은 서버가 검사한다.

처리·사례 화면의 미전송 입력과 미확인 원 명령은 메모리에 보존한다. 로그아웃·사용자 전환 시 지우며 목록 조회·폴링으로 업무 POST를 자동 실행하지 않는다.

## hops-system-1 목표 경로안

상태: PRD 1.44 화면·경로/접근/복귀 정의. 아래 표의 경로는 현재 router에 등록됐으며 실제 시스템 권한·저장은 서버 통합 검증과 구분한다. 이 절의 제목은 기존 참조 경로를 보존한다. 공통 UI·토큰·기존 채팅 조회/정정/초안 기반을 재사용한다.

| 목표 경로 | 구성·URL 상태 | 접근 |
|---|---|---|
| /login | 기존 로그인·내부 복귀 주소 유지 | 비로그인 |
| / | 자연어 입력·선택적 보고 시스템 | 로그인 |
| /inquiries | 내 문의 목록·page | 본인 |
| /inquiries/:inquiryId/chat | 문제별 질문/시스템 선택·결과 모달·GUIDE/업무 해결 확인 | 본인 |
| /tickets | 담당 시스템 보드/목록·view,systemId,state,page,size | 현재 PRIMARY |
| /tickets/:ticketId | 상세 모달·tab=request/work/case 및 목록 쿼리 보존 | 현재 책임 시스템 PRIMARY |
| /admin/tickets | 업무 관리 목록·systemId,state,page,size | BIZ_ADMIN |
| /admin/tickets/:ticketId | 제한된 상세·배정 이력·정정 모달 | BIZ_ADMIN |
| /cases | 검토 대상 목록·systemId,state,page,size | 현재 사례 시스템 PRIMARY |
| /cases/:caseId | 현재 초안/승인/반영·최신 버전 | 현재 사례 시스템 PRIMARY |
| /403, 미등록 경로 | 권한 없음·찾을 수 없음 | 기존 인증 가드 범위 |

tab/view는 표시 상태이며 서버 조회 필터로 보내지 않는다. systemId/state/page/size는 해당 v2 API가 허용한 값만 보낸다. 프론트 표시 page는 1부터, 전송 page는 0부터다. 상세에서 목록으로 돌아갈 때 필터·보기·페이지를 유지한다. 직접 진입은 해당 역할의 기본 목록으로 복귀한다. 관리자 URL의 scope=ADMIN은 프론트가 결정하더라도 서버가 역할을 재검사한다.

공통 메뉴는 새 문의·내 문의, PRIMARY가 있으면 담당 시스템 업무·사례 검토, BIZ_ADMIN이면 업무 관리다. 능력이 중첩되면 모두 표시한다. 최근 채팅은 본인 문의로만 구성한다. 로그인 기본 복귀는 내부 허용 주소 우선, 없으면 관리자 업무 → 담당 업무 → 새 문의 순이다. 헤더 사용자·로그아웃과 기존 디자인 토큰을 유지하고 [현재 frontend UI](README.md#ui-기준과-이번-작업-범위)를 화면 구현 기준으로 사용한다.

접수 안내·수동 정정·티켓 상세는 모달, 해결 확인은 본인 채팅 안 영역, 처리 기록은 티켓 상세 모달의 처리·검증 탭, 사례 편집·승인은 /cases에서 제공한다. /cases는 대상 선택에 필요한 최소 목록이며 통계·지식 관리 전용 대시보드를 추가하지 않는다.

현재 프론트는 /api/v2·시스템 권한을 사용한다. 화면의 접근·상태·오류는 [F001~F011](../../specs/README.md), 타입/전송은 [신규 계약](../../specs/contracts/README.md)을 따른다.


### ERD 대조 후 화면 데이터

문의의 Q-표시 번호는 inquiryNumber, 티켓의 TK-표시 번호는 ticketNumber를 사용하고 URL/권한/변경 요청은 UUID를 유지한다. 목록 필터는 wire enum을 전송하고 DB 상태 변환은 Spring이 수행한다. 현재 PRIMARY에는 별도 담당 관계 상세/유효 구간을 만들지 않는다. 처리 이력은 실패 시도·확인된 원인·적용 버전을, CASE 상세는 문제 설명·사례 종류·같은 원 기록의 확인/승인/반영 버전을 표시한다. 구현 순서는 [프론트 범위](README.md#erd-대조-후-프론트-구현-범위)를 따른다.
