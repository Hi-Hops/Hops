# 구현된 화면 경로

> **PRD 1.44 전환:** 아래 경로·부서 권한은 현재 등록된 구현을 기술한다. 목표의 시스템 담당자 업무·확인·사례 승인은 새 명세와 계약에 맞춰 별도 구현하며 아래 기존 경로가 이미 지원함을 뜻하지 않는다.

상태: Mock 구현 기준 / 운영 권한 정책은 팀 합의 대상. 실제 등록은 [router.tsx](../../frontend/src/app/router.tsx), 공용 경로 생성은 [paths.ts](../../frontend/src/shared/config/paths.ts)가 원본이다.

## 경로와 접근 범위

| 경로                         | 화면                        | 접근 범위                                                             | 스펙                  |
| ---------------------------- | --------------------------- | --------------------------------------------------------------------- | --------------------- |
| `/login`                     | 로그인                      | 비로그인 사용자. 로그인 상태면 복귀 주소 또는 역할별 첫 화면으로 이동 | F001                  |
| `/`                          | 새 문의                     | 로그인 사용자                                                         | F003                  |
| `/inquiries`                 | 내 문의 최소 목록           | 본인 문의만 조회                                                      | F006 일부             |
| `/inquiries/:inquiryId/chat` | 채팅·결과·메시지 정정       | 문의 소유자. 최종 조회 권한은 서버 검사                               | F003·F004·F005        |
| `/tickets`                   | 부서 티켓 목록              | 현재 처리 부서 구성원 또는 BIZ_ADMIN                                  | F009                  |
| `/tickets/:ticketId`         | 같은 목록 위 티켓 상세 모달 | 현재 처리 부서 구성원 또는 BIZ_ADMIN                                  | F009                  |
| `/admin/tickets`             | 관리자 전체 티켓 최소 조회  | BIZ_ADMIN 가드                                                        | F007 일부             |
| `/admin/tickets/:ticketId`   | 같은 목록 위 티켓 상세 모달 | BIZ_ADMIN 가드와 상세 조회 권한 검사                                  | F007 일부·F009 재사용 |
| `/403`                       | 권한 없음                   | 인증된 사용자에게 접근 가능한 문의 화면 안내                          | F001                  |
| `*`                          | 찾을 수 없음                | 인증된 사용자의 미등록 경로                                           | F001                  |

`/login` 이외 경로는 인증 가드 아래 있다. 비로그인 접근은 로그인으로 보내고 원래 경로·쿼리를 보존한다. 로그인 후 내부 복귀 주소가 있으면 우선하며, 없으면 BIZ_ADMIN은 관리자 티켓, 처리 부서원은 부서 티켓, 그 외는 새 문의로 이동한다. 접근 여부는 `/api/auth/me`의 CurrentUser를 사용하고 토큰을 직접 해석하지 않는다.

## URL 상태

- 문의·티켓 경로에는 표시 번호가 아닌 서버 UUID를 사용한다.
- `/inquiries`: `page`.
- `/tickets`, `/admin/tickets`: `page`, `size`, `processingStatus`. 페이지는 0부터, 화면 표시는 1부터다. 값·범위와 권한은 [전송 계약](../../specs/contracts/WIRE_CONTRACT.md)을 따른다.
- 두 티켓 경로의 `view=board|list`는 프론트 표시 상태다. 부서는 기본 보드, 관리자는 기본 목록이며 보기 전환으로 필터·페이지를 초기화하지 않는다. REST에는 page/size/processingStatus만 보낸다. 보드는 현재 페이지를 4개 처리 상태 컬럼으로 나누며 컬럼 건수를 전체 서버 집계로 표시하지 않는다.
- 티켓 상세는 optional param으로 목록과 같은 컴포넌트를 사용한다. 열고 닫아도 쿼리를 유지하고, 닫을 때 해당 목록 링크 또는 페이지 제목으로 포커스를 돌린다.

역할별 메뉴는 `AppLayout`에서 조립한다. 화면 가드는 내용 노출을 막는 보조 수단이며 서버 권한 검사를 대신하지 않는다.

왼쪽 사이드바 상단에는 `+ 새 문의`(`/`), 처리 부서 구성원 또는 BIZ_ADMIN의 `부서 티켓 현황`(`/tickets`), BIZ_ADMIN의 `관리자 페이지`(`/admin/tickets`)를 둔다. 새 문의 선택은 문의 입력창에 포커스를 옮기며 저장 요청을 보내지 않는다. 기존 `/inquiries` 경로는 유지하지만 별도 상단 메뉴에는 노출하지 않는다. 하단 `채팅 세션`은 본인 문의 목록이며 선택한 문의의 채팅 경로로 재진입한다. 추가 페이지는 목록 Query 캐시에서 관리하고 채팅 URL에 page를 붙이지 않는다. 상세 동작은 F003-AC15·F006-AC10~AC12를 따른다.

## 미등록 범위

문의 상세 모달(`/inquiries/:id`), 관련 대화, 새 문의 분리 동의, 기술 복구 경로는 구현하지 않았다. 후속 경로·기능을 미리 등록하지 않으며 필요한 시점에 스펙과 이 문서를 함께 갱신한다.

## hops-system-1 목표 경로안

상태: PRD 1.44 팀 리뷰용 화면 계약. 위 표는 현재 router 등록 상태이고 아래 표는 새 구현 목표다. 문서만으로 경로가 등록되거나 실제 시스템 권한이 연결되지는 않는다. 공통 UI·토큰·기존 채팅 조회/정정/초안 기반을 재사용한다.

| 목표 경로 | 구성·URL 상태 | 접근 |
|---|---|---|
| /login | 기존 로그인·내부 복귀 주소 유지 | 비로그인 |
| / | 자연어 입력·선택적 보고 시스템 | 로그인 |
| /inquiries | 내 문의 목록·page | 본인 |
| /inquiries/:inquiryId/chat | 문제별 질문/시스템 선택·결과 모달·GUIDE/업무 해결 확인 | 본인 |
| /tickets | 담당 시스템 보드/목록·view,systemId,state,page,size | 현재 PRIMARY |
| /tickets/:ticketId | 독립 상세·tab=request/work/case 및 목록 쿼리 보존 | 현재 책임 시스템 PRIMARY |
| /admin/tickets | 업무 관리 목록·systemId,state,page,size | BIZ_ADMIN |
| /admin/tickets/:ticketId | 제한된 상세·배정 이력·정정 모달 | BIZ_ADMIN |
| /cases | 검토 대상 목록·systemId,state,page,size | 현재 사례 시스템 PRIMARY |
| /cases/:caseId | 초안/승인/반영·caseVersion 선택, 미지정은 최신 | 현재 사례 시스템 PRIMARY |
| /403, 미등록 경로 | 권한 없음·찾을 수 없음 | 기존 인증 가드 범위 |

tab/view는 표시 상태이며 서버 조회 필터로 보내지 않는다. systemId/state/page/size는 해당 v2 API가 허용한 값만 보낸다. 프론트 표시 page는 1부터, 전송 page는 0부터다. 상세에서 목록으로 돌아갈 때 필터·보기·페이지를 유지한다. 직접 진입은 해당 역할의 기본 목록으로 복귀한다. 관리자 URL의 scope=ADMIN은 프론트가 결정하더라도 서버가 역할을 재검사한다.

공통 메뉴는 새 문의·내 문의, PRIMARY가 있으면 담당 시스템 업무·사례 검토, BIZ_ADMIN이면 업무 관리다. 능력이 중첩되면 모두 표시한다. 최근 채팅은 본인 문의로만 구성한다. 로그인 기본 복귀는 내부 허용 주소 우선, 없으면 관리자 업무 → 담당 업무 → 새 문의 순이다. 헤더 사용자·로그아웃과 기존 디자인 토큰은 유지하는 안이며 Page 3의 배치만으로 별도 변경을 확정하지 않는다.

접수 안내·수동 정정은 모달, 해결 확인은 본인 채팅 안 영역, 처리·사례 상태는 상세 탭에서 제공한다. 담당자 상세는 기존 목록 위 모달에서 독립 페이지로 전환한다. /cases는 대상 선택에 필요한 최소 목록이며 통계·지식 관리 전용 대시보드를 추가하지 않는다.

현재 프론트는 기존 /api·부서 권한·모달 상세를 사용한다. 신규 화면의 접근·상태·오류는 [F001~F011](../../specs/README.md), 타입/전송은 [신규 계약](../../specs/contracts/README.md)을 따른다. 목표 표를 현재 구현 목록으로 옮기는 시점은 실제 router·컴포넌트·권한 연결과 검증 후다.
