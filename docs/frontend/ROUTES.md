# 구현된 화면 경로

상태: Mock 구현 기준 / 운영 권한 정책은 팀 합의 대상. 실제 등록은 [router.tsx](../../frontend/src/app/router.tsx), 공용 경로 생성은 [paths.ts](../../frontend/src/shared/config/paths.ts)가 원본이다.

## 경로와 접근 범위

| 경로                         | 화면                        | 접근 범위                                                             | 스펙                  |
| ---------------------------- | --------------------------- | --------------------------------------------------------------------- | --------------------- |
| `/login`                     | 로그인                      | 비로그인 사용자. 로그인 상태면 복귀 주소 또는 역할별 첫 화면으로 이동 | F001                  |
| `/`                          | 새 문의                     | 로그인 사용자                                                         | F003                  |
| `/inquiries`                 | 내 문의 최소 목록           | 본인 문의만 조회                                                      | F006 일부             |
| `/inquiries/:inquiryId/chat` | 채팅·결과·메시지 정정       | 문의 소유자. 최종 조회 권한은 서버 검사                               | F003·F004·F005        |
| `/tickets`                   | 부서 티켓 목록              | 현재 처리 부서 구성원 또는 BIZ_ADMIN                                  | F009                  |
| `/tickets/:ticketId`         | 같은 목록 위 티켓 상세 모달 | 현재 처리 부서 구성원 또는 BIZ_ADMIN                                  | F009                  |
| `/admin/tickets`             | 관리자 전체 티켓 최소 조회  | BIZ_ADMIN 가드                                                        | F007 일부             |
| `/admin/tickets/:ticketId`   | 같은 목록 위 티켓 상세 모달 | BIZ_ADMIN 가드와 상세 조회 권한 검사                                  | F007 일부·F009 재사용 |
| `/403`                       | 권한 없음                   | 인증된 사용자에게 접근 가능한 문의 화면 안내                          | F001                  |
| `*`                          | 찾을 수 없음                | 인증된 사용자의 미등록 경로                                           | F001                  |

`/login` 이외 경로는 인증 가드 아래 있다. 비로그인 접근은 로그인으로 보내고 원래 경로·쿼리를 보존한다. 로그인 후 내부 복귀 주소가 있으면 우선하며, 없으면 BIZ_ADMIN은 관리자 티켓, 처리 부서원은 부서 티켓, 그 외는 새 문의로 이동한다. 접근 여부는 `/api/auth/me`의 CurrentUser를 사용하고 토큰을 직접 해석하지 않는다.

## URL 상태

- 문의·티켓 경로에는 표시 번호가 아닌 서버 UUID를 사용한다.
- `/inquiries`: `page`.
- `/tickets`, `/admin/tickets`: `page`, `size`, `processingStatus`. 페이지는 0부터, 화면 표시는 1부터다. 값·범위와 권한은 [전송 계약](../../specs/contracts/WIRE_CONTRACT.md)을 따른다.
- 티켓 상세는 optional param으로 목록과 같은 컴포넌트를 사용한다. 열고 닫아도 쿼리를 유지하고, 닫을 때 해당 목록 링크 또는 페이지 제목으로 포커스를 돌린다.

역할별 메뉴는 `AppLayout`에서 조립한다. 화면 가드는 내용 노출을 막는 보조 수단이며 서버 권한 검사를 대신하지 않는다.

왼쪽 사이드바 상단에는 `+ 새 문의`(`/`), 처리 부서 구성원 또는 BIZ_ADMIN의 `부서 티켓 현황`(`/tickets`), BIZ_ADMIN의 `관리자 페이지`(`/admin/tickets`)를 둔다. 새 문의 선택은 문의 입력창에 포커스를 옮기며 저장 요청을 보내지 않는다. 기존 `/inquiries` 경로는 유지하지만 별도 상단 메뉴에는 노출하지 않는다. 하단 `채팅 세션`은 본인 문의 목록이며 선택한 문의의 채팅 경로로 재진입한다. 추가 페이지는 목록 Query 캐시에서 관리하고 채팅 URL에 page를 붙이지 않는다. 상세 동작은 F003-AC15·F006-AC10~AC12를 따른다.

## 칸반 MVP 추가 예정 URL 상태 (2026-10-27 · 팀 리뷰·구현 검증 별도)

위 표와 URL 상태는 현재 구현 기준이다. 아래는 `/tickets` 부서 티켓 현황의 보드·목록 전환을 위한 추가 명세이며 현재 프론트가 구현했다고 간주하지 않는다. `/tickets/:ticketId`는 두 보기 위의 같은 상세 모달을 사용한다. `/admin/tickets`에는 보드 전환을 필수로 확장하지 않으며 기존 관리자 목록·상세를 유지한다.

- `view=board|list`: 유효 값은 그대로 사용하고, 없거나 잘못된 값이면 1024 CSS px 이상은 board, 미만은 list다. 너비 변경만으로 유효한 선택을 덮어쓰지 않는다. view는 클라이언트 전용이며 API에 전달하지 않는다.
- `q`: 티켓 번호·제목 검색어. `quickFilter`: MINE/URGENT/HIGH/RESOLUTION_REPORTED 또는 생략(전체). 정확한 검색·직렬화·검증은 WIRE_CONTRACT 10절의 칸반 추가 프로필을 따른다. 검색/필터는 보기 전환 후에도 유지한다.
- `processingStatus`: 목록의 상태 필터. 보드에서는 URL 값만 보존하고 API에 적용하지 않는다. 각 컬럼의 상태 조건으로 치환한다. 목록 복귀 시 보존된 필터를 다시 적용한다.
- `page`, `size`: 목록의 기존 페이지·크기. 보드도 size는 적용하며 컬럼별 page/추가 카드/스크롤은 Query 캐시로 관리한다. 보기 또는 검색/필터 변경 시 page와 보드 추가 페이지를 초기화한다.
- 상세 열기/닫기는 view·검색·필터·목록 페이지와 보드 캐시를 보존한다. 상세 닫기는 선택한 카드/행 링크, 해당 항목이 없으면 페이지 제목으로 포커스를 복원한다. 새로고침은 같은 보기/조건의 첫 컬럼 페이지부터 조회한다.

미구현 화면의 경로를 추가 등록하지 않는다. 칸반 상세 동작은 F009-AC11~AC20을 따른다.

## 미등록 범위

문의 상세 모달(`/inquiries/:id`), 관련 대화, 새 문의 분리 동의, 기술 복구 경로는 구현하지 않았다. 후속 경로·기능을 미리 등록하지 않으며 필요한 시점에 스펙과 이 문서를 함께 갱신한다.
