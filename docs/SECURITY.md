# Hops 보안 개발 명세

상태: 보안 목표 명세 · 구현·설정·검증 상태는 해당 코드와 환경에서 확인한다. 제품 범위와 정책은 [PRD](PRD.md), 상세 서비스 경계는 [API](API.md)와 [목표 공통 계약](../specs/contracts/TARGET_CONTRACT.md), 현재 동작은 각 서비스의 코드와 실행 안내를 따른다. 충돌하거나 상세 계약이 없으면 임의로 정하지 말고 관련 담당자와 합의한다.

이 문서는 **OWASP Top 10 for LLM Applications 2025 한국어판**을 참고해 Hops에 필요한 통제와 검증을 정리한다. 참고: [OWASP GenAI Security Project](https://genai.owasp.org/). OWASP 항목은 위험 분류이지 인증 기준이 아니다. 문서나 일부 테스트의 통과만으로 모든 위험이 제거되거나 보안 인증을 받았다고 말하지 않는다. 일반적인 웹·API·인프라 보안도 별도로 필요하다.

## 1. 적용 방법

- 보안·인증·데이터·AI·검색·도구·외부 연동 작업을 시작하기 전 이 문서와 변경 대상의 기존 코드·계약을 확인한다. 사람과 개발 AI 모두 같은 기준을 사용한다.
- 변경의 진입점, 신뢰 경계, 접근 주체, 다루는 데이터와 실패 시 영향을 먼저 확인한다. 아래 요구사항 중 적용되는 항목을 기능 명세·계약·테스트에 연결한다. 관련 없는 항목을 구현 범위에 억지로 추가하지 않는다.
- 기능 구현 전 정상·권한 없음·실패의 관찰 가능한 결과를 정한다. 서비스 연결 전 인증·입출력·상태·오류·제한과 소비자 영향을 합의한다. 값이나 경로가 미정이면 임의로 확정하지 않는다.
- AI가 생성한 코드·설정·테스트는 검토 대상이다. 기존 인증·인가를 제거하거나 우회하고, 검증 실패를 성공으로 바꾸거나, 보안 검사를 비활성화해 테스트를 통과시키지 않는다.
- 작업 결과에는 실제 적용 내용, 실행한 검증과 미실행 사유를 남긴다. Fake·Mock, 실제 모델, 실제 저장소 및 서비스 간 통합 검증은 각각 구분한다. 미구현 요구사항은 완료로 표시하지 않는다.

## 2. 신뢰 경계와 책임

| 경계 | 신뢰할 수 없는 입력 또는 위험 | 책임 |
|---|---|---|
| 브라우저 → Spring | 사용자 입력, 식별자, 역할 주장, 재전송 | Spring이 인증과 현재 권한·소유권·입력을 검증하고 업무 상태를 확정한다. 화면 숨김은 권한 검사가 아니다. |
| Spring → AI | 서비스 호출자, 사용자·접근 문맥, 문의와 실행 버전 | 서비스 신원을 확인한다. Spring은 검증된 최소 문맥을 제공하고 AI 서버는 인증되지 않은 호출과 허용되지 않은 결과 접근을 거부한다. 상세 위임·검증 방식은 합의한다. |
| AI → 모델 | 문의, 대화, 검색 문서, 사례, 도구 응답에 포함된 지시·민감정보 | 외부 콘텐츠는 업무 데이터로 구분하고 필요한 내용만 제공한다. 데이터 속 지시는 권한이나 시스템 정책을 변경하지 못한다. |
| 모델 → AI·Spring·화면 | 조작되거나 부정확한 답변, 식별자, 도구 인자, 실행 지시 | 모델 출력을 신뢰할 수 없는 입력으로 검증한다. 서버가 권한·근거·업무 상태를 확인하고 표시 맥락에 맞게 안전하게 처리한다. |
| AI → Vector·Neo4j·읽기 도구 | 검색 범위 우회, 오염 자료, 권한 밖 조회 | 서버가 확정한 권한과 공개 상태를 강제한다. 조회 도구는 허용된 읽기 전용 Mock이며 실제 시스템 쓰기는 MVP 범위 밖이다. |
| 지식 작성 → 색인 → 검색 | 미검수 문서, 사례 초안, 부분 반영, 오래된 권한 | 출처·검수·승인·버전·반영 상태를 구분한다. [데이터 구축 계획](knowledge/DATASETS.md#저장검색과-사례-공개)의 공개 조건을 양쪽 검색 경로에 적용한다. |

프롬프트의 문구, 모델이 주장한 역할, 검색 점수, 식별자를 알고 있다는 사실, 내부망이라는 이유만으로 권한을 부여하지 않는다. 시스템 프롬프트를 비밀 저장소나 유일한 보안 경계로 사용하지 않는다. 프롬프트 인젝션을 완전히 차단한다고 가정하지 않고 피해를 제한하고 검증한다.

## 3. 공통 요구사항

아래 ID는 이 문서의 목표 요구사항이다. 실제 필드명·경로·상태 코드·수치와 테스트 연결은 기능 구현 전에 정한다.

### 인증·정보 보호

- **SEC-01 인증과 권한:** Spring은 요청별로 현재 사용자, 대상 소유권과 시스템 담당 관계를 확인한다. 서비스 간 호출에도 호출자 인증을 적용하고 실행 결과·이벤트 접근 범위를 검증한다. 인증·권한·공개 상태를 확인할 수 없으면 관련 내용을 반환하거나 업무 성공으로 확정하지 않는다. 기존 업무 기록은 보존한다.
- **SEC-02 최소 정보:** 모델·검색·도구에 해당 작업과 권한에 필요한 정보만 전달한다. 직원 답변과 담당자 내부 자료를 구분한다. 비밀번호·키·토큰은 프롬프트, 저장소, 로그, 오류 응답, 테스트 결과에 넣지 않는다. 실제 개인정보의 사용·마스킹·보존은 실제 데이터 도입 전에 합의한다.
- **SEC-03 로그와 오류:** 인증·권한 거부, 제한 초과, 검색·모델·도구 실패를 원인 조사에 필요한 범위에서 기록한다. 문의 원문, 민감정보, 인증 정보와 내부 예외 상세가 외부 오류나 로그에 불필요하게 노출되지 않도록 한다. 검색 0건·권한 거부·시스템 오류를 내부적으로 구분하되 외부에 허용되지 않은 자료의 존재를 노출하지 않는다.

### 입력·모델·출력

- **SEC-04 입력과 인젝션:** 사용자 대화, 문서·사례·도구 결과를 출처가 구분되는 데이터로 취급한다. 이 내용이 시스템 지시를 무시하거나 권한을 늘리거나 다른 자료를 공개하도록 요구해도 코드가 정한 권한·도구·공개 범위를 바꾸지 않는다. 입력 필터나 프롬프트 지시만을 유일한 방어로 사용하지 않는다.
- **SEC-05 출력 처리:** 모델 결과의 형식·허용값·참조 대상·현재 버전·접근 범위를 소비 전에 검증한다. 구조가 올바르다는 사실이 답변의 정확성이나 공개 허용을 증명하지 않는다. 화면에서는 출력 맥락에 맞게 안전하게 표시하고, 모델 생성 문자열을 검증 없이 HTML, 명령, 쿼리, 경로 또는 외부 호출로 실행하지 않는다.
- **SEC-06 도구·업무 경계:** 도구는 등록된 허용 목록, 역할·사용자 범위, 인자와 대상 권한을 코드로 검사한다. 모델은 티켓 저장·배정, 계정 변경, 해결·승인·공개를 확정하지 않는다. Spring의 실제 검증·저장 결과 없이 성공을 표시하지 않는다. MVP에는 실제 시스템 쓰기·원격 제어·자동 복구를 추가하지 않는다.
- **SEC-07 근거와 불확실성:** 존재하고 접근 가능한 근거와 출처·버전·적용 조건을 확인한다. 검색 결과가 없거나 검색에 실패하면 구분하고 근거를 만들어내지 않는다. 과거 사례·그래프 관계나 모델의 주장만으로 현재 원인·해결을 확정하지 않는다.

SEC-06의 HOPS 내부 티켓 생성·조회 허용 범위는 [Ticket 도구 REST 계약](../contracts/agents/TICKET_TOOLS.md)이다. 서비스 인증된 Spring API만 호출하며 업무 정본의 검증·저장 확정은 Spring이 수행한다. 외부 업무 시스템의 쓰기 권한으로 확장하지 않는다.

### 지식·자원·공급망

- **SEC-08 지식과 검색:** 원본의 출처·사용 조건·검수·공개 범위·버전을 관리하고 미검수 자료와 사례 초안을 공개 검색에 사용하지 않는다. 사례는 문의자 해결 확인, 해당 시스템 담당자의 승인과 동일 승인 버전의 Vector·Neo4j 양쪽 반영이 모두 확인돼야 공개한다. 한쪽 실패·미확인·버전 불일치 또는 권한 확인 실패 시 양쪽에서 공개하지 않는다. 승인과 업무 기록은 보존한다.
- **SEC-09 검색 접근:** 서버가 확인한 현재 사용자·목적·시스템 범위와 공개 상태에 맞는 결과만 검색과 후속 관계 탐색, 모델 입력, 응답에 사용한다. 검색 전 제한과 반환 전 재검증을 설계한다. 캐시·색인과 업무 정본의 권한이나 공개 상태가 불일치하거나 확인되지 않으면 공개하지 않는다. 임베딩과 파생 데이터에도 원본에 상응하는 접근 통제를 적용한다.
- **SEC-10 자원 제한:** 요청 크기·입력량, 요청 빈도·동시 실행, 실행 시간·재시도·모델 호출·입출력 토큰 및 비용을 적절한 경계에서 제한한다. 제한 초과·취소·외부 장애는 안전한 실패로 처리하고 저장된 업무를 보존한다. 한 실행의 제한과 서비스 전체의 제한을 구분한다. 구체 값·적용 위치·오류·복구는 합의 후 설정한다.
- **SEC-11 공급망:** 공통으로 사용하는 모델, 패키지, 데이터와 도구의 출처·버전·사용 조건을 확인하고 알려진 취약점과 변경 영향을 검토한다. 신규 의존성·외부 서비스와 비용은 기존 팀 규칙에 따라 검토한다. 알 수 없는 자료나 의존성을 검증 없이 공통 기본값이나 검색 정본으로 채택하지 않는다.

## 5. 기능별 보안 검증 사례

관련 기능을 변경할 때 적용 가능한 사례를 자동화하고, 실제 연결 전에 경계별 통합 검증을 추가한다. 아래는 목표 결과이며 테스트가 이미 존재하거나 통과했다는 뜻이 아니다. 합성 데이터와 가짜 비밀값을 사용한다.

| 시나리오 | 기대 결과 |
|---|---|
| 인증되지 않은 호출자가 AI 실행 생성·결과 SSE에 접근 | 인증 실패로 거부하고 사용자 문맥과 결과를 노출하지 않는다. 서비스 인증의 실제 방식과 오류 계약은 합의한다. |
| 문의자 A가 B의 문의 ID를 사용하거나 담당자가 다른 시스템 자료를 요청 | 서버가 현재 소유권·담당 관계를 확인해 거부하며 내용이 응답·모델 입력에 포함되지 않는다. |
| 권한 변경 후 조회·SSE 재연결 또는 오래된 캐시 사용 | 현재 권한을 재확인해 접근을 거부한다. 이미 열린 연결의 회수 방식은 구현 전 합의한다. |
| 문의 또는 검색 문서가 이전 지시 무시, 내부 자료 공개, 권한 확대나 도구 실행을 요구 | 외부 데이터의 지시가 권한을 바꾸지 못하고 허용되지 않은 자료·도구·업무 변경이 차단된다. 직접·간접 사례를 각각 확인한다. |
| 모델이 존재하지 않는 근거·다른 시스템·허용되지 않은 도구나 잘못된 인자를 반환 | 소비 전에 검증 실패 또는 권한 거부로 처리하고 외부 호출·업무 저장을 하지 않는다. |
| 모델 응답에 스크립트나 악성 마크업이 포함 | 화면에 안전하게 표시하거나 거부하며 브라우저에서 스크립트가 실행되지 않는다. |
| 미승인 초안, Vector만 성공, Neo4j 미확인 또는 승인 버전 불일치 사례 검색 | 양쪽 경로에서 해당 사례를 공개하지 않고 승인 및 기존 업무 기록을 유지한다. |
| 허용 범위 검색 결과 없음, 권한 거부, 검색 장애 | 내부적으로 세 경우를 구별하고, 사용자에게 권한 밖 자료의 존재나 내부 오류 상세를 노출하지 않는다. |
| 저장·배정 실패 또는 결과 미확인인데 모델이 성공이라고 응답 | 성공으로 확정하지 않는다. 실제 저장 여부를 확인하고 이미 저장된 결과를 보존한다. |
| 큰 입력, 반복 요청, 동시 실행 또는 모델 호출 한도 초과 | 합의된 경계에서 제한하고 안전한 오류를 반환하며 완료된 업무를 되돌리지 않는다. |
| 가짜 비밀번호·토큰이 입력이나 외부 오류에 포함 | 인증 정보가 로그·외부 오류·공유 검증 결과에 기록되지 않는지 확인한다. |

적대적 모델 테스트는 모델·프롬프트·데이터·검색 버전과 실행 조건을 기록한다. 확률적 모델의 응답 결과와 결정론적 권한·출력 검사의 결과를 구분한다. 단일 성공 사례는 인젝션 방어의 완전성을 증명하지 않는다.

## 6. 구현 전 협의와 리뷰

서비스 간 인증과 자격 증명 관리, 권한 문맥의 생성·전달·검증, 결과 스트림 접근, 열린 연결의 권한 회수, 검색 전 필터와 공개 상태 확인, 캐시 일치, 로그 보존, 입력·동시성·토큰·비용 상한, 오류·복구 계약은 담당자 간 합의 후 구체화한다. 실제 운영 데이터는 현재 제품 범위의 가상 데이터와 구분한다. 구체 계약이 정해지기 전 실서비스 연결이 안전하다고 가정하지 않는다.

기능·PR 리뷰에서는 적용된 SEC ID와 관련 기능 인수 조건, 검증한 정상·거부·실패 사례, 실제 실행 환경과 미실행 사항을 확인한다. 기존 [에이전트 통합 안내](AGENT_DEVELOPMENT.md), [기능 명세](../specs/README.md), [데이터 구축 계획](knowledge/DATASETS.md)가 각 도메인의 구체 내용을 소유하며, 공통 원칙을 여러 문서에 복사해 따로 관리하지 않는다.
