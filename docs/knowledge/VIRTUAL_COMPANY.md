# Hops 가상 기업 환경 v0

상태: 데이터 담당자 확정 · 팀 리뷰 전 · 2026-10-26

## 1. 환경

Hops가 지원하는 대상은 Windows 11 PC를 사용하는 일반 사내 직원이다. 직원 단말 OS와 서버 컨테이너 OS는 역할이 다르므로 같을 필요가 없다.

| 구분 | v0 정의 |
|---|---|
| 직원 단말 | Windows 11, PC 웹 브라우저 |
| Demo Portal | 별도 Linux 컨테이너, Docker Compose 실행 |
| 첫 업무 서비스 | 사내 LMS |
| Hops | Demo Portal과 분리된 장애 대응 서비스 |
| 연결 방식 | 포털 오류 화면·도움말에서 Hops 문의 화면으로 연결 |
| 데이터 | 가상 사용자·강의·장애 데이터만 사용 |

Demo Portal과 Hops를 분리하는 이유는 업무 서비스와 장애 대응 서비스를 독립적으로 개발·실패·배포하기 위해서다. 사용자는 포털에서 바로 Hops로 이동할 수 있으므로 별도 서비스라는 구현 경계가 사용 흐름을 끊지는 않는다.

### 원격 접속 표준

가상 기업의 VPN은 **Windows 11 회사 관리형 프로필 + IKEv2 기반 Always On VPN +
Windows Server RRAS + NPS**로 정의한다. 인증서 기반 인증을 지원한다.

- 이 범위는 지식 답변과 Mock 진단용이며 실제 VPN 인프라는 구축하지 않는다.
- 오류 809의 UDP 500·4500 도달성, 오류 812의 NPS 정책, IKEv2 인증서 오류를 구분한다.
- Agent는 방화벽·NPS·인증서·VPN 프로필을 변경하지 않고 근거 기반 안내 또는 `NETWORK` 이관만 제안한다.
- PPTP·GRE 기반 VPN과 DirectAccess는 v0 범위에서 제외한다.

## 2. 역할과 부서

### 사용자 역할

| 역할 | 책임 |
|---|---|
| 문의자 | 문의 등록, 직원 가이드 수행, 해결 여부 응답 |
| IT 담당자 | 자기 부서 티켓 처리, 전 부서 런북 열람, 처리 결과 기록 |
| 업무 관리자 | 배정 예외와 수동 배정, 업무 현황 관리 |
| 에이전트 운영 관리자 | AI 실행 이력과 기술 실패 복구. 업무 결론 변경은 불가 |

### IT 부서 8개

| 코드 | 부서 | 주 범위 |
|---|---|---|
| `ACCOUNT_PERMISSION` | 계정 권한 | 계정·권한·MFA·사용자 인증 |
| `NETWORK` | 네트워크 | VPN·Wi-Fi·사내망·통신 경로 |
| `BACKEND` | Backend | 서버 애플리케이션·API·서비스 인증 |
| `FRONTEND` | Frontend | 웹 화면·브라우저 렌더링 |
| `DB` | DB | DB 연결·잠금·쿼리·데이터 계층 |
| `INFRA` | 인프라 | 컴퓨팅·가상화·스토리지·실행 기반 |
| `SYSTEM` | 시스템 | OS·파일 서버·시스템 서비스 |
| `CS` | CS | 질문 한도 후에도 분류할 수 없는 IT 문의 검토 |

문의 유형과 처리 부서는 일대일 관계가 아니다. Agent는 가상 서비스·관측 근거·부서 카탈로그를 사용해 부서를 제안하고 Spring이 최종 검증한다.

## 3. 서비스 범위

전체 데이터 조사 범위는 다음 네 사용자 서비스다.

| 사용자 서비스 | 원인 컴포넌트 | 현재 상태 |
|---|---|---|
| 계정·인증 | 비밀번호, MFA, SSO | MFA 런북 1건·직원 가이드 4건 담당자 확정, SSO는 라우팅 참조만 있음 |
| 원격 접속 | VPN, Wi-Fi 802.1X | VPN 런북 2건·가이드 1건 담당자 확정, Wi-Fi는 근거 hold |
| 공유 드라이브 | SMB | 런북 3건·직원 가이드 2건 담당자 확정 |
| 사내 포털·LMS | `PORTAL_API`, `PORTAL_DB` | 런북 5건·직원 가이드 3건 담당자 확정, 실제 재현은 아직 수행 전 |

사용자는 “포털이 안 된다”고 문의하므로 화면에는 `PORTAL` 하나로 보인다. 사용자에게 API와 DB를 먼저 고르게 하지 않는다. 내부 진단 후 다음처럼 분기한다.

| 컴포넌트 | 기본 담당 | 대표 근거 |
|---|---|---|
| `PORTAL_API` | `BACKEND` | 애플리케이션 예외, HikariCP 풀 포화 |
| `PORTAL_DB` | `DB` | 연결 한도, Lock·Deadlock, Slow Query |

이 분리는 사용자 UI 분류가 아니라 Diagnosis·Ticket의 정답과 평가 기준이다. 서비스를 추가할 때 사용자 서비스와 내부 컴포넌트를 카탈로그에 추가하면 기존 부서 경계를 다시 만들지 않아도 된다.

## 4. Agent 경계

Agent가 할 수 있는 일:

- 승인된 문서 검색
- 사용자에게 안전한 가이드 안내
- 등록된 읽기 전용 Tool을 통한 관측
- 근거·불확실성·담당 부서 제안
- 해결되지 않거나 근거가 부족할 때 이관 제안

Agent가 하지 않는 일:

- 코드 수정
- 설정 변경
- 배포·재시작
- DB 쓰기·세션 종료
- 해결 완료나 티켓 저장을 모델 판단만으로 확정

기계 판독 정본은 [virtual_company.json](../../datasets/knowledge/v0/catalogs/virtual_company.json)이다.
