# 가상 기업·시스템 초기 명세

기준은 [PRD](../PRD.md)의 단일 기업·한국어 PC 웹·MVP 시스템 3개다. 아래 기능과 업무 규칙은 데이터·매뉴얼·읽기 전용 Mock을 일관되게 만들기 위한 **설계 제안**이다. 구현된 대상 시스템이나 확정된 화면·API를 설명하지 않는다. 현재 활용할 기존 전자결재 데모는 확보되지 않았다.

## 기업과 담당 구조

부서는 임직원의 소속 정보다. 문의 배정은 책임 시스템의 현재 유효한 주담당자 한 명을 기준으로 한다. 한 사람이 여러 시스템을 담당할 수 있다. 가상 인물·부서명·ID와 실제 담당 조합은 소량 데이터 검토 때 정한다.

| 역할 | 데이터에서 확인할 범위 |
|---|---|
| 문의자 | 자신의 문의·대화·해결 확인, 해당 업무 자료에 대한 접근 범위 |
| 시스템 주담당자 | 담당 시스템의 티켓·처리 기록·허용된 내부 지식, 해당 시스템 해결 사례 승인 |
| 업무 관리자 | 권한이 허용된 업무 조회와 책임 시스템·담당자 수동 정정 |

실제 개인정보·조직도를 사용하지 않는다. 역할 이름만으로 모든 대화나 파일에 접근할 수 있다고 가정하지 않는다.

## 최소 기능 범위

| 시스템 | 기능 검토안 | 정상 동작을 명세할 항목 | 대표 문의 |
|---|---|---|---|
| 전자결재 | 문서 작성 | 필수 입력·저장 조건, 작성 중과 제출 후의 구분 | 어디에서 어떻게 작성하는가 |
| 전자결재 | 문서 조회 | 조회 대상·기간 조건·열람 권한, 결과 없음 | 지난 문서가 보이지 않음 |
| 전자결재 | 결재 상태 확인 | 문서 진행 상태의 의미와 볼 수 있는 사용자 | 현재 처리 단계 문의 |
| 전자결재 | 첨부 열람 | 문서·첨부 접근 조건, 없음과 열람 실패의 구분 | 첨부를 열 수 없음 |
| 공통 로그인 | 로그인·SSO | 인증 성공·실패·반복 화면의 구분, 대상 시스템 진입 | 로그인 후 다시 로그인하라고 함 |
| 공통 로그인 | 계정·시스템 접근 신청 | 인증 문제와 시스템 이용 권한 신청의 구분, 신청에 필요한 정보 | 특정 시스템 이용 권한 요청 |
| 파일 공유 | 파일 조회·열람 | 파일 존재·공유 범위·접근 권한, 권한 없음과 결과 없음 | 공유 파일이 열리지 않음 |
| 파일 공유 | 공유·권한 요청 | 공유 대상·업무 목적·허용 범위와 담당자 처리 경계 | 동료에게 파일 공유 요청 |

버튼명·화면 경로·기본 조회 기간·문서 상태 코드·첨부 제한은 아직 정하지 않았다. 매뉴얼의 실제 절차를 쓰기 전에 먼저 정하고 Mock과 일치시킨다. 전자결재의 일괄 다운로드는 변경 요청 시나리오 후보이며, 이미 존재하거나 반드시 없는 기능으로 확정하지 않는다.

## 기능과 권한의 책임 경계

검토안은 공통 로그인이 인증과 시스템 진입 권한을, 각 업무 시스템이 자기 문서·파일의 열람 범위를 담당하는 구조다. 세부 경계는 담당자 검토 후 고정한다. 정상 로그인에 성공했다는 사실만으로 모든 문서·파일의 열람 권한이 있다고 판단하지 않는다.

전자결재와 공통 로그인은 인증 의존 관계를 표현할 수 있다. 전자결재 첨부와 파일 공유의 저장소 연결은 아직 정하지 않았으므로 자동 연결하지 않는다. 특정 상용 SSO·파일 프로토콜·클라우드 제품을 기본 전제로 두지 않는다.

문의자가 현상을 경험한 보고 시스템과 실제 처리를 맡을 책임 시스템은 구분한다. 전자결재에서 로그인 반복을 보고했다면 원 맥락은 전자결재로 보존한다. 대화와 허용된 근거가 공통 로그인의 처리를 뒷받침할 때만 책임 시스템 변경을 제안한다. 의존 관계만 있거나 근거가 부족하면 보고 시스템 담당자가 최초 조사한다. 시스템 자체가 확인되지 않으면 PRD의 시스템 확인 대기를 따른다.

## 매뉴얼과 Mock의 공통 기준

각 기능마다 다음 내용을 정한 뒤 동일한 기준으로 매뉴얼·대화·Mock을 만든다.

- 사용자 목적과 이용 전제, 정상적인 절차와 관찰 가능한 결과.
- 사용자가 확인할 수 있는 정보, 담당자만 볼 수 있는 정보와 접근 조건.
- 결과 없음·권한 거부·조회 오류·조건 불일치의 구분 및 담당자 전달 정보.
- 적용 버전·기능 경계·근거, 아직 정하지 않은 사항.

Mock은 고정된 읽기 전용 관측이다. 계정·권한 변경, 문서 수정, 자동 복구를 에이전트가 실행하는 도구로 만들지 않는다. 대상 시스템 전체를 구현하는 대신 대표 문의를 재현하는 최소 기능만 설계한다.

소량 검토는 문서 조회 사용법, 파일 열람 권한 요청, 로그인 반복의 세 흐름부터 시작하는 안이다. 사용법 안내와 조사·처리 요청을 구분할 수 있는지 확인하고 기능 추가·개선 및 복합 문의로 확장한다. 실제 대화 생성과 Mock 구현은 별도 작업이다.
