# Hops 가상 기업과 시스템

기준: [PRD 1.44](../PRD.md) · 팀 합의 제품 범위. 현재 `datasets/knowledge/v0/catalogs/virtual_company.json`은 기존 4개 서비스·부서 기반 카탈로그이며 새 시스템·담당자 정본이 아니다. 데이터 ID·인물·관계와 실제 예제는 별도 설계·검수한다.

## MVP 환경

하나의 가상 기업 임직원이 자체 계정으로 PC 웹에서 한국어 텍스트 문의를 한다. 부서는 소속 정보이고 배정은 업무 시스템의 유효한 주담당자 한 명을 기준으로 한다. 한 사람이 여러 시스템을 맡을 수 있다. 문의자·시스템 담당자·업무 관리자의 권한을 구분한다.

| 시스템 | 주요 기능 | 예시 | 제공 수준 |
|---|---|---|---|
| 전자결재 | 문서 작성·조회·결재·첨부 | 문서 열람 실패·일괄 다운로드 개선 | 대표 시나리오·제한된 Mock/기존 데모 |
| 공통 로그인 | 로그인·SSO·계정·접근 권한 | 로그인 반복·권한 요청 | 문서·합성 사례·읽기 전용 Mock |
| 파일 공유 | 업무 파일 조회·공유·접근 권한 | 공유 파일 열람 불가 | 문서·합성 사례·읽기 전용 Mock |

보고 시스템과 처리할 책임 시스템은 다를 수 있다. 전자결재 화면의 로그인 현상이 대화와 근거로 공통 로그인 문제임을 뒷받침하면 공통 로그인 담당자에게 배정한다. 근거가 부족하면 보고 시스템 담당자가 먼저 조사한다. 시스템 간 의존 관계만으로 원인을 확정하지 않는다.

시스템 경계·ID·기능·가상 인물·관계는 데이터 설계에서 정한다. 기존 VPN·기술 부서·PORTAL 중심 자료는 기계적으로 이름을 바꾸지 않고 재사용·수정·범위 외를 검토한다. 실제 기업이나 운영 이력으로 표현하지 않는다. 대상 시스템 전체를 새로 구현하지 않는다.

## 후속

인사·전자결재·경비 정산·구매와 인증·문서 저장·알림을 포함한 7개 구성은 후속 목표다. 외부 고객·계열사·테넌트는 범위에 없다.

## 시스템별 기능과 문의 경계

아래는 **가상 시나리오의 범위**다. 실제 제품 화면·코드·배포 환경이나 이미 구축된 Mock API를 의미하지 않는다. ID·기능 상세와 가상 담당자 이름은 데이터 준비에서 정한다.

| 대상 | 예시 기능 | 가능한 문의 | 담당자가 확인할 맥락 |
|---|---|---|---|
| 전자결재 | 문서 작성·조회·결재 상태·첨부 열람 | 문서를 찾지 못함, 첨부를 열 수 없음, 일괄 다운로드 요청 | 현재 기능·기대/실제 동작, 조회 조건·시점, 관련 시스템 근거 |
| 공통 로그인 | 계정·로그인·SSO·접근 권한 | 로그인 반복, 계정 접근이나 권한 신청 | 어떤 시스템에서 어떤 인증 단계에 발생했는지, 사용자에게 확인한 사실·미확인 항목 |
| 파일 공유 | 업무 파일 열람·공유·접근 권한 | 공유 파일을 열 수 없음, 공유 대상 변경 요청 | 파일 공유 기능·업무 목적·접근 범위·표시된 현상 |

권한 요청과 기능 추가·개선은 현상 확인과 별도 의도다. 실제 시스템의 기능 유무나 버튼 명칭을 가상의 요청만으로 확정하지 않는다. 운영 환경의 읽기·쓰기 또는 접근 권한을 부여하는 서비스가 구현된 것처럼 표현하지 않는다.

## 사용자와 소유권 예시

| 역할 | 업무 범위 | 허용 여부를 확인할 기준 |
|---|---|---|
| 문의자 | 자신의 문의·대화·결과 조회, 확인·정정 | 해당 문의의 소유권. 담당자 전용 내부 자료는 자동 공개하지 않는다. |
| 시스템 주담당자 | 현재 맡은 시스템의 관련 티켓·대화·지식 조회, 처리·검증·사례 승인 | 서버의 현재 시스템 담당 관계와 해당 업무 범위. |
| 업무 관리자 | 허용된 업무 조회와 수동 시스템/담당자 정정 지원 | 현재 관리자 권한, 대상 업무와 정정 사유. 모든 대화의 무제한 접근을 뜻하지 않는다. |

한 사람이 전자결재와 다른 시스템을 함께 맡을 수 있다. 가상 데이터에서 시스템별 유효한 주담당자는 하나다. 누락·중복·만료는 정상 데이터에 없다고 가정하지만, 서버가 실제 담당 관계를 확인하지 못하면 배정 성공을 확정하지 않는다. 담당자 선점·수락·휴가 기반 자동 선택은 요구하지 않는다.

## 보고 시스템과 책임 시스템 예

1. 문의자가 전자결재에서 문서가 보이지 않는다고 보고하면 보고 시스템은 전자결재로 보존한다.
2. 문의자와 대화해 화면·기대/실제 동작·발생 시점을 확인한다. 허용된 검색이나 관계를 사용해 추가 확인 항목을 제안할 수 있다.
3. 로그인 공통 기능을 처리 대상으로 볼 만한 대화·근거가 확인되면 공통 로그인을 책임 시스템 후보로 제안한다. Spring이 지원 목록과 주담당자를 검증해 확정한다.
4. 의존 관계만 있거나 근거가 부족하면 전자결재 주담당자가 최초 조사하고 미확인 항목을 보존한다. 담당자 또는 관리자는 잘못된 책임 시스템을 사유·근거와 함께 수동 정정할 수 있다.

## Mock과 데이터 준비

MVP 도구는 허용된 범위의 읽기 전용 Mock이다. 정상·결과 없음·권한 거부·조회 오류를 구분하고 Mock 관측이 실제 운영 상태임을 암시하지 않는다. 실제 시스템 변경·계정 조작·자동 복구·원격 제어는 에이전트 범위 밖이다. 시연에는 문의 저장·티켓·담당자 기록·확인·승인·검색 반영을 실제 HOPS 흐름으로 연결하며 대상 시스템 전체를 새로 만들지 않는다.

초기 자료·기능·인물·관계는 가상 데이터로 설계·검수한다. 기존 v0의 VPN·기술 부서·PORTAL 용어를 새 시스템의 실제 구조나 정답으로 일괄 치환하지 않는다. [데이터 전환 목록](DATA_MIGRATION_REVIEW.md)과 [시나리오](INCIDENT_SCENARIOS.md)를 함께 검토한다.
