# PRD 1.44 지식·문의 목표 정책

상태: 팀 합의 기획에 따른 정책 문서 · 기계 판독 정책 v0 전환·데이터 검수·검색 적재는 미완료. 기존 `POLICY-*.v1.md`와 대응 JSON은 이전 정책 이력이다. 이 문서를 추가했다고 기존 JSON·청크·인덱스의 내용이 자동 갱신되거나 검색에 사용할 수 있다는 뜻은 아니다.

## 문의·시스템·티켓

- Inquiry는 문제당 최대 5회 질문 묶음으로 사실을 확인한다. 시스템이 확인되지 않으면 사용자 시스템 선택을 요청하고 확인 대기를 보존한다. 범위 밖은 안내하며 CS에 임의 배정하지 않는다.
- 독립된 요청·완료 조건은 문제와 티켓으로 분리한다. 저장 성공·실패·미확인을 구분하고 저장 여부 확인 전 재생성하지 않는다. Spring이 권한·버전·중복을 검증한다.
- 보고 시스템을 보존하고 대화·근거로 책임 시스템을 제안한다. 근거가 부족하면 보고 시스템 주담당자가 조사한다. 그래프 의존만으로 원인을 확정하지 않는다. 수동 정정은 근거·사유를 기록한다.

## 해결과 사례

- 담당자 처리·검증, 기능 요청 구현 완료와 문의자 해결 확인을 구분한다. 미해결은 같은 티켓에서 계속 처리하며 무응답은 확인 대기다. 예약 재알림·자동 종료·완료 후 재오픈·장애 그룹 일괄 완료는 제외한다.
- 해결 기록 저장 후 Curator가 초안을 만든다. 문의자 확인 이후 해당 시스템 주담당자가 검토·수정·승인한다. 자기 승인을 허용한다. 무티켓 대화만으로 초안을 만들지 않는다.
- 같은 승인 버전의 Vector와 Neo4j 반영이 모두 성공해야 어느 경로에서든 검색 공개한다. 한쪽 실패·미확인은 비공개이며 업무 기록·승인을 유지한다. 실패 반영 재실행은 필요하지만 전용 화면·자동 재시도는 제외한다.
- 사례의 출처, 문서 버전, 적용 시스템 버전과 조건을 구분한다. 담당자가 현재 환경을 비교하며 미확인은 추정하지 않는다. 구버전 사례를 무조건 차단·삭제하지 않는다. 실패 시도는 업무 이력에 보존한다.

## 접근·평가

Spring이 현재 접근 범위와 승인·공개 상태를 확인한다. 직원 가이드와 담당자 내부 자료를 분리하고 모델의 주장만으로 권한·원인·저장·해결을 확정하지 않는다. 그래프 관계와 과거 사례는 현재 원인 확정이 아니다. 합성 사례의 가상 확인과 실제 HOPS 문의자 확인을 구분한다.

평가 사건의 정답 매핑·숨겨진 요구사항·미래 해결 내용을 KB·프롬프트에 넣지 않는다. 기존 승인된 관련 사례 자체의 검색은 허용한다. 자세한 수명주기는 [Knowledge 수명주기](../KNOWLEDGE_LIFECYCLE.md)를 따른다.

## 데이터 전환 조건

기존 정책 JSON·스키마·가이드·런북·scenario catalog와 생성 청크/해시의 연쇄 갱신 및 검수를 먼저 수행한다. 기존 가상 시스템·부서 시나리오의 정답과 관계를 새 기획으로 기계 치환하지 않는다. 검수 전 `ingest_status=PENDING`을 유지하고 기존 자료를 새 정책의 RAG 근거로 사용하지 않는다.
