## 목적

보고 시스템을 보존하고 책임 시스템 주담당자에게 배정한다.

## 규칙

### 10 · RULE-NEW-ROUTE-ASSIGN

- 조건: 담당자 처리가 필요한 문제가 준비됨
- 에이전트 제안: Ticket이 책임 시스템과 근거를 제안한다.
- 최종 권한: SPRING
- 강제 지점: Spring은 지원 시스템·주담당자를 검증하고 티켓과 배정을 확정한다.
- 사용자에게 보이는 동작: 저장된 배정 결과를 보여준다.
- 필요한 근거: 보고 시스템, 책임 시스템 판단 근거
- 금지 결과: 그래프 의존만으로 원인 확정, 주담당자 미확인 상태에서 배정 성공 표시

### 20 · RULE-NEW-ROUTE-FALLBACK

- 조건: 다른 책임 시스템을 식별할 근거가 부족함
- 에이전트 제안: 확인된 보고 시스템과 미확인 내용을 제안한다.
- 최종 권한: SPRING
- 강제 지점: Spring은 보고 시스템 주담당자에게 최초 조사 업무를 연결한다.
- 사용자에게 보이는 동작: 불확실한 내용을 구분한다.
- 필요한 근거: 확인된 보고 시스템
- 금지 결과: 원인 임의 확정

### 30 · RULE-NEW-ROUTE-RETRY

- 조건: 복합 문의의 일부 티켓 생성이 실패 또는 미확인임
- 에이전트 제안: 실제 미생성으로 확인된 작업만 다시 제안한다.
- 최종 권한: SPRING
- 강제 지점: Spring은 문의 버전과 기존 저장 결과를 먼저 확인한다.
- 사용자에게 보이는 동작: 성공·실패·미확인을 구분한다.
- 필요한 근거: 문제와 저장 결과, 현재 문의 버전
- 금지 결과: 미확인 상태에서 새 티켓 생성, 성공 티켓 취소
