## 목적

## 규칙

### 10 · RULE-NEW-CASE-CONFIRM

- 조건: 담당자가 조치 또는 기능 구현·검증을 마침
- 에이전트 제안: 문제별 해결 확인을 요청한다.
- 최종 권한: SPRING
- 강제 지점: Spring은 사용자 확인을 검증하고 미해결은 같은 티켓에서 계속 처리한다.
- 사용자에게 보이는 동작: 무응답 시 확인 대기를 표시한다.
- 필요한 근거: 담당자 처리 기록, 문의자 응답
- 금지 결과: 무응답 자동 종료, 확인 없는 최종 완료, 완료 후 재오픈

### 20 · RULE-NEW-CASE-DRAFT

- 조건: 담당자가 해결 기록을 저장함
- 에이전트 제안: Curator가 원문과 처리 기록에 근거해 초안을 제안한다.
- 최종 권한: SPRING
- 강제 지점: 초안 실패는 기존 업무 기록이나 완료를 취소하지 않는다.
- 사용자에게 보이는 동작: 담당자가 초안을 확인하고 수정한다.
- 필요한 근거: 연결 처리 기록
- 금지 결과: 무티켓 대화만으로 사례 생성, 실패 시도만으로 해결 사례 생성

### 30 · RULE-NEW-CASE-APPROVE

- 조건: 문의자가 해결을 확인함
- 에이전트 제안: 담당자의 검토를 지원한다.
- 최종 권한: SPRING
- 강제 지점: 해당 시스템 담당자의 승인과 기능 요청의 구현·검증 기록을 검사한다.
- 사용자에게 보이는 동작: 승인과 공개를 구분한다.
- 필요한 근거: 문의자 해결 확인, 담당자 승인
- 금지 결과: 확인 전 사례 공개, 승인 전 사례 공개
