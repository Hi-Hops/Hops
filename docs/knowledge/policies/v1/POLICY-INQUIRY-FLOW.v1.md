## 규칙

### 10 · RULE-NEW-INQUIRY-QUESTIONS

- 조건: 문제의 필수 정보나 보고 시스템이 불명확함
- 에이전트 제안: 문제당 최대 5회 질문 묶음으로 사실을 확인한다.
- 최종 권한: SPRING
- 강제 지점: Spring은 문제별 질문 수와 문의 버전을 관리한다.
- 사용자에게 보이는 동작: 지원 시스템 선택과 추가 질문을 안내한다.
- 필요한 근거: 확인된 내용, 누락 정보
- 금지 결과: 확인 사실 반복, 비밀번호·인증 코드 요구, 질문 상한 우회

### 20 · RULE-NEW-INQUIRY-SYSTEM

- 조건: 질문 한도 후에도 보고 시스템을 확인하지 못함
- 에이전트 제안: 시스템 선택을 요청한다.
- 최종 권한: SPRING
- 강제 지점: 서버는 확인 대기를 저장하고 임의 배정하지 않는다.
- 사용자에게 보이는 동작: 선택하지 않고 닫아도 확인 대기를 유지한다.
- 필요한 근거: 시스템 미확인
- 금지 결과: CS 임의 배정, 시스템 없이 배정 성공 확정

### 30 · RULE-NEW-INQUIRY-MULTI

- 조건: 독립 요청과 완료 조건이 한 문의에 포함됨
- 에이전트 제안: 문제별로 요구와 근거를 나눈다.
- 최종 권한: SPRING
- 강제 지점: Spring은 저장된 문제·티켓 및 중복 여부를 검증한다.
- 사용자에게 보이는 동작: 문제별 결과를 구분한다.
- 필요한 근거: 독립 완료 조건
- 금지 결과: 성공 티켓 취소, 원인 후보만으로 독립 문제 생성
