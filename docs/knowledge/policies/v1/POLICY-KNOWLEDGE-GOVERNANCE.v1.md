## 규칙

### 10 · RULE-NEW-GOV-PUBLISH

- 조건: 해결 확인을 받은 사례가 담당자 승인을 받음
- 에이전트 제안: 승인된 관계 및 사례 반영을 지원한다.
- 최종 권한: SPRING
- 강제 지점: 같은 승인 버전의 Vector·Neo4j 성공 확인 전 양쪽 검색에서 비공개한다.
- 사용자에게 보이는 동작: 승인과 공개 가능 여부를 구분한다.
- 필요한 근거: 승인 버전, 두 저장소 반영 결과
- 금지 결과: 한쪽 성공만으로 공개, 미확인을 성공으로 표시

### 20 · RULE-NEW-GOV-RETRY

- 조건: 한쪽 반영이 실패하거나 결과가 미확인임
- 에이전트 제안: 오류를 확인하고 실패한 반영의 재실행을 지원한다.
- 최종 권한: SPRING
- 강제 지점: 기존 승인·업무 기록을 보존하며 재반영과 공개 조건을 확인한다.
- 사용자에게 보이는 동작: 반영 실패와 성공을 구분한다.
- 필요한 근거: 승인 버전, 반영 상태
- 금지 결과: 반영 실패로 처리 기록 취소, 전용 복구 화면 강제

### 30 · RULE-NEW-GOV-EVAL

- 조건: 평가 데이터와 검색 자료를 구성함
- 에이전트 제안: 현재 사건의 미래 해결 내용과 정답을 감춘다.
- 최종 권한: SPRING
- 강제 지점: 평가 분할·지식 버전·권한을 검토한다.
- 사용자에게 보이는 동작: 정답 노출 없는 평가를 수행한다.
- 필요한 근거: 평가 분할, 고정된 검색 자료
- 금지 결과: 평가 사건 정답 매핑 노출, 조건별로 정답을 다르게 제공
