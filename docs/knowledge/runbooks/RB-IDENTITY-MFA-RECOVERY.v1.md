# MFA 인증 수단 복구 및 재등록 대응

## 적용 범위와 사용자 증상

- 서비스/컴포넌트: IDENTITY / MFA
- 기본 담당: ACCOUNT_PERMISSION
- 적용 환경: HOPS_VIRTUAL_COMPANY
- 제품: Windows 11, Microsoft Entra ID 가상 기업 테넌트 정책
- 문서 상태/인덱싱: DRAFT / PENDING

## 적용 가정

- 가상 기업은 Microsoft Entra ID 기반 MFA를 사용한다.
- 신원 확인과 인증 수단 변경은 계정 권한 담당자가 회사 승인 절차에 따라 수행한다.
- Agent는 인증 수단의 존재·상태를 읽기 전용으로만 확인하며 삭제·초기화·재등록을 실행하지 않는다.
- 직원 답변에는 관리자 화면, 사용자 식별자, Graph 요청, 인증 수단 내부 ID를 노출하지 않는다.

## 범위 밖

- 비밀번호 자체를 분실한 문의
- SSO 애플리케이션 설정 오류
- Agent가 MFA 방법 삭제, 초기화 또는 계정 차단 해제를 실행하는 작업
- 지원 부서가 아닌 사람이 사용자의 인증 코드나 복구 비밀을 수집하는 작업

## 사용자 증상

### SYM-01

사용자 표현:
- 휴대폰을 잃어버려서 인증할 수 없어요.
- 번호를 바꾼 뒤 인증 문자가 오지 않아요.

관측 신호:
- 사용자가 기존 휴대폰 또는 전화번호에 접근할 수 없다.
- 다른 등록 인증 수단의 사용 가능 여부가 확인된다.

### SYM-02

사용자 표현:
- 인증 앱을 더 등록할 수 없다고 나와요.
- 등록된 기기가 너무 많다는 오류가 보여요.

관측 신호:
- 오류 문구가 인증 앱·하드웨어 토큰 등록 한도와 일치한다.
- 기존 로그인 방법을 정리하거나 재등록해야 하는 상태다.

## 진단 1: 요청·로그 연결

### DIA-01 · 비밀번호 문제와 MFA 인증 수단 문제를 구분한다.

- 조치: 사용자에게 비밀번호 입력 단계 통과 여부, 안전한 오류 문구, 휴대폰 분실·번호 변경·코드 미수신·등록 한도 중 해당 증상을 확인한다. 인증 코드와 비밀번호는 수집하지 않는다.
- 도구: 미등록 — 실행 불가
- 기대 신호:
- 비밀번호 검증 뒤 MFA 단계에서 실패한다.
- MFA 관련 오류 유형과 발생 시각이 확인된다.
- 일치 시: DIA-02에서 사용 가능한 다른 인증 수단을 확인한다.
- 불일치 시: 비밀번호 또는 SSO 오류이면 해당 경로로 전환한다.
- 근거: GE-001, GE-052, GE-053

### DIA-02 · 직원이 안전하게 사용할 수 있는 대체 인증 수단이 있는지 확인한다.

- 조치: 사용자 화면에 회사가 허용한 다른 인증 옵션이 표시되는지와 본인이 보안 정보 화면에 접근할 수 있는지만 확인한다. Agent는 인증 수단 목록의 민감값을 요청하지 않는다.
- 도구: 미등록 — 실행 불가
- 기대 신호:
- 사용 가능한 다른 인증 옵션이 있거나 없다.
- 사용자가 본인 보안 정보에 접근 가능한지 구분된다.
- 일치 시: 대체 수단이 있으면 GUID-01을 안내하고, 없으면 DIA-03으로 이동한다.
- 불일치 시: 정보를 확인할 수 없으면 신원 확인이 필요한 계정 권한 문의로 이관한다.
- 근거: GE-001, GE-053

## 진단 2: 계층 구분과 근거 충분성

### DIA-03 · 담당자 복구가 필요한 조건을 구분한다.

- 조치: 읽기 전용 계정 상태가 제공되면 등록 방법 수, 재등록 필요 상태, 로그인 차단 여부를 확인한다. Tool이 없거나 권한이 없으면 상태를 추정하지 않는다.
- 도구: 미등록 — 실행 불가
- 기대 신호:
- 등록 한도 도달, 기존 수단 접근 불가, 연락처 불일치 또는 로그인 차단 후보 중 하나가 확인된다.
- 사람의 신원 확인과 관리자 조치 필요 여부가 구분된다.
- 일치 시: 확인된 후보와 필요한 사람 조치를 기록해 계정 권한 담당자에게 이관한다.
- 불일치 시: 필수 상태를 확인하지 못하면 원인을 단정하지 않고 근거 부족으로 이관한다.
- 근거: GE-001, GE-052, GE-053

## 원인 후보와 반대 신호

### CAUSE-01 · 사용자가 등록 한도만큼 인증 앱 또는 장치를 보유해 새 인증 앱을 추가할 수 없다.

- 필요 신호 ID: SIG-028
- 필요 신호:
- 등록 한도 오류 문구
- 기존 인증 수단이 이미 등록되어 있음
- 반대 신호 ID: SIG-030
- 반대 신호:
- 등록 수에 여유가 있음
- 새 등록이 아니라 기존 휴대폰 분실이 유일한 증상
- 담당 부서: ACCOUNT_PERMISSION
- 근거: GE-001

#### 레지스트리에서 결합된 신호 정의

- SIG-028 [필요] · MFA 등록 한도 오류 (ERROR_MESSAGE)
  - 매칭: mfa_registration_limit
  - 의미: 새 인증 앱 또는 장치를 더 등록할 수 없는 상태
  - 확정 제한: 기존 등록 수단과 조직 정책을 확인하기 전 관리자 삭제를 제안하지 않음
- SIG-030 [반대] · MFA 인증 코드 미수신 (USER_OBSERVATION)
  - 매칭: mfa_code_not_received
  - 의미: 등록된 연락 수단으로 인증 코드가 도착하지 않는 증상
  - 확정 제한: 번호 변경·통신 지연·계정 차단 중 원인을 단독 확정하지 않음

### CAUSE-02 · 휴대폰 분실·번호 변경·코드 미수신 또는 계정 차단으로 기존 MFA 방법을 사용할 수 없다.

- 필요 신호 ID: SIG-027, SIG-030
- 필요 신호:
- 기존 전화 또는 번호에 접근할 수 없음이나 코드 미수신
- 다른 인증 방법으로도 로그인할 수 없거나 계정 상태 확인이 필요함
- 반대 신호 ID: SIG-028
- 반대 신호:
- 다른 인증 옵션으로 정상 로그인됨
- 등록 한도 오류만 발생함
- 담당 부서: ACCOUNT_PERMISSION
- 근거: GE-052, GE-053

#### 레지스트리에서 결합된 신호 정의

- SIG-027 [필요] · 비밀번호 성공 후 MFA 실패 (AUTH_STAGE)
  - 매칭: password_verified+mfa_failed
  - 의미: 비밀번호 문제와 추가 인증 수단 문제를 분리
  - 확정 제한: 계정 차단·MFA 등록 상태는 별도 확인
- SIG-030 [필요] · MFA 인증 코드 미수신 (USER_OBSERVATION)
  - 매칭: mfa_code_not_received
  - 의미: 등록된 연락 수단으로 인증 코드가 도착하지 않는 증상
  - 확정 제한: 번호 변경·통신 지연·계정 차단 중 원인을 단독 확정하지 않음
- SIG-028 [반대] · MFA 등록 한도 오류 (ERROR_MESSAGE)
  - 매칭: mfa_registration_limit
  - 의미: 새 인증 앱 또는 장치를 더 등록할 수 없는 상태
  - 확정 제한: 기존 등록 수단과 조직 정책을 확인하기 전 관리자 삭제를 제안하지 않음

## Agent 사용자 안내와 처리 경계

### GUID-01 · Agent 안내

- 조건: 사용자 화면에 회사가 허용한 다른 인증 옵션이 표시되는 경우
- 안내: 다른 인증 옵션을 한 번 선택하고, 본인이 확인할 수 있는 전화번호가 올바른지만 확인하도록 안내한다. 인증 코드·비밀번호·전체 전화번호는 Hops에 입력하지 않도록 알린다.
- 예상 결과: 대체 인증 수단으로 로그인하거나 잘못된 연락처·접근 불가 상태를 구분한다.
- 미해결 시: 반복 시도를 중단하고 발생 시각과 안전한 오류 문구를 첨부해 계정 권한 부서로 이관한다.
- 근거: GE-053

### GUID-02 · Agent 안내

- 조건: 휴대폰 분실, 등록 한도, 대체 수단 부재 또는 계정 상태 확인이 필요한 경우
- 안내: 사용자에게 신원 확인 후 MFA 재등록 또는 복구가 필요하다고 안내하고 계정 권한 부서로 이관한다. 관리자 화면과 삭제 절차는 제공하지 않는다.
- 예상 결과: 사용자는 추가 비밀정보를 제출하지 않고 담당자 신원 확인 절차로 이동한다.
- 미해결 시: 담당자 확인 전 해결 완료로 표시하지 않는다.
- 근거: GE-001, GE-052, GE-053

### Agent 처리 경계

- 허용 결과: GUIDE_USER, HANDOFF
- 이관 사유: INSUFFICIENT_EVIDENCE, GUIDANCE_NOT_RESOLVED
- 금지 작업: CODE_CHANGE, CONFIG_CHANGE, DEPLOY, RESTART, DB_WRITE
- 해결 확정 근거: USER_CONFIRMATION, BACKEND_STATE

## 이관 후 IT 담당자 조치·검증

### RES-01 · 사람 수행

- 조치: 회사 계정 복구 정책에 따라 사용자의 신원을 확인하고, 등록 한도·기존 수단 접근 가능성·연락처·로그인 차단 상태를 관리자 화면에서 확인한다.
- 승인 필요: 예
- 확인: 사용자와 대상 계정이 일치하고 필요한 복구 유형이 기록된다.
- 롤백: 해당 없음
- 근거: GE-001, GE-052, GE-053

### RES-02 · 사람 수행

- 조치: 확정된 원인에 따라 승인된 관리자 기능으로 재등록 요구, 잘못된 연락처 수정 또는 불필요한 인증 수단 정리를 수행한다. Graph 직접 삭제는 기본 절차로 사용하지 않는다.
- 승인 필요: 예
- 확인: 사용자가 새 인증 수단을 등록할 수 있고 회사 정책의 최소 인증 수단을 충족한다.
- 롤백: 잘못된 계정을 변경했거나 사용자가 로그인할 수 없으면 즉시 변경을 중단하고 계정 보안 관리자에게 승격한다.
- 근거: GE-001, GE-052, GE-053

### RES-03 · 사람 수행

- 조치: 사용자와 함께 로그인·MFA 등록을 재시험하고 기존 분실 장치가 더 이상 사용되지 않는지 확인한다.
- 승인 필요: 아니오
- 확인: 사용자가 승인된 인증 수단으로 로그인에 성공하고 해결을 확인한다.
- 롤백: 재시험에 실패하면 티켓을 닫지 않고 RES-01의 계정 상태를 다시 확인한다.
- 근거: GE-001, GE-052, GE-053

### 완료 판정

성공 신호:
- 사용자가 승인된 인증 수단으로 로그인한다.
- 새 인증 수단 등록 또는 기존 수단 사용이 정상이다.
- 사용자가 해결을 확인한다.

실패 신호:
- 대체 인증 수단을 사용할 수 없다.
- 재등록 후에도 같은 오류가 발생한다.
- 신원 또는 계정 상태를 확인할 수 없다.

### 이관

- 대상: ACCOUNT_PERMISSION
- 조건:
- 다른 인증 옵션으로 해결되지 않음
- 휴대폰 분실·번호 변경으로 기존 수단 접근 불가
- 등록 한도 또는 로그인 차단 상태 확인 필요
- 첨부 근거:
- 발생 시각
- 안전한 오류 문구와 증상 유형
- 대체 인증 옵션 사용 가능 여부
- 사용자가 제공한 비민감 계정 식별 정보
