# VPN 오류 코드별 진단 및 이관

## 적용 범위와 사용자 증상

- 서비스/컴포넌트: REMOTE_ACCESS / VPN
- 기본 담당: NETWORK
- 적용 환경: HOPS_VIRTUAL_COMPANY
- 제품: Windows 11, Windows Server Always On VPN 지원 버전
- 문서 상태/인덱싱: DRAFT / PENDING

## 적용 가정

- 가상 기업은 IKEv2 기반 Always On VPN과 NPS를 사용한다.
- 직원 PC의 RasClient 이벤트와 서버의 NPS·RRAS 이벤트는 권한이 적용된 읽기 전용 경로로만 조회한다.
- 오류 코드 하나는 원인 확정이 아니라 진단 분기 신호로 사용한다.
- Agent는 방화벽·인증서·NPS 정책·VPN 프로필을 변경하지 않는다.

## 범위 밖

- 오류 720의 WAN Miniport 상세 조치
- PPTP·GRE 기반 VPN 환경
- 사내 Wi-Fi 802.1X 인증 문제
- Agent가 인증서를 설치하거나 방화벽·NPS·VPN 설정을 변경하는 작업

## 사용자 증상

### SYM-01

사용자 표현:
- 재택에서 VPN 오류 809가 나요.
- VPN 서버가 응답하지 않는다고 해요.

관측 신호:
- RasClient 이벤트에 오류 809가 기록된다.
- VPN 서버까지 UDP 500 또는 4500 경로 문제 후보가 존재한다.

### SYM-02

사용자 표현:
- VPN 인증 방식이 맞지 않는다고 연결이 거부돼요.
- VPN에서 인증서 관련 오류가 보여요.

관측 신호:
- 오류 812 또는 이벤트 20276이 인증 정책 불일치를 나타낸다.
- 오류 13806·13801·0x80070040·0x800B0109가 인증서 구성·신뢰 문제 후보를 나타낸다.

## 진단 1: 요청·로그 연결

### DIA-01 · 사용자 증상과 정확한 VPN 오류 코드를 연결한다.

- 조치: 발생 시각, VPN 프로필 이름, 안전한 오류 문구를 확인하고 RasClient 이벤트의 오류 코드를 읽는다. 사용자명·인증서 원문·공인 IP는 Agent 응답에서 마스킹한다.
- 도구: 미등록 — 실행 불가
- 기대 신호:
- RasClient 이벤트와 사용자의 발생 시각이 일치한다.
- 오류 코드를 800·809·812·인증서 계열 또는 기타로 구분한다.
- 일치 시: DIA-02에서 오류 코드별 관측값을 확인한다.
- 불일치 시: 코드와 로그를 확인할 수 없으면 네트워크·클라이언트·계정 원인을 단정하지 않고 이관한다.
- 근거: GE-011

### DIA-02 · 도달성·인증 정책·인증서 분기를 구분한다.

- 조치: 오류 809는 승인된 포트 도달성 관측을, 오류 812는 NPS 이벤트와 인증 방식 일치를, 인증서 계열은 만료·EKU·신뢰 체인·서버 이름 일치를 읽기 전용으로 확인한다.
- 도구: 미등록 — 실행 불가
- 기대 신호:
- 오류 코드에 대응하는 서버 또는 네트워크 신호가 확인된다.
- 서로 다른 오류 계열의 반대 신호가 함께 기록된다.
- 일치 시: CAUSE-01부터 CAUSE-03 중 근거가 맞는 후보로 이동한다.
- 불일치 시: 코드와 대응 신호가 맞지 않으면 코드만으로 원인을 확정하지 않는다.
- 근거: GE-011

## 진단 2: 계층 구분과 근거 충분성

### DIA-03 · 단일 사용자 문제와 공통 VPN 서비스 문제를 구분한다.

- 조치: 같은 시간대의 영향 사용자 수, 동일 오류 코드 반복, VPN 서버·NPS 공통 이벤트를 집계한다. 원시 사용자 목록은 Agent에 제공하지 않는다.
- 도구: 미등록 — 실행 불가
- 기대 신호:
- 한 사용자·한 단말 문제인지 여러 사용자의 공통 장애인지 구분된다.
- 기본 담당 부서와 협업 부서 후보가 근거와 함께 정리된다.
- 일치 시: 영향 범위와 근거를 첨부해 NETWORK로 이관한다.
- 불일치 시: 영향 범위가 불명확하면 단일 사용자 장애로 단정하지 않고 관측 공백을 기록한다.
- 근거: GE-011

## 원인 후보와 반대 신호

### CAUSE-01 · 방화벽·NAT·라우터가 IKEv2에 필요한 UDP 500 또는 4500 통신을 차단해 오류 809가 발생한다.

- 필요 신호 ID: SIG-034, SIG-035, SIG-036
- 필요 신호:
- RasClient 오류 809
- VPN 서버가 응답하지 않으며 UDP 500·4500 경로 차단 관측
- 반대 신호 ID: SIG-037, SIG-040
- 반대 신호:
- UDP 경로가 정상이고 NPS가 인증 요청을 거부함
- 오류가 720으로 기록됨
- 담당 부서: NETWORK
- 근거: GE-011

#### 레지스트리에서 결합된 신호 정의

- SIG-034 [필요] · RasClient Event ID 20227 (WINDOWS_EVENT)
  - 매칭: RasClient/20227
  - 의미: VPN 연결 실패 시각과 반환 오류 코드를 연결
  - 확정 제한: 이벤트 자체는 원인이 아니며 포함된 오류 코드와 범위를 추가 확인
- SIG-035 [필요] · VPN 오류 809 (ERROR_CODE)
  - 매칭: VPN_ERROR_809
  - 의미: VPN 서버까지 필요한 네트워크 통신이 성립하지 않은 도달성 계열 오류
  - 확정 제한: 방화벽·NAT·라우팅 중 어느 계층인지 단독 확정하지 않음
- SIG-036 [필요] · IKEv2 UDP 500·4500 도달성 (NETWORK_REACHABILITY)
  - 매칭: udp/500|udp/4500
  - 의미: IKEv2 협상에 필요한 UDP 경로의 허용 여부
  - 확정 제한: 포트 관측만으로 인증서·NPS 문제를 배제하지 않음
- SIG-037 [반대] · VPN 오류 720 (ERROR_CODE)
  - 매칭: VPN_ERROR_720
  - 의미: PPP IP 프로토콜 구성 또는 주소 할당 실패 계열 오류
  - 확정 제한: 클라이언트 binding과 서버 주소 할당 문제를 추가 구분
- SIG-040 [반대] · VPN 오류 812·NPS Event 20276 (AUTH_POLICY)
  - 매칭: VPN_ERROR_812|NPS/20276
  - 의미: 클라이언트 인증 방식과 NPS 정책 조건이 일치하지 않을 가능성
  - 확정 제한: NPS 거부 사유와 적용 정책을 확인하기 전 정책 불일치로 확정하지 않음

## Agent 사용자 안내와 처리 경계

### GUID-01 · Agent 안내

- 조건: 사용자가 정확한 오류 코드를 확인할 수 있는 경우
- 안내: 오류 코드와 발생 시각을 기록하고, 회사가 허용한 다른 네트워크가 있다면 한 번만 재시도하도록 안내한다. 방화벽 해제·인증서 설치·VPN 프로필 수정은 안내하지 않는다.
- 예상 결과: 환경별 재현 차이를 확인하거나 동일 오류가 반복됨을 확인한다.
- 미해결 시: 오류 코드와 재시도 결과를 첨부해 NETWORK로 이관한다.
- 근거: GE-011

### GUID-02 · Agent 안내

- 조건: 오류 812 또는 인증서 계열 오류가 확인된 경우
- 안내: 사용자에게 서버 인증 정책 또는 인증서 점검이 필요하다고 안내하고 추가 변경 없이 이관한다.
- 예상 결과: 사용자는 반복 로그인이나 임의 인증서 설치를 중단하고 담당자 점검을 기다린다.
- 미해결 시: NPS·인증서 담당이 확인할 수 있도록 NETWORK 티켓을 유지한다.
- 근거: GE-011

### Agent 처리 경계

- 허용 결과: GUIDE_USER, HANDOFF
- 이관 사유: INSUFFICIENT_EVIDENCE, GUIDANCE_NOT_RESOLVED
- 금지 작업: CODE_CHANGE, CONFIG_CHANGE, DEPLOY, RESTART, DB_WRITE
- 해결 확정 근거: USER_CONFIRMATION, BACKEND_STATE

## 이관 후 IT 담당자 조치·검증

### RES-01 · 사람 수행

- 조치: 오류 코드에 따라 클라이언트 RasClient, VPN 서버 RRAS, NPS 로그를 같은 시간대로 비교하고 영향 범위를 확정한다.
- 승인 필요: 아니오
- 확인: 사용자 요청과 서버 측 연결·인증 이벤트가 시간과 코드로 연결된다.
- 롤백: 해당 없음
- 근거: GE-011

### RES-02 · 사람 수행

- 조치: 확정 원인에 따라 네트워크 경로, NPS 인증 조건 또는 인증서 배포를 회사 변경 절차와 승인 아래 수정한다.
- 승인 필요: 예
- 확인: 같은 클라이언트와 프로필에서 VPN 연결이 성공하고 관련 오류 이벤트가 재발하지 않는다.
- 롤백: 변경 후 다른 사용자 연결 실패가 증가하면 승인된 이전 정책·인증서·방화벽 설정으로 되돌린다.
- 근거: GE-011

### RES-03 · 사람 수행

- 조치: 수정 후 단일 사용자와 별도 시험 계정에서 재연결을 확인하고 사용자 해결 여부를 받는다.
- 승인 필요: 아니오
- 확인: 연결·사내 자원 접근이 정상이고 사용자가 해결을 확인한다.
- 롤백: 재현되면 티켓을 재개하고 오류 코드 분류부터 다시 확인한다.
- 근거: GE-011

### 완료 판정

성공 신호:
- VPN 연결이 성공한다.
- 동일 오류 코드가 재발하지 않는다.
- 사용자가 사내 자원 접근과 해결을 확인한다.

실패 신호:
- 동일 오류가 반복된다.
- 서버·NPS 관측과 오류 코드가 연결되지 않는다.
- 변경 후 다른 사용자에게 새 오류가 발생한다.

### 이관

- 대상: NETWORK
- 조건:
- 직원 안전 재시도로 해결되지 않음
- 809·812·인증서 계열 오류 확인
- 서버·NPS·방화벽·인증서 변경 필요
- 첨부 근거:
- 발생 시각과 VPN 프로필 이름
- RasClient 오류 코드
- 다른 네트워크 재시도 결과
- 마스킹된 RRAS·NPS·인증서 상태 요약
