# IT 용어집 50건 담당자 검수

검수일: 2026-10-27
검수 역할: 데이터 담당자 (`DATA_OWNER`)
상태: 담당자 확정 · 팀 리뷰 전

## 목적

직원 질문과 IT 담당자 설명에서 같은 용어를 같은 뜻으로 사용하게 한다. 용어집은
장애 원인 정답이나 실행 절차가 아니며, 정의 자체만 RAG 검색 후보가 된다.

## 검수 기준

1. 가상 기업의 4개 서비스와 Hops 지식 처리에 실제로 쓰이는 용어인가.
2. 정의가 짧고 특정 원인을 단정하지 않는가.
3. 운영 명령, 원시 로그, 내부 설정, 개인정보, 비밀값을 포함하지 않는가.
4. 직원에게 인용해도 안전한가.
5. 오류 코드별 판정 규칙이나 관측 신호를 용어집에 중복하지 않는가.

## 결과

| 구분 | 수량 | 내용 |
|---|---:|---|
| 기존 검토 | 35 | PORTAL API·PostgreSQL·관측·RAG 기본 용어 |
| 범위 보완 | 15 | MFA·SSO 3, VPN 7, SMB 5 |
| 최종 | 50 | 담당자 확정, 팀 리뷰 대기 |

기존 정의 중 `leak detection`, `Slow Query`, `Index Scan` 3건은 단일 신호나
실행계획만으로 문제를 확정하지 않도록 표현을 보수적으로 고쳤다.

50건 모두 짧은 정의만 담고 있어 v0에서는 `EMPLOYEE/QUOTABLE` 후보로 둔다.
`RAG`, `청크`, `임베딩`은 Hops의 동작 방식에 관한 질문에 설명할 수 있지만 장애
원인 판정 근거로는 사용하지 않는다.

## 신호 레지스트리와의 경계

- 용어집: “무엇을 뜻하는가”를 설명하며 RAG 검색 후보가 된다.
- 신호 레지스트리: 로그·메트릭·오류 코드의 매칭과 확정 한계를 정의하며 독립 RAG에 넣지 않는다.
- 런북: 증상·원인 후보·필요/반대 신호·안내·이관 절차를 제공한다.

오류 코드별 의미와 판정 규칙은
[`ERROR_SIGNALS.md`](ERROR_SIGNALS.md)의 정본에서 관리한다.

## 아직 검증하지 않은 것

- 팀원 1명 이상의 내용 리뷰
- 실제 검색 질의에서의 용어 검색 정확도
- 사용자 답변에서 불필요한 전문 용어가 과도하게 노출되지 않는지 여부
