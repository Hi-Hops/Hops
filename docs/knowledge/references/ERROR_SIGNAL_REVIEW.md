# 오류·관측 신호 55건 AI 사전 검수

> **PRD 1.44 전환:** 아래는 기존 v0 검수·자료다. 새 3개 시스템·담당자·접근 범위와 해당 JSON 카탈로그를 함께 재검토하며 과거 확인을 새 자료 승인이나 검색 적재로 간주하지 않는다.

검수일: 2026-10-27
상태: 데이터 담당자 확정 · 팀 리뷰 전

## 검수 기준

1. 확정된 4개 서비스와 컴포넌트 범위에 포함되는가.
2. 사용자 진술, 로그, 메트릭, 이벤트 또는 읽기 조회로 관측할 수 있는가.
3. 하나의 신호만으로 원인을 확정하지 않도록 한계가 적혀 있는가.
4. 직원에게 관리자 절차·원시 로그·개인정보를 노출하지 않는가.
5. 런북·시나리오와 출처 관계를 추적할 수 있는가.
6. Agent가 수정·재시작·배포·DB 쓰기를 수행한다는 의미가 없는가.

## 결과

| 구분 | 수량 | 설명 |
|---|---:|---|
| 담당자 확정 | 55 | 현재 가상 기업 범위에서 정의를 사용할 수 있음 |
| 담당자 결정 필요 | 0 | 없음 |
| 제외 권고 | 0 | 현재 범위를 벗어나거나 안전상 삭제해야 할 신호 없음 |

`검수 준비 완료`는 팀 승인이나 RAG 적재 승인이 아니다. 신호 레지스트리 자체는
계속 RAG에 적재하지 않으며, 런북 청크 생성 시 필요한 정의만 결합한다.

## 자동 보정한 항목

| 대상 | 보정 내용 |
|---|---|
| `SIG-003` | 같은 예외 지문이 근본 원인을 확정하지 않는다는 제한을 추가 |
| `SIG-009` | Hikari 설정명과 실제 leak 경고의 의미를 구분하고 단독 누수 확정을 금지 |
| `SIG-014` | 실제로 참조하는 DB Lock 런북을 출처 관계에 추가 |
| `SIG-020` | 반복 slow query 판단에 필요한 `calls`를 해당 원인 가설의 필수 신호 ID에 추가 |
| `SIG-029` | 대체 인증 수단의 존재 여부와 실제 접근 가능 상태를 명확히 하고 인증정보 수집을 금지 |
| `SIG-055` | WAN Miniport 드라이버 손상을 관측 사실처럼 확정하지 않고 이상 후보로 제한 |

## 확정한 VPN 환경

다음 3개는 가상 기업의 VPN 표준 환경과 함께 유지하기로 확정했다.

| ID | 신호 | 필요한 환경 가정 |
|---|---|---|
| `SIG-036` | IKEv2 UDP 500·4500 도달성 | IKEv2 기반 VPN 사용 |
| `SIG-040` | VPN 오류 812·NPS Event 20276 | NPS 인증 정책 사용 |
| `SIG-041` | IKEv2 인증서 오류 계열 | 인증서 기반 IKEv2 연결 사용 |

가상 기업의 VPN은 **Windows 11 + IKEv2 기반 Always On VPN + RRAS + NPS**로
정의한다. 세 신호와 `RB-REMOTE-VPN-CODES`를 유지하되 실제 VPN 인프라는 구축하지
않고 Knowledge-only 및 Mock fixture로 검증한다. 오류 720 런북도 별도로 유지한다.

## 아직 검증하지 않은 것

- 실제 MCP Tool 출력 필드와 신호 매칭
- Demo Portal·Mock 환경의 관측 재현
- 검색 정확도와 Evidence Bundle 조립 결과
- 실제 해결 CASE와의 일치 여부
