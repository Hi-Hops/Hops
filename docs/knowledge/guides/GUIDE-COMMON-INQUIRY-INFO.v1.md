# IT 문의 전에 준비할 정보

## 적용 상황

- Hops에 IT 장애 또는 사용 문의를 처음 등록하려 함
- 오류 원인이나 담당 부서를 모르는 상태에서 문의하려 함

## 사용자 표현

- IT 문의할 때 어떤 정보를 적어야 하나요?
- 어느 부서 문제인지 모르겠어요.
- 오류가 났는데 무엇을 준비해야 하나요?

## 안전한 확인 순서

1. 문제가 발생한 서비스·화면·장치를 적습니다.
   - 예상 결과: Hops가 문의 범위를 구분할 수 있습니다.
2. 발생 시각, 안전한 오류 문구·코드, 수행하던 작업을 적습니다.
   - 예상 결과: 지식 문서와 읽기 전용 관측 결과를 같은 시점에 연결할 수 있습니다.
3. 본인만 겪는지 다른 사용자도 겪는지, 업무 영향과 가능한 우회 방법을 적습니다.
   - 예상 결과: 영향 범위와 우선순위 판단에 필요한 정보가 준비됩니다.
4. 여러 문제가 섞였다면 문제별로 구분해 설명합니다.
   - 예상 결과: Hops가 필요한 경우 문제별 처리 경로와 티켓으로 나눌 수 있습니다.

## 중단 및 이관 조건

- 비밀번호·인증 코드·토큰·개인정보를 입력해야만 설명할 수 있다고 생각되는 경우
- 업무 전체가 중단되거나 여러 사용자가 동시에 영향을 받는 경우
- 어떤 서비스인지 전혀 구분할 수 없는 경우

## 문의에 준비할 정보

- 서비스·화면·장치
- 발생 시각
- 안전한 오류 문구·코드
- 재현한 작업
- 영향 사용자와 업무 범위
- 우회 가능 여부

## 하지 말아야 할 일

- 비밀번호·인증 코드·토큰·개인정보를 입력하지 않기
- 내부 서버 주소나 원시 로그 전체를 붙이지 않기
- 같은 저장·제출 작업을 반복하지 않기
- 원인을 추측해 담당 부서를 임의로 확정하지 않기

## 계보

- 관련 런북: 없음
- 공개 근거: 없음
- 프로젝트 정책: PRD-3.1, PRD-3.2, PRD-3.5
