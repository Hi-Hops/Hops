# Knowledge·평가 데이터 검수 체크리스트 — PRD 1.44

상태: 신규 검수 기준 · 아직 데이터 검수나 적재를 완료하지 않았다. [데이터 범위](DATASETS.md), [전환 목록](DATA_MIGRATION_REVIEW.md), [수명주기](KNOWLEDGE_LIFECYCLE.md)를 함께 확인한다.

## 공통·접근

- [ ] 가상 자료와 실제 운영 자료를 구분하고 출처·사용 조건·버전·공개 범위를 확인했다.
- [ ] 전자결재·공통 로그인·파일 공유와 기능 경계, 시스템별 주담당 관계를 검토했다.
- [ ] 직원 공개 가이드와 담당자 내부 런북을 분리하고 민감정보·원격 제어·쓰기 절차를 부적절하게 공개하지 않는다.
- [ ] 기존 v0 자료의 기술 사실과 새 정책 적용 여부를 각각 확인했고 전환 전 자료를 새 검색 정본으로 취급하지 않았다.

## 문의와 담당자 연결

- [ ] 사용법·권한·현상·기능 추가·개선을 구분하고 질문 한도 5회 및 시스템 확인 대기를 검증했다.
- [ ] 보고/책임 시스템 구분, 근거 부족 시 보고 시스템 담당자 조사, 수동 정정과 미확인 항목을 확인했다.
- [ ] 독립 문제별 성공·실패·저장 미확인과 재시도 전 기존 저장 확인을 검토했다.

## 해결 사례·검색

- [ ] 처리 기록·문의자 확인·담당자 승인·Vector 반영·Neo4j 반영·공개를 구분했다.
- [ ] 기능 요청의 구현·검증 완료를 확인하고 실패 시도를 해결 사례로 취급하지 않는다.
- [ ] 같은 승인 버전의 양쪽 반영 성공 전 어느 검색 경로에서도 공개하지 않는다.
- [ ] 문서 버전·시스템 적용 버전·적용 조건, 합성/데모/실제 출처, 가상 확인과 실제 확인을 구분했다.
- [ ] 오래된 사례를 버전만으로 자동 차단하지 않고 적용 여부를 담당자가 확인한다.

## 평가·변환

- [ ] 평가 사건의 숨겨진 정답·미래 해결 내용·정답 매핑이 검색 자료와 프롬프트 예시에 들어가지 않았다.
- [ ] 표현 변형을 원 사건과 같은 분할에 두고 비교 조건·지식 버전·권한·모델을 고정했다.
- [ ] JSON·schema·문서·청크·해시·manifest의 연결과 검수·적재 상태를 확인했다.
- [ ] 공통 데이터 PR을 리뷰했으며 실제 통합·평가를 실행한 경우에만 결과를 기록했다.

기존 v0의 검수 상태는 이번 검수 완료를 뜻하지 않는다.

## 문서 유형별 추가 검수

### 직원 가이드

- [ ] 대상 시스템·기능·사용자가 하려는 작업과 안내가 필요한 조건이 명확하다.
- [ ] 직원이 확인할 수 없는 서버 내부 정보·다른 사람의 개인 정보·비밀번호·인증 코드를 요구하지 않는다.
- [ ] 실제 화면이나 기능이 확인되지 않은 가상 예시는 가정으로 표시하고, 미해결 시 담당자에게 전달할 정보와 한계를 정리했다.
- [ ] 공개 가능한 근거와 적용 버전·출처를 추적하고 담당자 런북의 내부 절차를 직원 답변에 그대로 포함하지 않는다.

### 담당자 런북·관계

- [ ] 현상·확인할 사실·가능 원인·반대 근거 또는 미확인 항목을 구분했다.
- [ ] 관계 데이터·검색 유사도만으로 현재 사건의 원인을 확정하지 않는다. 읽기 Mock과 실제 운영 관측은 구분한다.
- [ ] 시스템 간 책임 후보가 달라지는 근거와 미확인 시 보고 시스템 담당자의 조사 경계를 검토했다.
- [ ] 실제 시스템 변경·원격 제어를 AI의 자동 도구로 요구하지 않으며, 담당자 참고자료의 공개 범위를 제한했다.

### 정책과 해결 사례

- [ ] `HOW_TO`, 권한 요청, 현상 확인, 기능 추가·개선과 내부 처리 유형을 구분하고 데이터에서 모델 출력/서버 확정을 혼동하지 않는다.
- [ ] 실제 처리 기록, Curator 초안, 문의자 확인, 담당자 승인과 검색 반영을 각각 확인한다. 기능 요청의 실제 구현·검증 기록이 있다.
- [ ] 사례 원문·티켓·처리 기록의 연결과 문서 버전·시스템 적용 버전·조건이 있다. 적용 버전을 모르면 미확인으로 기록한다.
- [ ] 합성·데모 검증·실제 운영을 구분하고 가상 문의자 확인 설정을 실제 확인으로 표시하지 않는다.
- [ ] 각 저장소의 동일 승인 버전 반영 성공을 확인하지 못하면 어떤 검색 경로에서도 공개하지 않는다.

### 산출물과 연결 검증

- [ ] 원문·JSON·설명 문서·관련 시나리오·스키마의 식별자와 버전을 확인하고 검토 상태를 실제 결과에 맞게 표시한다.
- [ ] 청크·manifest·해시가 생성되는 데이터라면 정본 변경 후 생성기와 함께 검증한다. 설명 문서만 수정해 검색 데이터가 바뀐 것처럼 표시하지 않는다.
- [ ] 권한 거부, 검색 0건/오류, 저장소 부분 실패/미확인/버전 불일치와 복구를 가상 사례로 확인한다.
- [ ] 작성자 외 팀원의 공통 데이터 PR 리뷰 결과와 제품 내 담당자 사례 승인을 각각 기록한다.

이 체크리스트는 내용·데이터 리뷰 기준이며 실제 모델 품질, 서버 권한, 색인 반영 또는 전체 E2E 테스트의 통과를 대체하지 않는다.
