# 에이전트 개발·통합 안내

기준: [PRD 1.44](PRD.md) · 팀 합의 제품 방향 / 구현 및 실제 검증 별도. 실제 환경·설정과 현재 단일 baseline, 규칙 라우터·Fake 구현 범위는 [AI 실행 안내](../ai/README.md)를 따른다. 기존 동작을 이미 새 기획이 구현된 것으로 보지 않는다.

## 1. 개발 목표와 책임

MVP부터 모델 판단 기반 Supervisor와 Inquiry·Knowledge·Ticket·Curator를 연결한다. Inquiry는 대화·질문·문제 분리, Knowledge는 Vector·Neo4j 검색과 조건부 분석, Ticket은 표준 요청 및 책임 시스템 제안, Curator는 해결 기록의 사례 초안·기존 관계 후보 제안을 담당한다. Diagnosis는 별도 역할이 아니다. 모든 문의가 모든 역할을 실행하지 않는다.

Python은 제안과 근거를 반환하고, Spring이 인증·권한·저장·배정·완료·승인·공개를 확정한다. 조회 도구는 허용된 읽기 전용 Mock이다. 실행 코드는 모델의 선택을 허용 경로·시간·호출·토큰·재시도 범위로 제한한다. 모델·임베딩·예산과 실제 실행 계약은 기능별로 정한다.

## 2. 통합 경로

1. 시스템·기능·주담당자와 표준 요청, 역할별 입력·출력·실패 계약을 합의한다.
2. 가상 데이터와 Mock을 준비하고 실제 모델로 Inquiry→필요 시 Knowledge→Ticket→Spring 저장·배정을 연결한다. 보고 시스템과 책임 시스템을 분리한다.
3. 문제별 질문 최대 5회, 시스템 확인 대기, 무티켓 안내, 복합 문의와 부분 실패·결과 미확인을 검증한다.
4. 담당자 기록·문의자 해결 확인·Curator 초안·담당자 승인과 동일 버전 양쪽 검색 반영·재검색을 연결한다.
5. 권한·늦은 결과·중복 요청·두 저장소 부분 실패와 복구를 확인하고 고정된 데이터로 평가한다.

Curator 실패가 업무 저장을 취소하지 않는다. 승인과 양쪽 반영 전 CASE를 두 검색 경로에서 숨긴다. 같은 승인 버전의 각 반영 상태, 재반영 식별·권한·공개 검증 방법은 [API](API.md) 및 역할 담당자가 구현 전 합의한다.

## 3. 데이터와 평가

대상은 전자결재·공통 로그인·파일 공유의 가상 시스템이다. 합성·데모 검증·실제 운영 출처를 구분하며 합성 CASE에는 가상 문의자 확인 설정을 표시한다. 검수 전 자료는 적재하지 않는다. 테스트 정답·미래 해결 내용을 검색 자료나 프롬프트에 넣지 않는다.

같은 데이터·문서 버전·권한·모델 조건에서 Vector 단독과 관계 보강, 원문과 표준화를 비교하고 응답 시간을 기록한다. 검색 결과와 답변의 품질을 별도 측정한다. 단일/멀티 비교나 단일 baseline 신규 개발은 필수가 아니다. 수량·분포·목표는 데이터 준비 후 정한다.

## 4. 작업 책임과 미결정

- AI: [에이전트 계약](../contracts/agents/README.md)의 목표 경계와 실제 코드 간 차이를 정리한다.
- Knowledge·데이터: [지식 수명주기](knowledge/KNOWLEDGE_LIFECYCLE.md), 가상 시스템, 스키마·시나리오의 출처와 리뷰를 관리한다.
- Spring: [데이터](DATA.md)·[API](API.md)의 승인되지 않은 물리 계약을 구체화하고 저장·권한·부분 실패를 검증한다.
- Frontend: [기능 명세](../specs/README.md)와 실제 화면을 구분하고 처리·확인·사례 승인 흐름을 연결한다.
- 공통: API·상태·그래프 스키마·예산·담당·평가 데이터 분할을 정하고 실제 통합/E2E와 Mock 검사를 별도로 보고한다.

## 5. 역할별 준비물과 관찰 가능한 완료 조건

각 역할 담당자를 특정 개인으로 확정하는 표가 아니다. 실제 작업 배정·일정과 공통 데이터 선정은 팀이 정한다. 역할별 구현에 앞서 [에이전트 계약](../contracts/agents/README.md)의 입력·결과·실패와 소비자 영향을 리뷰한다.

### 5.1 Supervisor·Inquiry

- **준비:** 한국어 최초 문의, 문제별 추가 응답·정정, 시스템이 모호한 경우와 범위 밖, 독립된 두 요청, 기존에 저장된 티켓을 포함한 가상 대화.
- **구현 대상:** 문의 의도·확인 사실·미확인 항목, 문제당 최대 5회 질문 묶음, 지원 시스템 확인 및 시스템 선택 대기, 독립 완료 조건의 문제 분리. Supervisor의 모델 판단과 허용된 실행 경로를 구분한다.
- **완료 확인:** 시스템을 확인하지 못하면 선택 대기를 보존한다. 같은 문제의 질문 수를 재실행마다 초기화하지 않는다. 최신 입력 버전만 반영하고 기존 티켓을 반복 생성하지 않는다. 모델 실패를 범위 밖이나 CS 배정으로 바꾸지 않는다.

### 5.2 Knowledge·관계 검색

- **준비:** 직원 공개 가이드·담당자 내부 자료, 출처·권한·문서 버전이 있는 합성 사례, 시스템·기능·증상·가능 원인·확인 항목의 관계와 적용 조건. 실제 공통 데이터·모델·임베딩은 검토 후 선정한다.
- **구현 대상:** Vector 의미 검색과 필요한 Neo4j 관계 탐색, 접근 범위 검사, 추가 질문·원인 후보·근거·미확인 항목의 조건부 분석. 실제 시스템 쓰기·원격 제어는 제외한다.
- **완료 확인:** 근거가 없으면 없다고 반환하고 검색 오류와 구분한다. 그래프 연결만으로 원인을 확정하지 않는다. 검색 경로 모두에서 승인·동일 버전 양쪽 반영·권한을 검사하고 담당자에게 적용 버전과 조건을 보여준다.

### 5.3 Ticket·Spring 업무 연결

- **준비:** 세 시스템·주담당자 목록의 가상 데이터, 보고/책임 시스템이 같은 경우·다른 경우·근거가 부족한 경우, 복합 문의와 기존 성공 작업·저장 미확인 사례.
- **구현 대상:** 문제별 표준 요청, 제목·내용·처리 유형·책임 시스템 후보와 근거 제안. Spring은 지원 시스템·담당자·버전·권한과 기존 저장을 확인한다.
- **완료 확인:** AI가 티켓 저장·담당자 배정 성공을 만들어내지 않는다. 일부 실패해도 성공 티켓이 유지된다. 저장 여부 미확인은 새로 만들지 않고 기존 결과 확인 후 실제 미생성 작업만 재시도한다.

### 5.4 Curator·지식 공개

- **준비:** 담당자의 합성 처리·검증 기록, 문의자 확인, 기능 구현 완료 기록, 가상 확인 설정을 포함한 합성 사례, 중복/관계 연결 후보와 반영 실패 시나리오.
- **구현 대상:** 처리 기록 저장 후 자동 초안, 담당자의 확인·수정, 문의자 해결 확인 후 승인, 동일 승인 버전의 Vector·Neo4j 반영과 실패한 반영의 재실행.
- **완료 확인:** 초안 실패가 처리 기록·업무 완료를 취소하지 않는다. 문의자 확인·담당자 승인·양쪽 동일 버전 반영이 모두 확인되기 전 양쪽 검색에서 비공개한다. 문서 버전과 시스템 적용 버전을 구분한다.

## 6. 공통 통합 사례와 검증 증거

| 사례 | 관찰할 결과 |
|---|---|
| 정보 부족·사용자 모름 | 문제별 질문 수를 보존하고 필요한 정보를 추정으로 채우지 않는다. |
| 시스템 미확인 | 다섯 번의 질문 묶음 안에서도 불명확하면 시스템 선택 대기를 저장하고 화면을 닫아도 보존한다. |
| 다른 책임 시스템 | 전자결재 보고·공통 로그인 책임의 근거와 주담당자 검증을 구분한다. 근거 부족 시 보고 시스템 담당자가 조사한다. |
| 무티켓 안내 | 승인 직원 가이드에 근거해 안내하고 문의자의 해결 확인 전 완료로 확정하지 않는다. |
| 복합 문의·부분 실패 | 독립 요청의 티켓은 분리하고 저장된 성공을 유지한다. 저장 미확인에서는 신규 생성하지 않는다. |
| 정정·늦은 결과 | 최신 문의 버전을 확인하고 기존 티켓과 원문/이력을 보존한다. |
| 기능 구현·미해결 | 구현·검증 기록 후 확인을 요청하고 미해결이면 같은 티켓에서 처리한다. |
| 사례 한쪽 실패 | 같은 승인 버전의 두 반영 전 양쪽 검색을 차단하고 승인·기록은 보존한다. |
| 반영 복구·재검색 | 실패한 반영을 재실행한 뒤 두 성공과 권한을 확인하고 다음 문의에서 적용 버전·조건을 제시한다. |
| 권한·검색 실패 | 타인 문의·담당자 내부 자료를 노출하지 않는다. 검색 0건, 권한 거부, 시스템 오류를 구분한다. |

각 결과에는 사용한 입력·기대 결과·데이터/프롬프트/모델/검색 버전과 실제 실행 환경을 기록한다. Mock·Fake 테스트, 실제 모델 호출, Spring 저장 연동, 전체 브라우저 E2E와 평가를 분리한다. 모델 내부 사고 과정·비밀값·실제 개인정보를 산출물에 넣지 않는다.

## 7. 담당 작업과 통합 리뷰 산출물

- 역할별 입출력 의미·버전·오류와 정상/정보 부족/실패 사례, 영향을 받는 생산자·소비자.
- 인증·현재 권한·조회 범위, 도구 허용 범위 및 거부 시 동작.
- 같은 업무 작업 식별, 서버 저장 확인, 중복·동시성·이전 버전 차단 및 부분 실패 결과.
- Curator와 각 색인 반영의 승인 버전, 실패·미확인 시 비공개와 재실행 조건.
- 실제 실행한 테스트·명령·결과, 미실행 사유, 환경변수의 이름과 목적. 비밀값은 제외한다.
- 새로운 공통 데이터·검색 설정의 출처·사용 조건·검수/평가 결과. 개인 실험은 공통 기본값과 구분한다.

현재 개발 버전·명령은 [AI](../ai/README.md), [Spring](../backend/spring/hops/README.md), [Frontend](../frontend/README.md)와 실제 설정을 따른다. 문서의 예시만으로 의존성이 설치됐거나 실제 통합이 실행됐다고 판단하지 않는다.
