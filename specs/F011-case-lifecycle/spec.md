# F011 해결 사례 초안·승인·검색 공개

상태: PRD 1.44 목표 · 상세 계약·화면·구현·통합 검증 전. 관련 문서: [PRD](../../docs/PRD.md), [API](../../docs/API.md), [데이터](../../docs/DATA.md), [지식 수명주기](../../docs/knowledge/KNOWLEDGE_LIFECYCLE.md).

## 목표와 사용자

시스템 주담당자는 실제 처리 기록으로 생성된 사례 초안을 확인·수정하고, 문의자의 해결 확인 후 승인한다. 기능 요청은 구현·검증 기록도 필요하다. 문의자 확인 및 담당자 승인이 없으면 검색에 공개하지 않는다.

## 인수 조건

- **F011-AC01** 담당자 해결 기록 저장 직후 Curator 실행을 요청하고, 초안 실패가 저장된 업무 기록이나 완료를 취소하지 않는다.
- **F011-AC02** 시스템 담당자가 원문·실제 조치·검증·적용 조건·공개 범위·민감정보를 확인·수정한다. 별도 검토자 없이 자기 승인을 허용한다.
- **F011-AC03** 문의자 해결 확인과 담당자 승인 및 같은 승인 버전의 Vector·Neo4j 반영이 모두 성공한 사례만 검색 공개한다.
- **F011-AC04** 반영 하나가 실패하거나 상태 미확인이면 어느 검색 경로에서도 공개하지 않는다. 승인 및 업무 기록은 보존한다.
- **F011-AC05** 원인 수정 뒤 실패 반영을 재실행할 수 있다. 중복 방지·재실행 권한·조작은 구현 계약에서 정하고 전용 화면·자동 재시도는 요구하지 않는다.
- **F011-AC06** 결과에 시스템 적용 버전과 조건을 제공하며 버전을 모르면 미확인으로 표시한다. 오래된 사례를 자동 삭제·차단하지 않는다.
- **F011-AC07** 합성 사례의 가상 문의자 확인과 실제 HOPS에서 수행한 확인을 출처와 함께 구분한다.

## 화면과 사용자 흐름

### 화면

- 시스템 담당자의 사례 초안 조회·수정·승인과 검색 반영 상태 표시. 별도 복구 화면은 요구하지 않으며 실제 경로는 미정이다.
- 담당자 사례 검색 결과는 적용 시스템·버전·조건을 함께 표시한다.

### 흐름

1. 담당자 해결 기록이 저장되면 Curator가 사례 초안과 기존 관계 연결 후보를 제안한다.
2. 문의자가 해결을 확인한 뒤 해당 시스템 담당자가 초안을 수정·승인한다.
3. 같은 승인 버전의 Vector·Neo4j 반영을 확인하고 양쪽 성공 후 권한별 검색에 공개한다.

## 상세 인수 조건과 예외

- **F011-DETAIL-01 초안 실패:** Curator 실행이 실패해도 저장된 담당자 기록과 업무 완료를 취소하지 않으며 검색 공개로 표시하지 않는다.
- **F011-DETAIL-02 검토·수정:** 담당자는 원문·실제 조치·검증 결과·적용 조건·공개 범위·민감정보를 확인한다. 별도 지식 검토자 없이 자기 승인을 허용한다.
- **F011-DETAIL-03 문의자 확인:** 문의자의 해결 확인 전이나 담당자의 승인 전에는 공개하지 않는다. 기능 요청은 실제 구현·검증 완료 기록도 확인한다.
- **F011-DETAIL-04 부분 반영:** Vector만 또는 Neo4j만 성공하면 양쪽 검색에서 해당 승인 버전을 반환하지 않는다. 성공한 반영과 승인·업무 기록은 보존한다.
- **F011-DETAIL-05 미확인·버전 불일치:** 한쪽 결과가 미확인이거나 승인 사례와 색인 버전이 다르면 공개 가능으로 취급하지 않는다.
- **F011-DETAIL-06 재반영:** 원인을 수정하고 실패한 반영을 다시 실행한다. 자동 재시도·전용 복구 화면은 제외하며 조작·권한·멱등성은 미정이다.
- **F011-DETAIL-07 버전·적용:** 사례 문서 버전과 적용 시스템 버전을 구분하고 알 수 없는 적용 버전은 미확인으로 표시한다. 오래된 사례를 무조건 삭제·차단하지 않는다.
- **F011-DETAIL-08 출처:** 합성 사례의 가상 문의자 확인 설정과 실제 HOPS 확인을 구분한다. 실제 운영 이력으로 오인하지 않는다.
- **F011-DETAIL-09 검색 권한:** 직원용 공개 지식과 담당자 내부 자료를 분리하고 서버가 승인·공개 상태 및 현재 접근 권한을 검색 양쪽 경로에서 검증한다.
- **F011-DETAIL-10 무티켓·실패:** 담당자 처리 기록이 없는 무티켓 안내 대화만으로 초안을 만들지 않는다. 실패 시도는 업무 이력에 남기되 해결 사례로 게시하지 않는다.

## 계약·화면 상태

- 사례 ID·문서 버전·대상 시스템/적용 버전·출처·확인·승인·Vector/Neo4j 결과 및 공개 여부가 필요하다. 실제 필드명·상태 코드·경로는 목표 공통 계약에서 협의한다.
- 사례 수정 후 새 버전·재승인, 부분 반영의 중복 방지와 공개의 구체 처리 방식은 구현 전에 정한다.

| 상태 | 사용자에게 보이는 동작 |
|---|---|
| 로딩·처리 중 | 현재 요청의 진행을 표시하고 저장·완료로 단정하지 않는다. |
| 정상 결과 | 서버가 확정한 값만 표시한다. |
| 빈 결과 | 정상 조회된 0건을 안내한다. |
| 실패·결과 미확인 | 실패와 저장 미확인을 구분하고 입력·이미 저장된 결과를 보존한다. |
| 권한 없음 | 서버가 접근을 거부하고 허용되지 않은 내용을 표시하지 않는다. |

## 범위·연관 기능

- 완료 후 재오픈, 사례 자동 재검토·비활성화·폐기 전파와 시스템 직접 변경은 제외한다.

## 현재 구현과 남은 작업

담당자 기록·Curator·승인·두 검색 저장소 반영의 실제 연동 및 통합 검증은 별도다.

기능의 목표 인수 조건은 구현·통합 검증을 대신하지 않는다. 새 API 경로·필드·enum·권한과 테스트 연결은 담당자 간 계약 확정 후 진행한다.
