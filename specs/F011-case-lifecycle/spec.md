# F011 해결 사례 초안·승인·검색 공개

상태: PRD 1.44 목표 · hops-system-1 구체 계약·화면안 추가 / 팀 리뷰·구현·통합 검증 별도. 관련 문서: [PRD](../../docs/PRD.md), [API](../../docs/API.md), [데이터](../../docs/DATA.md), [지식 수명주기](../../docs/knowledge/KNOWLEDGE_LIFECYCLE.md).

## 목표와 사용자

시스템 주담당자는 실제 처리 기록으로 생성된 사례 초안을 확인·수정하고, 문의자의 해결 확인 후 승인한다. 기능 요청은 구현·검증 기록도 필요하다. 문의자 확인 및 담당자 승인이 없으면 검색에 공개하지 않는다.

## 인수 조건

- **F011-AC01** 담당자 해결 기록 저장 직후 Curator 실행을 요청하고, 초안 실패가 저장된 업무 기록이나 완료를 취소하지 않는다.
- **F011-AC02** 시스템 담당자가 원문·실제 조치·검증·적용 조건·공개 범위·민감정보를 확인·수정한다. 별도 검토자 없이 자기 승인을 허용한다.
- **F011-AC03** 문의자 해결 확인과 담당자 승인 및 같은 승인 버전의 Vector·Neo4j 반영이 모두 성공한 사례만 검색 공개한다.
- **F011-AC04** 반영 하나가 실패하거나 상태 미확인이면 어느 검색 경로에서도 공개하지 않는다. 승인 및 업무 기록은 보존한다.
- **F011-AC05** 원인 수정 뒤 실패 반영을 재실행할 수 있다. 중복 방지·재실행 권한·조작은 아래 index-checks/index-retries 계약안을 따르며 전용 화면·자동 재시도는 요구하지 않는다.
- **F011-AC06** 결과에 시스템 적용 버전과 조건을 제공하며 버전을 모르면 미확인으로 표시한다. 오래된 사례를 자동 삭제·차단하지 않는다.
- **F011-AC07** 합성 사례의 가상 문의자 확인과 실제 HOPS에서 수행한 확인을 출처와 함께 구분한다.

## 화면과 사용자 흐름

### 화면

- 시스템 담당자의 사례 초안 조회·수정·승인과 검색 반영 상태 표시. 별도 복구 화면은 요구하지 않으며 목표 경로는 아래 신규 계약안에서 제안한다.
- 담당자 사례 검색 결과는 적용 시스템·버전·조건을 함께 표시한다.

### 흐름

1. 담당자 해결 기록이 저장되면 Curator가 사례 초안과 기존 관계 연결 후보를 제안한다.
2. 문의자가 해결을 확인한 뒤 해당 시스템 담당자가 초안을 수정·승인한다.
3. 같은 승인 버전의 Vector·Neo4j 반영을 확인하고 양쪽 성공 후 권한별 검색에 공개한다.

## 상세 인수 조건과 예외

- **F011-DETAIL-01 초안 실패:** Curator 실행이 실패해도 저장된 담당자 기록과 업무 완료를 취소하지 않으며 검색 공개로 표시하지 않는다.
- **F011-DETAIL-02 검토·수정:** 담당자는 원문·실제 조치·검증 결과·적용 조건·공개 범위·민감정보를 확인한다. 별도 지식 검토자 없이 자기 승인을 허용한다.
- **F011-DETAIL-03 문의자 확인:** 문의자의 해결 확인 전이나 담당자의 승인 전에는 공개하지 않는다. 기능 요청은 실제 구현·검증 완료 기록도 확인한다.
- **F011-DETAIL-04 부분 반영:** Vector만 또는 Neo4j만 성공하면 양쪽 검색에서 해당 승인 버전을 반환하지 않는다. 성공한 반영과 승인·업무 기록은 보존한다.
- **F011-DETAIL-05 미확인·버전 불일치:** 한쪽 결과가 미확인이거나 승인 사례와 색인 버전이 다르면 공개 가능으로 취급하지 않는다.
- **F011-DETAIL-06 재반영:** 원인을 수정하고 FAILED 반영을 수동 재실행한다. UNKNOWN은 먼저 결과를 확인한다. 조작·권한·멱등성은 아래 신규 계약안을 따르며 자동 재시도·전용 복구 화면은 제외한다.
- **F011-DETAIL-07 버전·적용:** 사례 문서 버전과 적용 시스템 버전을 구분하고 알 수 없는 적용 버전은 미확인으로 표시한다. 오래된 사례를 무조건 삭제·차단하지 않는다.
- **F011-DETAIL-08 출처:** 합성 사례의 가상 문의자 확인 설정과 실제 HOPS 확인을 구분한다. 실제 운영 이력으로 오인하지 않는다.
- **F011-DETAIL-09 검색 권한:** 직원용 공개 지식과 담당자 내부 자료를 분리하고 서버가 승인·공개 상태 및 현재 접근 권한을 검색 양쪽 경로에서 검증한다.
- **F011-DETAIL-10 무티켓·실패:** 담당자 처리 기록이 없는 무티켓 안내 대화만으로 초안을 만들지 않는다. 실패 시도는 업무 이력에 남기되 해결 사례로 게시하지 않는다.

## 계약·화면 상태

신규 `hops-system-1` 팀 리뷰용 구체 계약안이다. 필드·enum은 [DATA_TYPES](../contracts/DATA_TYPES.md#신규-계약-hops-system-1), REST·오류·SSE·멱등성은 [WIRE_CONTRACT 12절](../contracts/WIRE_CONTRACT.md#12-신규-계약-hops-system-1), 업무 전이는 [TARGET_CONTRACT](../contracts/TARGET_CONTRACT.md)가 정본이다. 아래 내용은 구현·팀 승인·통합 완료 표시가 아니다.

| 조작 | 계약·검증 |
|---|---|
| 검토 진입 | 목표 /cases 목록·/cases/:caseId 상세. 담당 시스템·상태·페이지, 원 티켓 case 탭과 연결 |
| 초안 생성 | CaseGeneration은 원 검증 WorkRecord당 한 작업. FAILED는 담당자 수동 재시도, NO_REUSABLE_CASE는 사례 없음 |
| 편집·승인 | CaseEditCommand/CaseApproveCommand. 현재 담당 관계·원 기록 해결 응답·기능 검증·caseVersion 검사 |
| 승인 후 편집 | 새 DRAFT 버전 생성·재승인. 기존 승인/공개 버전은 자동 삭제·차단하지 않음 |
| 반영·확인 | CaseDetail.indexes의 저장소별 버전·상태와 Publication 표시. UNKNOWN은 index-checks로 확인 |
| 실패 반영 | FAILED 저장소만 index-retries. 성공한 반영·승인·업무 기록은 유지 |

| 화면 상태 | 관찰 가능한 동작 |
|---|---|
| 생성 중·실패·재사용 없음 | 업무 저장과 분리, 초안 없음과 실행 실패를 구별 |
| 초안·문의자 확인 전 | 검토·수정 가능, 승인 불가 사유 표시 |
| 승인·반영 중 | 승인과 공개를 별도 표시 |
| 부분 실패·UNKNOWN·버전 불일치 | 해당 버전 양쪽 비공개·허용된 확인/재실행 |
| SEARCHABLE | 동일 승인 버전의 두 성공+현재 ACL 검증 후 공개 표시 |

## hops-system-1 검증 시나리오

- **F011-CONTRACT-01:** 같은 WorkRecord 이벤트 중복은 Curator 작업·초안을 중복 생성하지 않는다.
- **F011-CONTRACT-02:** 해당 원 기록의 문의자 응답이 미해결이면 초안을 승인하지 못한다.
- **F011-CONTRACT-03:** 한쪽 실패/UNKNOWN/다른 버전 성공에서는 Vector와 Neo4j 양쪽 검색 모두 해당 승인 버전을 반환하지 않는다.
- **F011-CONTRACT-04:** 승인된 v1을 편집해 v2 초안을 만들더라도 v1 공개를 무조건 끄거나 v2를 자동 승인하지 않는다.
- **F011-CONTRACT-05:** 권한 없는 관리자는 사례를 승인하지 못하고 현재 시스템 담당자의 자기 승인은 가능하다.

문서/JSON 검사·Mock·실제 서버 저장/권한·실제 AI/검색·브라우저 E2E를 분리해 결과를 기록한다. 기존 테스트의 이전 AC 번호를 새 시나리오 통과로 간주하지 않는다.

## 범위·연관 기능

- 완료 후 재오픈, 사례 자동 재검토·비활성화·폐기 전파와 시스템 직접 변경은 제외한다.

## 현재 구현과 남은 작업

담당자 기록·Curator·승인·두 검색 저장소 반영의 실제 연동 및 통합 검증은 별도다.

기능의 목표 인수 조건은 구현·통합 검증을 대신하지 않는다. hops-system-1 계약안의 담당자 리뷰·승인 후 코드·테스트를 전환한다. 현재 구현을 문서만으로 완료 처리하지 않는다.
