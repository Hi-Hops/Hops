# 기능·계약·구현 작업 연결

기준: [PRD 1.44](../docs/PRD.md)·[hops-system-1 계약안](contracts/TARGET_CONTRACT.md). 아래는 제안 작업 단위다. GitHub 이슈를 생성·수정·완료한 기록이 아니며 실제 이슈 번호·담당·상태는 별도 확인한다.

공통 계약 문서 정리는 [이슈 #67](https://github.com/Hi-Hops/Hops/issues/67)에서 추적한다. 물리 ERD는 [이슈 #66](https://github.com/Hi-Hops/Hops/issues/66)의 별도 작업이며, 문서 PR에서 해당 구현 이슈를 완료 처리하지 않는다.

| 작업 | 범위·완료 증거 | 선행 |
|---|---|---|
| D1 전체 계약 리뷰 | C01~C10의 타입·전이·REST/SSE·AI State/wire·엔티티·공개·화면과 예시 검토 | PRD 1.44 |
| D2 환경·저장 선정 | S01~S08 산출물 중 관련 연결에 필요한 값과 DDL·마이그레이션 | D1, 선정 검수 |
| B1 인증·시스템 기반 | 현재 PRIMARY·v2 auth·권한·journal/outbox·DTO | D1, 관련 D2 |
| B2 문의·배정 | 문의/문제/정정·시스템 선택·AI 결과 검증·티켓 유일 저장/복구 | B1·AI1 |
| AI1 실제 상담 | 모델 Supervisor·Inquiry·Knowledge·Ticket·검색/읽기 Mock | D1, 모델/검색/예산 선정 |
| F1 문의 화면 | F001~F005·F008·F010 신규 어댑터·시스템/문제별 상태·접수 모달 | D1; 실서버 검증은 B1/B2 |

문서·화면·Fake 검사만으로 전체 MVP 완료를 표시하지 않는다. D1에는 사례/공개까지 전체 계약을 포함하며 F3/AI2는 이미 정한 범위를 구현하는 순서다. 기존 이슈의 부서 배정·선점·단일 에이전트·자동 종료/재이관 목표는 그대로 신규 완료 기준으로 사용하지 않는다.
