# 기능 명세와 공통 계약

기준: [PRD 1.44](../docs/PRD.md) · 팀 합의 제품 기획. 각 기능의 목표 인수 조건은 구현·통합 검증 완료를 뜻하지 않는다. [목표 공통 계약](contracts/TARGET_CONTRACT.md)은 상세 API·상태·역할 계약의 논리 초안이며, 기존 코드·Mock이 사용하는 [전환 전 계약](contracts/README.md)과 구분한다.

## MVP 기능

| ID | 목표 기능 | 주요 연계 |
|---|---|---|
| [F001](F001-auth/spec.md) | 로그인·시스템 담당 권한 | F002·F007·F009 |
| [F002](F002-realtime/spec.md) | SSE 진행과 재접속·상태 복구 | F003~F011 |
| [F003](F003-chat/spec.md) | 문의·추가 질문·시스템 확인·무티켓 안내 | F004·F005·F008 |
| [F004](F004-revision/spec.md) | 메시지 정정·버전·보완 정보 | F003·F005·F009 |
| [F005](F005-result-cards/spec.md) | 문제별 결과·복수 티켓·부분 실패 | F008·F010 |
| [F006](F006-my-inquiries/spec.md) | 내 문의와 해결 확인 | F009·F011 |
| [F007](F007-admin-view/spec.md) | 업무 관리자 조회와 수동 정정 지원 | F009 |
| [F008](F008-split-consent/spec.md) | 한 문의의 복합 문제 분리 | F003·F005 |
| [F009](F009-department-tickets/spec.md) | 담당 시스템 업무·처리·수동 정정 | F006·F011 |
| [F010](F010-creation-failures/spec.md) | 문제별 티켓 생성 복구 | F005 |

F008·F009의 디렉터리 이름은 현재 참조 경로를 유지한 것이다. 별도 새 문의 동의와 부서 선점은 새 기능 목표가 아니다. 신규 경로·필드·enum·권한·서비스 간 입출력은 관련 기능 구현 전에 합의한다. 자세한 미결정 사항은 [구현 계약 질문](QUESTIONS.md)을 따른다.

## 구현 상태와 이전 이력

현재 코드·Mock은 일부 기능의 이전 부서 중심 동작을 구현한다. 각 기능 명세는 구현 현황을 별도로 적는다. 기존 테스트의 인수 조건 ID는 이전 구현을 가리키며 새 목표 조건과 별개다. [Mock](mocks/README.md)은 기존 계약 기반이므로 새 시스템 배정·해결 확인·사례 공개가 구현됐다는 증거가 아니다. 단위/Mock 검사와 실제 저장·권한·AI·E2E 검증을 구분한다.
