# F006 내 문의 목록·상세

상태: 개발 기준 확정 / 구현·검증 별도 · 범위: MVP 최소 개인 세션 목록·채팅 재진입 / 독립 상세 모달은 후속 · 담당: frontend(화면) · 협의: backend(조회)
근거: PRD 4.1, 4.5 · API 1, 2.1 · DATA 1, 3 · ERD `inquiry`

## 확정 범위와 남은 작업 (2026-10-25)

MVP는 AC01~AC03의 최소 목록과 AC10~AC12의 세션/재진입이다. AC04~AC09의 독립 상세 모달 및 연결 예외는 후속 완료 조건이다. 목록 기본 20·최대 100, createdAt DESC·id DESC. 숨김/검색/확장 필터는 후속이다.

정확한 타입·enum은 [DATA_TYPES](../contracts/DATA_TYPES.md), 정책은 [WIRE_CONTRACT 10절](../contracts/WIRE_CONTRACT.md#10-인증재접속최신-대화분석-재시도-추가-프로필), 담당 구현·미검증은 [11절](../contracts/WIRE_CONTRACT.md#11-담당별-구현과-검증-상태)을 따른다. 확정은 개발 기준 선택이며 팀 리뷰/병합·서비스 구현 완료가 아니다.

## 1. 목표

본인 문의의 종합 상태와 문제·티켓별 진행을 확인하고, 같은 문의의 채팅을 이어간다. (PRD 4.5)

## 2. 화면

| 화면 | 경로(제안) | 접근 |
|---|---|---|
| 내 문의 목록 | `/inquiries` | 로그인 사용자(본인 문의) |
| 문의 상세 모달 | `/inquiries/:inquiryId` | 문의 소유자 |

## 3. 사용자 시나리오

1. 문의자가 내 문의 목록에서 최근 문의와 종합 상태를 본다.
2. 문의를 누르면 상세 모달에서 AI 요약, 문제별 상태, 연결된 티켓 목록을 본다.
3. "대화 이어가기"로 그 문의의 채팅으로 이동한다.
4. 모달을 닫으면 보던 목록 페이지로 돌아온다.

## 4. 인수 조건

- **F006-AC01 본인 문의 목록**
  `GET /api/inquiries`로 본인 문의만 보여 준다. 각 행에 제목, 종합 상태, 생성 시각을 표시한다. (API 2.1 · ERD `inquiry.title`, `inquiry_status`, `created_at`)
- **F006-AC02 페이지**
  목록은 `{items, page, size, totalElements}` 형식으로 받고, 페이지는 0부터 센다. (API 1 · 기본 크기 Q-BE-5)
- **F006-AC03 빈 목록과 실패 구분**
  문의가 없으면 "아직 문의가 없어요"와 메인으로 가는 버튼을, 조회 실패면 실패 안내와 다시 시도를 보여 준다. 실패를 빈 목록으로 보이지 않게 한다. (PRD 4.11)
- **F006-AC04 상세 모달**
  `GET /api/inquiries/{id}`로 AI 요약(기준 시각 포함), 문제별 상태, 연결 티켓 목록과 세부 현황, 생성 실패, 현재 실행을 보여 준다. 표시 규칙은 F005와 같다. (PRD 4.5 · API 2.1 · ERD `inquiry.summary`, `summary_updated_at`)
- **F006-AC05 대화 기록 없음**
  상세 모달에 채팅 로그를 넣지 않는다. 대화는 "대화 이어가기"로 채팅 화면에서 본다. (PRD 4.5 · API 2.1)
- **F006-AC06 담당자 화면으로 이동하지 않음**
  모달의 티켓 목록에서 담당자용 티켓 상세로 이동하는 링크를 두지 않는다. (PRD 4.5)
- **F006-AC07 남의 문의**
  다른 사람의 문의 주소로 들어오면 내용을 보여 주지 않고 권한 없음(403) 또는 찾을 수 없음(404) 화면을 보여 준다. (API 2.1 "타인 문의 거부" · PRD 4.11)
- **F006-AC08 모달 닫기**
  모달을 닫으면 목록의 페이지·필터를 그대로 유지한다. 주소로 모달을 직접 열 수 있다. (PRD 4.11)
- **F006-AC09 부분 실패**
  상세의 일부(예: 티켓 목록)만 실패하면 요약은 보여 주고 실패한 영역에만 다시 시도를 둔다. (PRD 4.11)

- **F006-AC10 사이드바 개인 채팅 세션**
  모든 로그인 화면의 왼쪽 사이드바 하단에 `채팅 세션` 목록을 둔다. `GET /api/inquiries?page=0&size=20`의 InquiryPage를 사용하고, 서버의 `createdAt` 내림차순·동률 `id` 내림차순을 유지한다. 제목·종합 상태·생성 시각을 표시하며 선택하면 해당 문의의 채팅으로 이동하고 현재 문의를 표시한다. 관리자도 이 영역에서는 본인 문의만 조회한다. 상단의 별도 `내 문의 내역` 메뉴는 제거하되 기존 `/inquiries` 최소 목록 경로는 유지한다.
- **F006-AC11 세션 목록 더 보기**
  고정 5건으로 자르지 않는다. 다음 페이지가 있으면 `더 보기`로 같은 size의 다음 page를 조회해 이어 붙이고 id 중복을 제거한다. 추가 조회 중 중복 요청을 막고, 실패하면 기존 목록과 같은 페이지의 재시도 버튼을 유지한다. 저장·업무 변경·재접속 시 기존 문의 목록 무효화 규칙을 적용한다. 계정 전환·로그아웃 시 이전 사용자의 캐시를 제거한다.
- **F006-AC12 세션 목록 상태**
  최초 로딩·조회 오류·빈 결과를 구분하고 오류에는 다시 시도를 제공한다. 빈 결과에도 `채팅 세션` 제목과 새 문의 안내를 유지한다. 상태 표시명은 IN_PROGRESS=`진행 중`, WAITING_USER=`추가 확인 중`, RESOLVED=`해결 완료`, CLOSED_UNCONFIRMED=`미확인 종료`, CLOSED=`종료`로 구분한다. 긴 목록은 목록 영역에서 스크롤하며 상단 업무 메뉴를 밀어내지 않는다. 모바일에서도 메뉴와 목록을 각각 식별할 수 있다.

현재 프론트 구현 범위는 최소 문의 목록·채팅 재진입·사이드바 세션 목록이다. AC04~AC09의 전체 상세 모달을 이번 사이드바 변경의 완료 범위로 간주하지 않는다.

## 5. 계약(화면이 기대하는 값)

| 용도 | 경로 | 판정 | 비고 |
|---|---|---|---|
| 목록 | `GET /api/inquiries` | 개발 기준 확정 | 기본 20·최대 100, createdAt DESC·id DESC. 검색/확장 필터 후속(Q-BE-5) |
| 상세 | `GET /api/inquiries/{id}` | 개발 기준 확정 | F005와 같은 응답 |
| 종합 상태 값 | ERD `IN_PROGRESS / WAITING_USER / RESOLVED / CLOSED_UNCONFIRMED / CLOSED` | 개발 기준 확정 | 코드/표시명은 DATA_TYPES(Q-ALL-2) |
| 숨기기·복원 | — | 미정 | API 2.2 "구현 전 합의", ERD 컬럼 없음. 이 스펙 범위 밖 |

## 6. 범위 밖

숨기기·복원(PRD 4.5에 있으나 경로·저장 위치 미정), 검색·확장 필터(후속, 기본 정렬은 확정 Q-BE-5), 해결 신고·해결 확인 응답(후속).

## 7. 막히는 정도

- 목으로 진행 가능: 목록·상세 모달·빈 화면·실패 화면 전부.
- 구현·검증 상태: 위 확정 범위와 공통 계약 11절을 따른다. 후속 상세 설계는 QUESTIONS의 해당 ID로 추적한다.
