# F006 내 문의·해결 확인

상태: PRD 1.44 목표 명세 · 팀 기획 합의 / hops-system-1 구체 계약안 추가·팀 리뷰/구현/검증 별도.

## 1. 목표와 범위

문의자가 본인의 대화와 문제별 처리 상태를 확인하고 해결 여부를 응답한다.

근거: [PRD](../../docs/PRD.md), [API](../../docs/API.md), [데이터](../../docs/DATA.md), [목표 공통 계약](../contracts/TARGET_CONTRACT.md).

## 2. 인수 조건

- **F006-TARGET-01:** 본인 문의 목록과 대화·연결 티켓의 진행 상태를 조회한다.
- **F006-TARGET-02:** 담당자가 처리 및 검증을 기록하면 해당 문제에 대한 해결 확인 요청을 표시한다.
- **F006-TARGET-03:** 기능 요청은 실제 구현·검증 완료와 문의자의 최종 해결 확인을 구분해 표시한다.
- **F006-TARGET-04:** 해결 응답 시 해당 문제의 최종 완료를 저장하고 미해결 응답 시 같은 티켓의 처리를 이어간다.
- **F006-TARGET-05:** 무응답은 확인 대기를 유지한다. 자동 종료·예약 재알림·완료 후 재오픈을 제공하지 않는다.
- **F006-TARGET-06:** 타인의 문의와 담당자 전용 자료는 노출하지 않는다.

## 화면과 사용자 흐름

### 화면

- 내 문의 목록과 본인 채팅 재진입. 현재 프론트의 `/inquiries` 및 채팅 경로는 구현 안내를 따른다.
- 처리 결과와 문제별 해결/미해결 확인은 새 기능이며 구체 화면은 아래 계약안의 채팅 안 확인 영역으로 제안한다.

### 흐름

1. 문의자가 목록에서 자신의 문의를 선택해 문제와 티켓 진행을 확인한다.
2. 담당자가 처리·검증한 문제의 결과를 확인한다.
3. 해결 또는 미해결을 응답하고 서버가 해당 문제의 상태를 확정한다.

## 상세 인수 조건과 예외

- **F006-DETAIL-01 목록·권한:** 본인 문의만 조회하고 다른 사용자의 ID로 상세를 열어도 서버가 거부한다.
- **F006-DETAIL-02 페이지·빈 결과:** 목록 로딩, 빈 목록, 오류를 구분한다. 추가 페이지 조회가 실패해도 이미 읽은 목록을 보존하고 해당 조회만 다시 시도할 수 있다.
- **F006-DETAIL-03 결과 확인 요청:** 담당자의 처리·검증 이후에만 해당 문제의 확인 요청을 표시한다. 알림 읽음은 해결 응답이 아니다.
- **F006-DETAIL-04 기능 요청:** 담당자의 구현 완료를 표시하되 문의자 확인 전 최종 해결 완료로 표시하지 않는다.
- **F006-DETAIL-05 해결:** 문의자 해결 응답은 관련 문제·티켓에만 적용한다. 다른 문제가 자동 완료되지 않는다.
- **F006-DETAIL-06 미해결·무응답:** 미해결은 같은 티켓의 처리로 돌아가며, 무응답은 확인 대기다. 예약 재알림·자동 종료·완료 후 재오픈은 제공하지 않는다.
- **F006-DETAIL-07 저장 오류:** 확인 요청의 응답이 유실되면 성공으로 단정하지 않고 입력과 대상 문제를 보존해 서버 상태를 확인한다.

## 계약·화면 상태

신규 `hops-system-1` 팀 리뷰용 구체 계약안이다. 필드·enum은 [DATA_TYPES](../contracts/DATA_TYPES.md#신규-계약-hops-system-1), REST·오류·SSE·멱등성은 [WIRE_CONTRACT 12절](../contracts/WIRE_CONTRACT.md#12-신규-계약-hops-system-1), 업무 전이는 [TARGET_CONTRACT](../contracts/TARGET_CONTRACT.md)가 정본이다. 아래 내용은 구현·팀 승인·통합 완료 표시가 아니다.

| 조작 | 계약·검증 |
|---|---|
| 목록 | /inquiries 상단 메뉴 제공. InquirySummary의 문제·티켓·대기 수와 updatedAt 표시 |
| 처리 결과 | 채팅 안에 activeResolutionRequest의 resultSummary와 대상 문제 표시. 내부 담당 자료는 제외 |
| 해결 응답 | ResolutionResponse.expectedRequestRevision과 대상 요청 ID로 한 처리 주기에 응답 |
| 무티켓 확인 | GUIDE source도 동일 해결 확인 API 사용. WORK_RECORD 확인의 전제와 구분 |

| 화면 상태 | 관찰 가능한 동작 |
|---|---|
| PENDING | 해결/미해결 버튼; 무응답은 대기 유지 |
| RESOLVED | 해당 문제 최종 완료. 다른 독립 문제는 그대로 |
| UNRESOLVED | 같은 티켓 처리 계속; 가이드이면 담당자 연결 검토 |
| 오래된/중복 응답 | 원 키 같은 응답은 기존 결과. 다른 응답·오래된 revision은 충돌 후 조회 |

## hops-system-1 검증 시나리오

- **F006-CONTRACT-01:** 두 문제 중 하나의 확인 응답이 다른 문제·티켓을 완료하지 않는다.
- **F006-CONTRACT-02:** 미해결 뒤 같은 티켓에서 새 검증 기록·새 확인 요청이 생성되며 이전 요청은 이력으로 유지된다.
- **F006-CONTRACT-03:** 무응답으로 시간이 지나도 대기 상태이고 알림 읽음은 해결 응답이 아니다.
- **F006-CONTRACT-04:** 응답 저장 후 HTTP 유실을 재확인하면 원 응답 하나만 남는다.

문서/JSON 검사·Mock·실제 서버 저장/권한·실제 AI/검색·브라우저 E2E를 분리해 결과를 기록한다. 기존 테스트의 이전 AC 번호를 새 시나리오 통과로 간주하지 않는다.

## 범위·연관 기능

- 문제별 확인을 제공하되 독립 상세 모달의 정확한 경로나 검색·숨김/복원 기능을 신규 필수로 가정하지 않는다.

## 현재 구현과 남은 작업

현재 프론트는 최소 개인 문의 목록·채팅 재진입을 제공한다. 처리·확인 연결은 미완료다.

기존 코드·테스트의 인수 조건 번호는 이전 기준이며 목표 조건과 구분한다. 목표 AC는 실제 구현·검증 완료를 뜻하지 않는다. 실제 구현 범위는 서비스 코드와 실행 안내에서 확인한다.

기능의 목표 인수 조건은 구현·통합 검증을 대신하지 않는다. hops-system-1 계약안의 담당자 리뷰·승인 후 코드·테스트를 전환한다. 현재 구현을 문서만으로 완료 처리하지 않는다.
