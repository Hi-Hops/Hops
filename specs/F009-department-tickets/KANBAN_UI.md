# F009 부서 티켓 현황 · 칸반 보드 UI

상태: 칸반 MVP 반영안 / 팀 리뷰·프론트·서버 구현 검증 별도 · 대상 화면: `/tickets` 부서 티켓 현황 · 갱신: 2026-10-27
근거: [F009 스펙](spec.md), [DATA_TYPES](../contracts/DATA_TYPES.md) `ProcessingStatus`·`RoutingStatus`, Figma v1.29 시안

이 문서는 부서 티켓 현황에 상태별 칸반 보드와 기존 목록(테이블)을 선택하는 UI의 디자인 의도와 Figma 위치를 정리한다. 칸반·전체 카드 정보·그룹 조회 표시·검색·빠른 필터는 MVP에 포함하고 업무 변경은 후속으로 유지한다. 제품 범위·화면 완료 조건의 원본은 [PRD 4.6·8.2](../../docs/PRD.md)와 [F009-AC11~AC20](spec.md), 조회 계약은 WIRE_CONTRACT 10절·DATA_TYPES다. 이 문서의 시안만으로 팀 리뷰·구현 완료를 확정하지 않는다.

## 보드 구성

### 컬럼 = `processingStatus`

| 컬럼 | 배지 | 포함 값 |
|---|---|---|
| 처리 대기 | Wait | `WAITING` |
| 처리 중 | Info | `IN_PROGRESS` |
| 사용자 확인 대기 | Wait | `WAITING_CONFIRM` |
| 종료 | Success | `RESOLVED`, `CLOSED_UNCONFIRMED` (카드에서 구분) |

- 컬럼 머리에 상태 배지와 건수를 둔다. 건수는 서버 응답 기준이며 화면이 계산해 범위를 넓히지 않는다.
- 컬럼 안 정렬은 기존 계약의 createdAt 내림차순·동률 id 내림차순을 따른다. 우선순위는 표시·빠른 필터에 사용하며 기본 정렬을 바꾸지 않는다.
- 비어 있는 컬럼은 `티켓 없음`을 표시한다. 전체 조회 성공 후 0건이면 F009-AC04의 빈 상태를, 검색·필터 0건이면 조건에 맞는 티켓이 없다는 안내를 표시한다. 일부 컬럼/더 보기 실패는 해당 조회에만 재시도를 제공하고 정상 결과는 유지한다. 실패를 0건으로 표시하지 않는다.
- 미등록 상태 문자열을 받으면 어느 컬럼에도 임의로 넣지 않고 안전한 안내로 표시한다(DATA_TYPES 규칙).

### 가로 구역(swimlane) = 장애 그룹

- 장애 그룹마다 구역을 하나 둔다. 구역 머리: 그룹 번호, 제목, `장애 그룹` 칩, 그룹 전체 구성 건수·영향 사용자·대표 티켓, 그룹 상태 배지·담당자. 현재 불러온 카드 수는 별도 표시한다. 시안의 `그룹 담당하기`·`그룹 상세`는 후속이며 MVP에서 숨긴다.
- 그룹에 속하지 않은 티켓은 마지막 `그룹 외 티켓` 구역에 모은다.
- 구역은 `▾`로 접고 펼친다. 그룹이 없으면 전체를 `그룹 외 티켓` 구역으로 표시한다. 기존 그룹 생성·해결 업무는 후속이며 MVP는 저장된 그룹의 조회 표현만 제공한다.

### 카드 (`Kanban card`)

| 위치 | 내용 | 컴포넌트 속성 |
|---|---|---|
| 상단 | 티켓 번호, 우선순위(`Priority` 인스턴스) | `Ticket number` |
| 본문 | 제목, 요청자·소속·접수 시각(대표/구성 티켓, 우선순위 설정 출처 포함) | `Title`, `Meta` |
| 태그 | 문의 유형 칩, `✋ 해결 신고`, 배정 상태 배지 | `Show resolve flag`, `Show routing badge` |
| 하단 | `내 담당` 칩 / 담당자 이름. `가져오기`는 후속으로 MVP에서 숨김 | `Show mine`, `Show assignee name`, `Assignee name`, `Show take=false` |

- 배정 상태 배지는 `routingStatus`가 `ASSIGNED`가 아닐 때(CS 검토, 재배정 중, 배정 예외, 복구 대기)만 보인다. 처리 상태(컬럼)와 배정 상태(배지)를 분리해 F009-AC02를 유지한다.
- 카드를 누르면 지금과 같이 티켓 상세 모달(`/tickets/:ticketId`)을 연다. 필터·검색 조건은 주소에 남겨 상세를 닫아도 보드가 유지된다(F009-AC03).

## 정책상 JIRA와 다르게 둔 점

- **드래그로 상태를 바꾸지 않는다.** 상태 확정은 서버가 담당한다(AGENTS 작업 규칙, F009 MVP는 읽기 전용). 카드 이동은 서버 상태가 바뀐 뒤 재조회 결과로만 일어난다.
- `가져오기`·`그룹 담당하기`·처리 완료·그룹 상세 버튼은 후속이며 MVP 구현에서는 숨긴다(F009 7절 범위 밖).
- `state.changed` 이벤트를 받으면 보드를 REST로 다시 조회한다. 이벤트만으로 카드를 다른 컬럼으로 옮기지 않는다(F009-AC10).

## 데이터 조회 (MVP 추가 프로필 · 팀 리뷰 대상)

기존 `GET /api/tickets`를 확장하고 별도의 보드 전용 엔드포인트는 만들지 않는다. 정확한 요청·응답은 WIRE_CONTRACT 10절과 DATA_TYPES의 칸반 MVP 추가 프로필이 원본이다. 기존 API·Mock이 이미 지원한다고 간주하지 않는다.

1. 앞의 세 컬럼은 단일 상태로, 종료는 추가하는 processingStatuses의 두 종료 상태 OR로 조회한다. 초기 4개 독립 요청이며 종료 상태는 서버가 한 결과로 정렬·페이지·집계한다.
2. 컬럼 머리는 현재 검색·빠른 필터·권한 범위의 전체 건수, 하단은 `더 보기`다. 기본 20·최대 100, 생성 시각 DESC·ID DESC이며 종료 기간 제한은 없다.

- 전체 카드 정보는 목록 전용 TicketListItem 추가 프로필로 제공하며 문의 결과용 TicketCard 기본 계약은 유지한다. 저장된 담당자·우선순위/출처·요청자/소속·문의 유형·해결 신고·장애 그룹을 표시한다. null을 추정 값으로 채우지 않는다.
- 번호·제목 기본 검색과 전체/내 담당/긴급/높음/해결 신고 중 단일 빠른 필터를 보드·목록에 제공한다. 서버가 페이지·집계 전에 적용하며 현재 받은 페이지만 거르지 않는다. 연결 전 계약 리뷰와 서버/프론트 구현·검증을 완료해야 하며 필드를 숨기는 것으로 MVP 완료를 대신하지 않는다.

## 보기 전환 (보드 · 목록)

툴바 오른쪽, 검색창 옆에 `보드 | 목록` 두 칸짜리 전환 버튼(`View toggle`)을 둔다. 시안 1차의 `목록 보기` 단일 버튼을 대체한다. 보드는 상태별 흐름을 볼 때, 목록(v1.29 테이블)은 많은 건을 한 번에 훑거나 키보드로 행을 이동할 때 쓴다.

| 항목 | 기준 |
|---|---|
| 모양 | `surface/sunken` 바탕의 묶음 안에 아이콘+라벨 두 칸. 선택된 칸은 `surface/default` 바탕·`Shadow/Raised`·`ink` 글자, 나머지는 `text/secondary` |
| 컴포넌트 | `View toggle` (`View=Board`, `View=List`) |
| 상태 보존 | 주소 쿼리 `view=board\|list`에 남긴다. 유효한 선택이 없으면 1024 CSS px 이상 board, 미만 list. 상세/새로고침 후 같은 보기·조건을 유지한다 |
| 함께 유지 | 빠른 필터·검색어는 보기를 바꿔도 그대로 둔다. 보기 전환은 조회 범위나 권한을 바꾸지 않는다 |
| 목록 보기의 상태 필터 | 목록에서는 processingStatus를 적용한다. 보드에서는 상태 필터 UI를 숨기고 URL 값만 보존하며 API에는 적용하지 않는다. 목록 복귀 시 복원한다 |
| 페이지 | 보기/검색/필터 변경은 목록 page와 보드 추가 페이지를 초기화한다. 상세 열기/닫기는 Query 캐시의 컬럼 페이지·카드를 유지하고 새로고침은 첫 페이지부터 조회한다 |
| 접근성 | `role="radiogroup"`과 `aria-label="보기 방식"`, 각 칸은 `role="radio"`·`aria-checked`. 화살표 키로 이동하고, 보기를 바꾸면 보드/목록 영역 제목으로 포커스를 옮기지 않고 전환 버튼에 남긴다 |
| 좁은 화면 | 유효 view가 없으면 목록 기본. 명시적 보드 선택 시 컬럼을 세로 배치한다. 반응형 시안은 미작성 |

## 접근성

- 컬럼은 `section`과 `aria-label`(예: "처리 중 6건"), 카드는 상세로 가는 링크 하나로 만든다. 카드 안 버튼은 링크와 겹치지 않게 별도 포커스 대상으로 둔다.
- 상태를 색으로만 구분하지 않는다. 컬럼 머리 배지에 상태 이름을 쓴다.
- 좁은 화면의 기본값·명시적 보드 선택은 F009-AC11·AC19를 따른다. 상태별 탭이라는 별도 대체 동작은 추가하지 않는다.

## 남은 작업

- 배정 상태 배지가 보이는 카드 예시, 로딩·빈·실패 보드 상태, 좁은 화면 시안은 아직 없다.
- 추가 조회 프로필을 backend와 리뷰하고 타입·Mock 예시·서버·프론트를 구현한다. 기존 fixture는 새 표시 필드·검색·종료 통합 조회를 아직 검증하지 않는다.
- F009-AC11~AC20에 따라 화면·접근성·실제 서버 연동을 검증한다. PRD·F009·ROUTES의 문서 반영과 팀 리뷰/병합·구현 완료를 구분한다.
