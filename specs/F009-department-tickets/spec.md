# F009 부서 티켓 보드·목록·상세와 관련 대화

상태: 기존 개발 기준 + 2026-10-28 REST·SSE 기준 칸반 MVP 확장안 / 팀 리뷰·구현·검증 별도 · 범위: MVP 부서 티켓 읽기 전용 보드·목록·상세 / 관련 대화·담당 업무는 후속 · 담당: frontend(화면) · 협의: backend(조회·권한·SSE)
근거: PRD 4.6, 4.11, 8.2, 8.3 · API 2.1 `GET /api/tickets`, 2.2 `GET /api/tickets/{id}/messages`, 2.4 · DATA 3, 4 · ERD `ticket`, `ticket_assignment`, `member`

## 개발 범위와 남은 작업 (2026-10-28)

MVP는 현재 처리 부서 또는 BIZ_ADMIN 범위의 읽기 전용 보드·목록·상세다. 칸반과 보기 전환, 모든 카드 표시 정보, 장애 그룹 가로 구역, 기본 검색·빠른 필터, 컬럼별 전체 건수·더 보기를 포함한다. AC07~AC09의 관련 대화와 가져오기/처리/그룹 담당하기 등 업무 변경은 후속이다. 목록/컬럼 기본 20·최대 100이다. 기존 processingStatus에 더해 검색·빠른 필터·종료 두 상태 통합 조회의 계약 확장안을 WIRE_CONTRACT 10절과 DATA_TYPES에 정의한다. 팀 리뷰·서버 구현 전까지 기존 API로 지원된다고 간주하지 않는다.

정확한 타입·enum은 [DATA_TYPES](../contracts/DATA_TYPES.md), 정책은 [WIRE_CONTRACT 10절](../contracts/WIRE_CONTRACT.md#10-인증재접속최신-대화분석-재시도-추가-프로필), 담당 구현·미검증은 [11절](../contracts/WIRE_CONTRACT.md#11-담당별-구현과-검증-상태)을 따른다. 확정은 개발 기준 선택이며 팀 리뷰/병합·서비스 구현 완료가 아니다.

## 1. 목표

부서 구성원이 현재 자기 부서에 배정된 티켓을 보드·목록과 상세로 확인한다. 관련 사용자·AI 대화 조회는 후속이다. 다른 부서 티켓, 다른 문제의 대화, 운영 로그는 보이지 않는다. MVP 범위는 조회까지다. 가져오기·처리 완료·재이관은 후속이다. (PRD 4.6, 8.2 "재이관·최종 처리·알림 전체를 MVP 완료 조건에 포함하지 않는다")

## 2. 범위 판단

| 항목 | 원본 문서 | 이슈 #31 |

| 부서 보드·목록/내 담당 조회 표시 | PRD 4.6·8.2 MVP / 담당자 업무 처리는 8.3 후속 | 같은 항목 + 칸반 추가 범위 |

## 3. 화면

| 화면 | 경로(제안) | 접근 |
|---|---|---|
| 부서 티켓 보드·목록 | `/tickets` | 현재 처리 부서 구성원 또는 BIZ_ADMIN |
| 티켓 상세 | `/tickets/:ticketId` | 현재 처리 부서 구성원, 업무 관리자(관련 대화 권한은 Q-BE-14) |

업무 관리자 화면(F007)은 같은 상세 컴포넌트를 읽기 전용으로 재사용한다. 현재 /tickets/:ticketId와 /admin/tickets/:ticketId 경로를 유지한다(Q-FE-1).

## 4. 사용자 시나리오

1. 네트워크 부서 구성원이 로그인 후 부서 칸반에서 VPN 티켓과 담당·우선순위·그룹 정보를 보고, 번호·제목 검색과 빠른 필터를 사용하거나 목록 보기로 전환한다.
2. 티켓을 누르면 상세에서 문의 요약, AI 진단, 처리 상태·배정 상태, 배정 이력을 본다.
3. 후속 기능에서는 상세의 "관련 대화"에서 VPN 문제와 관련된 메시지와 이관 뒤 보완 정보, 정정 이력을 시간순으로 본다. 같은 문의의 프린터 문제 대화는 보이지 않는다.
4. 다른 부서 티켓 주소로 들어가면 권한 없음 화면이 나온다.

## 5. 인수 조건

**목록 (MVP · API 2.1)**
- **F009-AC01 부서 범위 목록**
  `GET /api/tickets`로 서버가 허용한 범위의 티켓만 보드 카드 또는 목록 행에 보여 준다. 번호·제목·처리 부서·처리 상태·배정 상태·생성 시각 및 AC15의 표시 정보를 사용한다. 범위는 화면이 계산하지 않고 서버 응답을 그대로 쓴다. (API 2.1 · 범위 구분 방식 Q-BE-6)
- **F009-AC02 상태 분리**
  `processingStatus`와 `routingStatus`를 따로 표시한다. (API 2.1 · 상태값 Q-ALL-2)
- **F009-AC03 필터·페이지 유지**
  보기·검색·필터·목록 페이지는 주소에 남기고, 상세를 닫으면 그대로 복원한다. 보드 컬럼별 추가 페이지와 스크롤은 목록 Query 캐시에 보존한다. 새로고침은 같은 보기·검색·필터의 컬럼 첫 페이지부터 조회한다. 조건 변경은 목록/컬럼 페이지를 초기화하며 필터가 권한을 넓히지 않는다. (PRD 4.11 · AC11~AC14)
- **F009-AC04 빈 결과·실패 구분**
  모든 컬럼 조회 성공 후 전체 0건이면 "배정된 티켓이 없어요", 검색/필터 결과 0건이면 "조건에 맞는 티켓이 없어요"를 표시한다. 빈 컬럼은 "티켓 없음", 실패한 컬럼은 실패 안내와 다시 시도를 보여 주며 실패를 0건으로 표시하지 않는다. (PRD 4.11 · AC18)

**상세 (MVP · API 2.1)**
- **F009-AC05 티켓 상세 읽기**
  `GET /api/tickets/{id}`로 문의 요약, AI 진단, 현재 처리 부서, 처리 상태·배정 상태, 배정 이력을 보여 준다. MVP에서는 가져오기·처리 완료·재이관·AI 내용 정정 버튼을 두지 않는다. (PRD 4.6 · API 2.1 · 응답 필드 Q-BE-6)
- **F009-AC06 다른 부서 티켓**
  Given 현재 처리 부서 구성원도 업무 관리자도 아닌 사용자 · When 티켓 주소로 들어가면 · Then 내용을 보여 주지 않고 권한 없음 화면에서 부서 티켓 목록으로 돌아가도록 안내한다. 재이관으로 부서가 바뀐 뒤 다시 열어도 같다. (PRD 4.11 · DATA 4 "현재 처리 부서 구성원만 티켓과 관련 대화를 조회")
  프론트가 현재 사용자에게 티켓 화면 접근 자격이 없음을 아는 경우 상세 모달·상세 조회·TICKET SSE를 시작하지 않는다. 상세 훅에서도 같은 조건을 적용한다. 처리 부서 구성원 등 화면 접근 자격은 있으나 특정 티켓에 접근 가능한지는 서버가 최종 검사한다.

**관련 대화 (이슈 #31 · API 2.2 후속, Q-ALL-7)**
- **F009-AC07 관련 대화 조회**
  상세에서 `GET /api/tickets/{id}/messages`로 해당 티켓과 관련된 사용자·AI 대화를 시간순으로 보여 준다. 가져오기 전에도 현재 처리 부서 구성원이면 볼 수 있다. (PRD 4.6 · API 2.2 · 관련 범위 기준 Q-BE-14)
- **F009-AC08 이관 뒤 보완 정보와 정정 이력**
  이관 뒤 문의자가 보낸 보완 메시지와 정정을 구분해 표시하고, 정정된 메시지는 이전 내용을 볼 수 있게 한다. 표시 형식은 F004-AC02와 같다. (PRD 4.4 "관련 티켓 상세에서 담당자가 확인", 4.6 · DATA 3)
- **F009-AC09 범위 밖 대화 비노출**
  같은 문의의 다른 문제 대화와 내부 운영 로그는 표시하지 않는다. 화면은 문의 전체 대화(`GET /api/inquiries/{id}/messages`)를 대신 불러와 거르지 않는다. (PRD 4.6 · API 2.2 · API 2.4 "문의자용 전체 대화·담당자용 관련 티켓 대화 … SSE 대상 범위를 분리")

**실시간 (MVP · API 2.4)**
- **F009-AC10 재조회 신호**
  목록·상세에 있는 동안 Spring SSE로 `state.changed`를 받으면 해당 목록이나 티켓을 REST로 다시 조회한다. 이벤트만으로 상태를 확정 표시하지 않고, 재접속 또는 `resync.required` 뒤에도 REST로 다시 맞춘다. (API 2.4 · PRD 4.11 · 이슈 #31 "상태 변경 이벤트는 재조회 신호" · SSE 연결 대상 Q-INF-3)

**칸반·보기 전환 (MVP 추가 · 팀 리뷰·구현 검증 별도)**

- **F009-AC11 보기 전환과 기본값**
  Given `/tickets`에 접근 가능할 때 · When 처음 진입하거나 보기를 전환하면 · Then `보드 | 목록` 선택을 제공하고 `view=board|list`로 보존한다. 값이 없거나 잘못된 값이면 1024 CSS px 이상은 보드, 미만은 목록이다. 명시적인 유효 view는 너비보다 우선하며 너비 변화만으로 선택을 바꾸지 않는다. 전환 시 page와 컬럼 추가 페이지를 초기화하고 검색·빠른 필터를 유지한다.
- **F009-AC12 상태 컬럼과 종료 구분**
  Given 보드 보기일 때 · When 티켓 조회가 성공하면 · Then WAITING/IN_PROGRESS/WAITING_CONFIRM을 각각 처리 대기/처리 중/사용자 확인 대기로, RESOLVED와 CLOSED_UNCONFIRMED를 종료 컬럼으로 표시한다. 종료 카드에 원래 상태를 표시하여 해결 완료·미확인 종료를 구분한다. 배정 상태는 별도 배지이고 미등록 상태는 안전한 안내로 표시하며 알려진 컬럼에 임의 배치하지 않는다.
- **F009-AC13 전체 건수와 더 보기**
  Given 컬럼에 아직 조회하지 않은 티켓이 있을 때 · When `더 보기`를 누르면 · Then 해당 컬럼의 다음 페이지를 기존 카드 뒤에 붙이고 ID로 중복 제거한다. 머리 건수는 현재 조건의 서버 totalElements이며 불러온 카드 수와 구분한다. 기본 20·최대 100, createdAt DESC·id DESC를 적용한다. 종료 컬럼은 두 상태를 합친 서버 정렬·건수·페이지를 사용하며 기간 제한이나 `최근 7일` 문구를 두지 않는다.
- **F009-AC14 기본 검색과 조건 유지**
  Given 검색어를 입력했을 때 · When 검색 버튼 또는 Enter로 제출하면 · Then 티켓 번호·제목에 대한 서버 검색을 모든 목록/컬럼 조회에 적용한다. 검색 초기화와 검색 0건 안내를 제공하며 검색으로 조회 권한을 넓히지 않는다. 목록의 processingStatus는 보드에서 적용하지 않고 URL에 보존하여 목록 복귀 시 복원한다. 검색/필터 변경은 모든 페이지를 초기화한다. 상세 열기·닫기는 보기·조건·이미 불러온 카드를 유지하고 새로고침은 동일 조건의 첫 페이지부터 조회한다.
- **F009-AC15 카드의 전체 표시 정보**
  Given 저장된 TicketListItem을 받았을 때 · When 카드를 표시하면 · Then 기본 정보와 요청자·소속, 문의 유형, 우선순위·설정 출처, 담당자 이름·내 담당 여부, 해결 신고, 장애 그룹·대표 티켓 여부를 표시한다. null은 미지정/미배정/그룹 없음으로 구분하며 임의 값으로 채우지 않는다. 내 담당은 현재 사용자 ID와 담당자 ID를 비교한다. 번호·제목 링크는 기존 티켓 상세 모달을 열고 카드에서 업무 상태를 변경하지 않는다.
- **F009-AC16 장애 그룹 가로 구역**
  Given 그룹에 속한 티켓이 조회되면 · When 보드를 표시하면 · Then 그룹별 접고 펼치는 가로 구역에 티켓을 한 번씩 표시하고 그룹 외 티켓은 별도 구역에 둔다. 그룹 번호·제목·구성 건수·영향 사용자 수·대표 티켓·그룹 상태·담당자를 저장값으로 표시한다. 구역별 화면 카드 수는 현재 불러온 수이며 그룹 전체 건수와 구분한다. 그룹 구역에서도 컬럼별 정렬을 유지한다. 그룹 없음은 전체를 그룹 외 구역으로 표시한다. 그룹 상세·그룹 담당하기·그룹 변경 버튼은 MVP에서 숨긴다.
- **F009-AC17 빠른 필터**
  Given 전체/내 담당/긴급/높음/해결 신고 필터가 있을 때 · When 선택하면 · Then 선택된 빠른 필터 한 개를 서버 조건으로 적용한다. 전체는 빠른 필터만 해제하고 검색은 유지한다. 받은 페이지만 필터링하거나 전체 건수를 프론트에서 추정하지 않는다. URL과 상세 복귀에 선택을 보존한다.
- **F009-AC18 로딩·부분 실패·재시도**
  Given 컬럼별 또는 더 보기 조회 중일 때 · When 일부 요청이 실패하면 · Then 정상 컬럼과 이미 표시된 카드를 유지하고 실패한 조회만 재시도한다. 초기 로딩/빈 결과/실패/추가 로딩을 구분하고 실패 건수를 0으로 표시하지 않는다. 401/403은 공통 인증·권한 규칙을 우선하며 권한 회수 시 이전 데이터를 계속 노출하지 않는다.
- **F009-AC19 키보드와 반응형**
  Given 키보드 또는 좁은 화면으로 이용할 때 · When 보기·상세·더 보기·그룹 접기를 조작하면 · Then 보기 전환은 radiogroup/radio와 aria-checked·화살표 키를 지원하고 포커스는 선택한 버튼에 남는다. 컬럼은 이름과 건수가 있는 section, 카드는 상세 링크로 제공한다. 그룹 접기는 aria-expanded를 제공하고 상태는 문자로 구분한다. 기본 목록 전환 기준은 AC11을 따르며 좁은 화면에서 명시적으로 보드를 선택하면 컬럼을 세로로 배치해 가로 스크롤을 강요하지 않는다. 상세를 닫으면 해당 카드 링크, 없으면 페이지 제목으로 포커스를 복원한다.
- **F009-AC20 실시간 재조회와 읽기 전용**
  Given 보드에 추가 페이지가 표시되어 있을 때 · When Spring SSE의 state.changed·resync.required 또는 재접속으로 재조회하면 · Then 각 컬럼의 첫 페이지부터 현재 불러온 깊이까지 다시 맞추고 ID 중복·이전 컬럼 잔존 없이 저장 결과를 표시한다. 재조회 실패 시 마지막 결과임을 안내하고 재시도를 제공한다. 필터 변경 중 늦게 온 이전 응답은 현재 보드를 덮어쓰지 않는다. 드래그 상태 변경·가져오기·처리 완료·그룹 담당하기는 제공하지 않는다.

## 6. 계약(화면이 기대하는 값)

공통 필드·필수/nullable·wire 표현의 원본은 [데이터 타입·필드 문서](../contracts/DATA_TYPES.md)다. 아래 MVP 연결표는 확정 개발 기준이다. 후속 기능 후보와 실제 담당 구현·검증은 구분한다.

| 용도 | 경로·이벤트 | 공통 계약 타입 | 구현·검증 추적 |
|---|---|---|---|
| 부서/관리자 목록 | GET /api/tickets | TicketListQuery → TicketPage(TicketListItem[]) | Q-BE-5/6, 칸반 추가 프로필 |
| 읽기 전용 상세 | GET /api/tickets/{id} | TicketDetail, AssignmentHistory[] | Q-BE-6/12 |
| 부서 메뉴 판단 | GET /api/auth/me | CurrentUser.department.isRoutable | Q-ALL-5 |
| 목록/상세 실시간 연결 | GET /api/realtime/events?targetType={type}&targetId={id} | DepartmentTicketsTarget / TicketTarget | Q-INF-3 |
| 변경 재조회 | state.changed | StateChangedEvent | Q-INF-6 |
| replay 불가 시 복구 | resync.required | ResyncRequiredEvent(공통 타입 추가 필요) | Q-INF-6, 공통 계약 11절 |
| 관련 대화 | GET /api/tickets/{id}/messages | 이번 공통 Mock 제외 | Q-BE-14, Q-ALL-7 |

목록은 서버가 현재 사용자 부서 또는 BIZ_ADMIN 권한으로 범위를 정한다. page/size/processingStatus의 기존 계약에 칸반 추가 프로필의 다중 상태·검색·빠른 필터를 확장한다. 부서 선택으로 권한을 넓히지 않는다. 처리 부서 구성원이 아닌 업무 관리자도 허용되지만 운영 관리자 역할만으로는 허용되지 않는다. `/admin/tickets`의 기존 목록·상세는 유지하며 보드 전환의 필수 대상은 `/tickets`다. 읽기 전용 보드·목록·상세는 MVP, 관련 대화는 후속이다. 실제 서버 구현·통합 검증은 별도다.

### 목록·상세 SSE 생명주기

목록은 현재 권한으로 허용된 `DEPARTMENT_TICKETS` target, 상세는 해당 `TICKET` target에 `GET /api/realtime/events`로 연결한다. 보드의 4개 컬럼·그룹마다 별도 스트림을 열지 않고 같은 target 연결을 공유한다. 상세를 닫으면 상세 target 연결만 종료하고 목록 target은 화면에 남아 있는 동안 유지한다. 화면 이탈·로그아웃·권한 회수 때는 관련 연결과 비허용 데이터를 정리한다.

Bearer·Last-Event-ID·eventId 중복 제거·인증 갱신·재연결·`resync.required`는 F002와 WIRE_CONTRACT 5·9절의 공통 fetch SSE 계층에서 처리한다. 칸반은 `state.changed`·재접속·재동기화 시 AC20에 따라 REST 조회 캐시를 갱신한다. Socket.IO 명령·ACK·subscription.request를 새 칸반 연결 계약으로 사용하지 않는다. 실제 프론트의 REST·SSE 전환과 공통 타입/Mock 교체는 별도 구현·검증 대상이다.

## 7. 범위 밖

가져오기·반환, 처리 완료, 재이관, AI 내용 정정, 그룹 담당하기·그룹 생성/일괄 해결·장애 그룹 상세 화면, 부서 통계(모두 API 2.2·PRD 8.3 후속), 드래그 상태 변경. 저장된 담당자·우선순위·장애 그룹·해결 신고의 조회 표시와 내 담당 빠른 필터는 MVP이며 해당 업무의 생성/수정 API 구현을 포함하지 않는다. MVP에서 업무 변경 버튼은 숨긴다.

## 8. 막히는 정도

- 목으로 진행 가능: 목록·상세·권한 없음·빈/실패 상태, 관련 대화 표시 틀.
- 구현·검증 상태: 위 확정 범위와 공통 계약 11절을 따른다. 후속 상세 설계는 QUESTIONS의 해당 ID로 추적한다.
