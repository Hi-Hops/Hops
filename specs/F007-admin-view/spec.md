# F007 업무 관리자 조회·수동 정정

상태: PRD 1.44 목표 명세 · 팀 기획 합의 / hops-system-1 구체 계약안 추가·팀 리뷰/구현/검증 별도.

## 1. 목표와 범위

업무 관리자는 허용된 범위에서 업무를 조회하고 잘못된 책임 시스템·담당자의 정정을 지원한다.

근거: [PRD](../../docs/PRD.md), [API](../../docs/API.md), [데이터](../../docs/DATA.md), [목표 공통 계약](../contracts/TARGET_CONTRACT.md).

## 2. 인수 조건

- **F007-TARGET-01:** 서버가 확인한 업무 관리자에게만 허용된 업무 목록과 상세를 제공한다.
- **F007-TARGET-02:** 책임 시스템·담당자를 수동 정정할 때 주체·사유·근거와 변경 이력을 저장한다.
- **F007-TARGET-03:** 정정은 이미 저장된 문의와 티켓·이력을 보존하고 자동 재이관과 구분한다.
- **F007-TARGET-04:** 업무 조회 권한만으로 타인 문의의 전체 대화나 내부 자료를 무제한 공개하지 않는다.
- **F007-TARGET-05:** 별도 담당자 매핑 예외 큐·통계 대시보드·자동 재이관은 구현 범위에 넣지 않는다.

## 화면과 사용자 흐름

### 화면

- 업무 관리자용 허용 티켓 목록·상세와 수동 정정 조작. 현재 `/admin/tickets` 경로는 기존 프론트이며 정정은 모달과 아래 신규 계약안으로 제안한다.

### 흐름

1. 업무 관리자가 현재 권한으로 목록을 조회한다.
2. 책임 시스템 오류의 기존 배정과 근거를 확인한다.
3. 새 시스템과 사유·근거를 입력하고 Spring이 정정 결과를 저장·확정한다.

## 상세 인수 조건과 예외

- **F007-DETAIL-01 관리자 접근:** 서버가 현재 관리자 권한을 검사한다. 메뉴 노출만으로 접근을 허용하지 않는다.
- **F007-DETAIL-02 목록 및 오류:** 조회 범위는 서버가 먼저 제한한다. 빈 목록과 실패·부분 실패를 구분하고 성공한 영역을 보존한다.
- **F007-DETAIL-03 정정 확인:** 대상 티켓·기존/새 책임 시스템·사유·근거를 확인하고 주체와 변경 이력을 남긴다.
- **F007-DETAIL-04 부적합 대상:** 지원하지 않는 시스템이나 유효 주담당자를 확인하지 못하는 정정은 배정 성공으로 표시하지 않는다.
- **F007-DETAIL-05 응답 유실:** 정정 저장 여부를 확인할 수 없으면 성공으로 표시하지 않는다. 재시도 전 동일 작업의 결과와 최신 상태를 확인한다.
- **F007-DETAIL-06 정보 보호:** 업무 관리자라는 이유만으로 타인 전체 대화와 내부 지식이 무제한 공개되지 않는다. 조회 범위는 서버가 결정한다.

## 계약·화면 상태

신규 `hops-system-1` 팀 리뷰용 구체 계약안이다. 필드·enum은 [DATA_TYPES](../contracts/DATA_TYPES.md#신규-계약-hops-system-1), REST·오류·SSE·멱등성은 [WIRE_CONTRACT 12절](../contracts/WIRE_CONTRACT.md#12-신규-계약-hops-system-1), 업무 전이는 [TARGET_CONTRACT](../contracts/TARGET_CONTRACT.md)가 정본이다. 아래 내용은 구현·팀 승인·통합 완료 표시가 아니다.

| 조작 | 계약·검증 |
|---|---|
| 관리 목록 | GET tickets?scope=ADMIN. 관리자 허용 범위에서 시스템·상태·페이지 필터 |
| 관리 상세 | GET management/tickets/{ticketId} → TicketManagementDetail. 담당자 전용 상세 DTO와 분리 |
| 수동 정정 | F009와 같은 AssignmentCorrectionCommand. 관리자 권한의 근거는 evidenceNote 사용 가능 |
| 공통 상세 구성 | 관리자 화면에는 배정·이력·정정만 제공. 담당 능력이 함께 있을 때 별도 허용 담당 화면으로 이동 |

| 화면 상태 | 관찰 가능한 동작 |
|---|---|
| 새 시스템 조회 중/실패 | 담당자를 임의 입력·확정하지 않음 |
| 정정 저장 중 | 같은 조작 중복 차단 |
| 버전 충돌·권한 회수 | 정정 초안 보존·최신 업무 재조회; 내부 원문은 노출하지 않음 |

## hops-system-1 검증 시나리오

- **F007-CONTRACT-01:** BIZ_ADMIN만 가진 사용자는 관리 메타데이터를 읽고 관련 원문/사례 승인 API는 거부된다.
- **F007-CONTRACT-02:** 정정 경합에서 이전 ticketRevision 요청이 새 배정을 덮어쓰지 않는다.
- **F007-CONTRACT-03:** 같은 책임 시스템에서 잘못된 assignee를 현재 유효 PRIMARY로 정정할 수 있고 이력을 보존한다.

문서/JSON 검사·Mock·실제 서버 저장/권한·실제 AI/검색·브라우저 E2E를 분리해 결과를 기록한다. 기존 테스트의 이전 AC 번호를 새 시나리오 통과로 간주하지 않는다.

## 범위·연관 기능

- 자동 재이관, 매핑 누락 전용 업무 큐, 장애 그룹과 통계 대시보드는 새 MVP 범위에 넣지 않는다.

## 현재 구현과 남은 작업

현재 프론트에는 부서 기반 관리자 읽기 전용 조회가 있으며 새 수동 정정과 권한 검증은 별도다.

기존 코드·테스트의 인수 조건 번호는 이전 기준이며 목표 조건과 구분한다. 목표 AC는 실제 구현·검증 완료를 뜻하지 않는다. 실제 구현 범위는 서비스 코드와 실행 안내에서 확인한다.

기능의 목표 인수 조건은 구현·통합 검증을 대신하지 않는다. hops-system-1 계약안의 담당자 리뷰·승인 후 코드·테스트를 전환한다. 현재 구현을 문서만으로 완료 처리하지 않는다.
