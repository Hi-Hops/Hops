# F007 업무 관리자 조회

상태: 개발 기준 확정 / 구현·검증 별도 · 범위: MVP 읽기 전용 티켓 목록·상세 / 독립 실패·예외 목록은 후속 · 담당: frontend(화면) · 협의: backend(조회·권한), infra(대시보드 이벤트)
근거: PRD 2, 4.7, 5.1, 8.2 · API 2.1, 2.4 · DATA 1, 4 · ERD `ticket`, `ticket_assignment`, `member_role`

## 확정 범위와 남은 작업 (2026-10-25)

MVP는 업무 관리자 읽기 전용 티켓 목록·상세이며 BIZ_ADMIN을 서버가 검사한다. 현재 필터 processingStatus만 제공한다. AC04 독립 실패 목록과 AC08의 실패 목록 간 부분 로딩은 후속이다. AC07은 허용된 DEPARTMENT_TICKETS 대상만 구독하며 전체 관리자 전용 room을 가정하지 않는다. 타인 문의 전체 대화는 공개하지 않는다.

정확한 타입·enum은 [DATA_TYPES](../contracts/DATA_TYPES.md), 정책은 [WIRE_CONTRACT 10절](../contracts/WIRE_CONTRACT.md#10-인증재접속최신-대화분석-재시도-추가-프로필), 담당 구현·미검증은 [11절](../contracts/WIRE_CONTRACT.md#11-담당별-구현과-검증-상태)을 따른다. 확정은 개발 기준 선택이며 팀 리뷰/병합·서비스 구현 완료가 아니다.

## 1. 목표

업무 관리자가 전체 업무 현황에서 미해결 티켓, 배정 예외, 생성 실패를 구분해 확인한다. MVP는 조회까지이며 수동 배정·재검토는 후속이다. (PRD 4.7, 8.2 "관리자 조회")

## 2. 화면

| 화면 | 경로(제안) | 접근 |
|---|---|---|
| 관리자 조회 | `/admin/tickets` | 업무 관리자 |
| 티켓 상세(읽기 전용) | `/admin/tickets/:ticketId` | 업무 관리자 · [F009](../F009-department-tickets/spec.md) 상세 컴포넌트 재사용, 현재 두 경로 유지(Q-FE-1) |

## 3. 사용자 시나리오

1. 업무 관리자가 관리자 화면에서 티켓 목록과 생성 실패 목록을 본다.
2. 배정 상태가 "배정 예외"나 "CS 검토"인 티켓을 골라 본다.
3. 티켓을 누르면 문의 요약, 진단, 처리 부서와 배정 이력을 읽는다.
4. 새 티켓이 생기면 목록이 갱신된다.

## 4. 인수 조건

- **F007-AC01 접근 권한**
  업무 관리자만 들어온다. 다른 사용자는 권한 없음 화면으로 보낸다. 화면 이동 제한과 별개로 서버가 403을 돌려주면 같은 화면을 쓴다. (PRD 2 · F001-AC04 · 역할 값 Q-ALL-5)
- **F007-AC02 티켓 목록**
  `GET /api/tickets`로 업무 관리자 범위의 티켓을 보여 준다. 행마다 제목, 처리 부서, 처리 상태, 배정 상태, 생성 시각을 표시한다. (API 2.1)
- **F007-AC03 상태 분리**
  처리 상태와 배정 상태를 따로 표시하고, 배정 예외·복구 필요·CS 검토를 구분해 볼 수 있다. (API 2.1 · DATA 4 · 필터 방식 Q-BE-6)
- **F007-AC04 생성 실패 목록**
  `GET /api/creation-failures`로 아직 티켓이 없는 생성 실패를 티켓 목록과 따로 보여 준다. 생성 실패 항목은 티켓 상세로 연결하지 않는다. 역할별 표시와 재시도 버튼이 없다는 규칙은 F010-AC01~AC04를 따른다. (PRD 4.7 · API 2.1)
- **F007-AC05 티켓 상세 읽기**
  `GET /api/tickets/{id}`로 문의 요약, AI 진단, 현재 처리 부서와 배정 이력을 읽기 전용으로 보여 준다. 수정 버튼은 두지 않는다. 관련 대화를 업무 관리자에게도 보여 줄지는 Q-BE-14에서 정하고, 보여 주면 F009-AC07~AC09를 따른다. (PRD 4.7 · 응답 필드 Q-BE-6)
- **F007-AC06 필터가 권한을 넓히지 않음**
  주소의 필터 값을 바꿔도 서버가 허용한 범위만 보인다. (API 2.1)
- **F007-AC07 실시간 갱신**
  관리자 화면에 있는 동안 업무 변경 이벤트(`state.changed`)를 받으면 목록을 다시 조회한다. 이벤트를 받지 못해도 수동 새로고침으로 같은 결과를 얻는다. (PRD 5.1 · API 2.4 · 구독 대상 Q-INF-3)
- **F007-AC08 빈 결과·실패·부분 실패**
  티켓 목록과 생성 실패 목록은 따로 불러와, 한쪽이 실패해도 다른 쪽은 보여 준다. 빈 결과와 실패를 구분한다. (PRD 4.11)
- **F007-AC09 같은 티켓의 일관 표시**
  Given 문의자 결과 카드(F005)에 보이는 티켓 · When 업무 관리자 목록에서 같은 티켓을 보면 · Then 같은 티켓 `id`·처리 부서·처리 상태·배정 상태로 보인다. 각 화면은 자기 REST 응답만 쓰고, 다른 화면의 캐시나 이벤트 값으로 채우지 않는다. (PRD 7.1 "화면 표시만으로 저장·배정 성공을 인정하지 않는다" · API 2.1 · 이슈 #31)

## 5. 계약(화면이 기대하는 값)

| 용도 | 경로 | 판정 | 비고 |
|---|---|---|---|
| 티켓 목록 | `GET /api/tickets` | 개발 기준 확정 | BIZ_ADMIN을 서버가 검사, processingStatus 필터만 현재 범위 |
| 티켓 상세 | `GET /api/tickets/{id}` | 개발 기준 확정 | TicketDetail(DATA_TYPES), 서버 권한 범위 검증 필요 |
| 생성 실패 | `GET /api/creation-failures` | 후속 후보 | 역할별 필드는 Q-BE-15, API 2.2 |
| 배정 예외 전용 목록 | `GET /api/admin/routing-exceptions` | 초안(후속) | API 2.2 후속. MVP는 티켓 목록의 배정 상태로 구분 |
| 대시보드 이벤트 | `state.changed` | 개발 기준 확정 | 허용된 DEPARTMENT_TICKETS만 사용(Q-INF-3), 전용 관리자 대상 추가 없음 |

## 6. 범위 밖

수동 배정, 재검토 결정, AI 정정, CS 검토 다시 열기(모두 API 2.2 후속), 그룹 재결합, 기술 재시도(운영 관리자 영역 → [F010](../F010-creation-failures/spec.md)), 부서 구성원용 티켓 목록(→ [F009](../F009-department-tickets/spec.md)), 차트·CSV(PRD 8.4 제외).

## 7. 막히는 정도

- 목으로 진행 가능: 목록·상세·빈/실패 상태·권한 이동.
- 구현·검증 상태: 위 확정 범위와 공통 계약 11절을 따른다. 후속 상세 설계는 QUESTIONS의 해당 ID로 추적한다.
