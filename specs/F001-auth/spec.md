# F001 로그인·역할·시스템 접근

상태: PRD 1.44 목표 명세 · 팀 기획 합의 / 상세 계약·구현·검증 별도.

## 1. 목표와 범위

자체 계정으로 인증하고 문의자·주담당자·업무 관리자의 현재 권한에 맞게 화면과 자료를 제공한다.

근거: [PRD](../../docs/PRD.md), [API](../../docs/API.md), [데이터](../../docs/DATA.md), [목표 공통 계약](../contracts/TARGET_CONTRACT.md).

## 2. 인수 조건

- **F001-TARGET-01:** 유효한 계정의 로그인과 현재 사용자 조회를 통해 접근 가능한 화면을 제공한다.
- **F001-TARGET-02:** 문의자는 본인 문의와 연결 결과만 조회한다. 타인 문의를 ID만으로 조회할 수 없다.
- **F001-TARGET-03:** 주담당자는 자신이 맡은 시스템의 업무 및 권한 범위의 관련 자료만 조회한다. 업무 관리자 접근은 서버가 별도로 검사한다.
- **F001-TARGET-04:** 시스템 담당 관계가 바뀌거나 권한을 잃으면 이후 요청과 재연결에서 현재 권한을 검사한다. 열린 연결 회수의 구체 계약은 구현 전에 정한다.
- **F001-TARGET-05:** 인증 만료·오류 시 미전송 입력과 이미 저장된 업무를 보존하고 재인증 뒤 서버 상태를 다시 조회한다.

## 화면과 사용자 흐름

### 화면

- 로그인 화면: 아이디·비밀번호 입력, 오류와 재시도. 기존 경로 `/login`은 현재 프론트 경로다.
- 공통 헤더: 현재 사용자와 로그아웃, 현재 권한에서 접근 가능한 업무 메뉴. 시스템 담당 여부는 서버 정보를 기준으로 한다.

### 흐름

1. 비로그인 사용자가 보호된 화면에 접근하면 로그인하고 복귀할 화면을 보존한다.
2. 로그인 성공 후 현재 사용자와 접근 범위를 확인하고 허용된 화면을 연다.
3. 인증 만료나 담당 관계 변경 뒤에는 저장된 문의를 재조회하고 허용된 작업만 이어간다.

## 상세 인수 조건과 예외

- **F001-DETAIL-01 로그인 실패:** 자격 증명이 틀리면 로그인 성공처럼 이동하지 않고 오류를 표시한다. ID 입력은 유지하며 비밀번호·토큰을 로그에 기록하지 않는다.
- **F001-DETAIL-02 본인 문의:** 문의 소유자는 본인의 문의와 연결 결과를 조회한다. 다른 사용자의 식별자를 알아도 서버가 조회를 거부한다.
- **F001-DETAIL-03 담당 시스템:** 주담당자는 현재 맡은 시스템의 허용 업무만 읽고 처리한다. 담당 변경 전 클라이언트 캐시만으로 권한을 계속 부여하지 않는다.
- **F001-DETAIL-04 관리자:** 업무 관리자 여부와 정정 권한은 서버가 판정한다. 관리자 역할만으로 모든 타인의 문의 원문이 공개되지는 않는다.
- **F001-DETAIL-05 401·403·통신 오류:** 인증 만료/무효, 접근 권한 부족, 서버 연결 실패를 구분한다. 입력과 기존 저장 결과를 보존한다.
- **F001-DETAIL-06 계정 전환:** 로그아웃 또는 계정 전환 시 이전 사용자 캐시·초안·미확인 요청과 SSE를 새 사용자에게 노출하지 않는다.

## 계약·화면 상태

- 로그인·현재 사용자 조회는 기존 프로필에 존재한다. 사용자·시스템 담당 관계와 권한 범위 응답은 목표 공통 계약의 제안이며 필드·실제 서버 적용은 미정이다.
- 기존 프론트의 Access/Refresh 처리는 전송 계약의 기존 프로필을 따른다. 서버의 Refresh 쿠키·회전·CSRF·즉시 회수 구현은 별도 확인한다.

| 상태 | 사용자에게 보이는 동작 |
|---|---|
| 로딩·처리 중 | 현재 요청의 진행을 표시하고 저장·완료로 단정하지 않는다. |
| 정상 결과 | 서버가 확정한 값만 표시한다. |
| 빈 결과 | 정상 조회된 0건을 안내한다. |
| 실패·결과 미확인 | 실패와 저장 미확인을 구분하고 입력·이미 저장된 결과를 보존한다. |
| 권한 없음 | 서버가 접근을 거부하고 허용되지 않은 내용을 표시하지 않는다. |

## 범위·연관 기능

- SSE 토큰 전달과 재접속은 F002, 업무별 권한은 F006·F007·F009와 함께 검증한다. 비밀번호 재설정·계정 직접 변경은 범위 밖이다.

## 현재 구현과 남은 작업

현재 Spring은 로그인·내 정보 조회 및 부서 SSE 인증을 제공한다. 새 시스템 담당 관계 기반 권한과 인증 갱신·회수의 전체 통합은 별도다.

기존 코드·테스트의 인수 조건 번호는 이전 기준이며 목표 조건과 구분한다. 목표 AC는 실제 구현·검증 완료를 뜻하지 않는다. 실제 구현 범위는 서비스 코드와 실행 안내에서 확인한다.

기능의 목표 인수 조건은 구현·통합 검증을 대신하지 않는다. 새 API 경로·필드·enum·권한과 테스트 연결은 담당자 간 계약 확정 후 진행한다.
