# F008 복합 문의 문제 분리

상태: PRD 1.44 목표 명세 · 팀 기획 합의 / 상세 계약·구현·검증 별도.

## 1. 목표와 범위

하나의 문의에서 독립 요청은 별도 문제와 티켓으로 처리한다.

근거: [PRD](../../docs/PRD.md), [API](../../docs/API.md), [데이터](../../docs/DATA.md), [목표 공통 계약](../contracts/TARGET_CONTRACT.md).

## 2. 인수 조건

- **F008-TARGET-01:** 독립 요청과 완료 조건을 문제별로 나눈다. 사용자 제출 승인이나 담당자 수락 없이 서버가 검증한 티켓을 생성한다.
- **F008-TARGET-02:** 같은 증상의 여러 원인 후보만으로 새 문제를 만들지 않는다.
- **F008-TARGET-03:** 각 문제의 질문 횟수·진행·해결 확인을 구분하며 일부 실패해도 성공한 결과를 유지한다.
- **F008-TARGET-04:** 별도 새 문의 자동 생성과 사용자 동의 절차는 이번 MVP의 필수 기능이 아니다. 배정 후 보완 메시지로 새 티켓을 만들지 않는다.

## 화면과 사용자 흐름

### 화면

- 동일 문의 채팅의 문제별 진행과 결과 표시를 F003·F005에서 제공한다. 별도 새 문의 동의 카드는 요구하지 않는다.

### 흐름

1. 한 문의에 열람 오류와 다운로드 개선이 함께 들어온다.
2. Inquiry가 독립 완료 조건을 기준으로 두 문제를 제안한다.
3. 서버가 문제별 상태·티켓을 확정하고 각각의 해결 확인을 관리한다.

## 상세 인수 조건과 예외

- **F008-DETAIL-01 독립 문제:** 하나의 요청이 해결돼도 다른 요청의 완료 조건이 남으면 별도 문제로 분리한다.
- **F008-DETAIL-02 동일 증상 후보:** 한 증상에 권한·조회 조건 등 여러 가능한 원인이 있어도 원인 후보만으로 문제와 티켓을 여러 개 만들지 않는다.
- **F008-DETAIL-03 질문 수:** 각 문제의 질문 횟수와 시스템 확인 상태를 별도로 관리한다. 다른 문제의 질문 수를 합산하지 않는다.
- **F008-DETAIL-04 부분 성공:** 같은 담당자에게 배정되더라도 독립 문제의 티켓은 분리한다. 일부 실패 시 저장된 성공 티켓을 유지한다.
- **F008-DETAIL-05 사용자 동의:** 한 문의 안의 티켓 자동 생성에는 별도 제출 승인을 추가하지 않는다. 별도 새 문의 동의 흐름은 이번 MVP 필수가 아니다.
- **F008-DETAIL-06 배정 후 보완:** 이미 배정된 문제의 추가 대화는 보완으로 연결하며 자동 새 티켓을 생성하지 않는다.

## 계약·화면 상태

- 문의·문제·생성 작업·티켓의 세부 관계와 식별자, 부분 실패 반환 구조는 목표 계약을 기준으로 팀이 합의한다.

| 상태 | 사용자에게 보이는 동작 |
|---|---|
| 로딩·처리 중 | 현재 요청의 진행을 표시하고 저장·완료로 단정하지 않는다. |
| 정상 결과 | 서버가 확정한 값만 표시한다. |
| 빈 결과 | 정상 조회된 0건을 안내한다. |
| 실패·결과 미확인 | 실패와 저장 미확인을 구분하고 입력·이미 저장된 결과를 보존한다. |
| 권한 없음 | 서버가 접근을 거부하고 허용되지 않은 내용을 표시하지 않는다. |

## 범위·연관 기능

- 완료 조건이 다른 요청의 분리와 대화 전체를 별도 문의로 새로 만드는 기능을 구분한다.

## 현재 구현과 남은 작업

이전 F008은 별도 새 문의 생성 동의에 관한 후속 명세였다. 현재 목표는 같은 문의 안의 문제 분리이며 기존 별도 동의 화면은 구현되지 않았다.

기존 코드·테스트의 인수 조건 번호는 이전 기준이며 목표 조건과 구분한다. 목표 AC는 실제 구현·검증 완료를 뜻하지 않는다. 실제 구현 범위는 서비스 코드와 실행 안내에서 확인한다.

기능의 목표 인수 조건은 구현·통합 검증을 대신하지 않는다. 새 API 경로·필드·enum·권한과 테스트 연결은 담당자 간 계약 확정 후 진행한다.
